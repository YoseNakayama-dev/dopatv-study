#81 ・ 第7章 情報セキュリティ対策技術（3）暗号

証明書を支える要素とデジタル署名 失効と検証

  1. CAは証明書の発行と失効、RAは申請者の本人確認と審査を担う。失効情報はCRL（一覧）かOCSP（一件ずつ問い合わせ）。
  2. デジタル署名は、ハッシュ値を送信者の秘密鍵で署名し、公開鍵で検証する。改ざん検知・署名者の確認・否認防止ができる。
  3. 署名の検証だけでは失効は分からず、CRLは更新間隔の分だけ遅れる。秘密鍵が漏れると偽の署名を作られる。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題デジタル署名の説明として、適切なのは？

    1. 送信者の秘密鍵で署名、公開鍵で検証

    2. 署名は送信者の秘密鍵で作る

    3. 共通鍵で作るのはMAC。第三者に証明できない

    4. 署名は暗号化ではなく、改ざん検知・本人確認

  2. 受ける側は、CAが更新するCRLで失効を確認している。CAが証明書を失効させた直後に、その証明書での接続が通ってしまった。考えられる説明はどれか。

    1. 署名は失効後も有効に検証できる。署名の検証だけでは、失効は分からない。

    2. OCSPは一件ずつ問い合わせる方式で、一覧で確認するのはCRL。

    3. 正解。CRLは更新されるまで、最新の失効が反映されない。更新の間隔がそのまま遅れになる。

    4. RAは申請者の本人確認や審査を行う。失効はCAが行い、CRLはCAが署名する。

  3. 社内CAが発行した証明書が、他人名義の申請で発行されていた。申請時の確認が甘かった。見直すべき対策として最も適切なものはどれか。

    1. CRLは失効した証明書の一覧で、失効の反映に関わる。発行時の審査の問題とは別。

    2. 正解。申請者の本人確認と審査はRAの役割。RAでの審査を厳格にする。

    3. 署名の検証とハッシュ値の比較は、改ざんを検知するための手順。発行時の審査の不備は防げない。

    4. 秘密鍵の保管は流出への対策。今回は鍵が漏れたのではなく、申請時の審査の問題。

  4. 取引先が自社へ送る発注データには、共通鍵で作ったMACが付いている。後で取引先に「送っていない」と否認されても第三者に示せるよう、取引先に求める方式として適切なものはどれか。

    1. 共通鍵で作るMACは第三者に証明できない。否認に備えるには足りない。

    2. 署名は、受信者の公開鍵ではなく送信者の秘密鍵で作る。

    3. ハッシュ値は誰でも計算できるので、付けただけでは送信者を確認できず、否認防止にもならない。送信者の秘密鍵で署名してはじめて、署名者の確認と否認防止ができる。

    4. 正解。送信者の秘密鍵で署名し、受信者が公開鍵で検証する。第三者にも示せる。

  5. 署名付きファイルを受信し、公開鍵で署名を検証してハッシュ値を比べたところ、一致しなかった。適切な判断はどれか。

    1. 正解。署名を検証してハッシュ値を比べるのは、改ざんを検知するため。不一致なら改ざんを疑う。

    2. ハッシュ値の一致まで確かめる必要がある。不一致なら改ざんの検知として扱う。

    3. 有効期間とハッシュ値の一致は別の確認。署名を検証して、ハッシュ値の一致を確かめる必要がある。

    4. 失効はCRLやOCSPで確認する別の事柄。ハッシュ値の不一致は改ざんの検知に当たる。

  6. 受信した署名の検証に成功した。署名者の証明書が失効済みかは確認していない。適切な判断はどれか。

    1. 署名は失効後も有効に検証できる。失効の確認を省くと、漏れた鍵の証明書が使われ続ける。

    2. 正解。署名の検証だけでは失効は分からない。CRLやOCSPで失効情報を確認する。

    3. 署名は失効後も有効に検証できるので、検証の成功は失効していない証拠にならない。

    4. 失効の確認も検証の一部で、受ける側が失効情報を確認する。署名の検証だけでは足りない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 署名の検証に成功した文書の署名者証明書が、実は失効済みだった。検証で気付けない理由と防ぎ方を頭の中で説明してみよう。

    答えを開く

    署名は失効後も有効に検証できるので、署名の検証と失効の確認は別。CRLやOCSPで失効情報を確認する。CRLは更新間隔の分だけ反映が遅れる点も押さえる。

  2. デジタル署名で、改ざん検知と署名者の確認ができる理由を、鍵とハッシュ値に触れて頭の中で説明してみよう。

    答えを開く

    送信者がハッシュ値を自分の秘密鍵で署名し、受信者が公開鍵で検証してハッシュ値を比べる。不一致なら改ざんを検知できる。署名は送信者の秘密鍵で作るので、署名者の確認になる。

午後問題にチャレンジ

動画の午後問題です。ログを読んで、答えを頭の中で決めてから開いてください。

クライアント証明書の運用に関する調査記録（ダミー）
現状: 社員用のクライアント証明書を、社内のCAが発行している
ある社員の端末が紛失し、秘密鍵が漏れたおそれがある
この証明書の有効期間は、まだ残っている
要件: 接続を受ける側で、この証明書による接続を拒否したい

要件を満たす対応として、適切なのは？

答えを開く

CAがこの証明書を失効させ、受ける側が失効情報を確認して拒否する

よくある誤答

  • 有効期間が切れるまで待つ … 期間はまだ残っており、拒否したい要件を満たせない
  • 受ける側で、証明書のCA署名だけを検証する … 失効しても署名は有効なままで、拒否できない

本で読む

  • 7.7.3 デジタル証明書による認証基盤を構成する要素
  • 7.7.4 デジタル署名

CA・RA・失効情報（CRL/OCSP）の役割分担と、署名の検証と失効確認が別であること、MACとの違いを確かめながら読む。
