脅威モデリングとSAST・DAST・SCA 見つけられる範囲の違い

  1. 脅威モデリングは設計段階で資産・データの流れ・信頼境界を図にし、STRIDEの観点で脅威を洗い出して設計に反映する。
  2. SASTは実行せず解析（誤検知あり）、DASTは動作中に入力（触れた範囲のみ）、SCAは部品の既知の脆弱性（自社コード対象外）。
  3. 設計上の不備はツールでは見つけにくく、入れただけでは安全にならない。誤検知を確認し、優先度をつけて直す。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題DASTの説明として、適切なものは？

    1. それはSASTの説明

    2. それはSCAの説明

    3. それは脅威モデリング

    4. 動作中のアプリで挙動を調べる

  2. SASTとSCAは継続的に回しており、指摘は出ていない。ところがリリース後に、設計上の不備が見つかった。再発防止として最も適切なものはどれか。

    1. 正解。設計上の不備はツールでは見つけにくい。設計の段階で脅威モデリングを行い、脅威を洗い出して設計に反映する。

    2. 設計上の不備は、ツールでは見つけにくい。SASTは、コードを実行せずに解析する手法。

    3. SCAは利用部品の既知の脆弱性を調べる手法で、自社コードの誤りは対象外。

    4. DASTは動作中のアプリに外から入力し、触れた範囲しか分からない。ツールを入れただけでは安全にならず、設計上の不備はツールでは見つけにくい。

  3. DASTの結果は「指摘なし」だった。ただし検査ツールは認証情報を持たず、記録されたリクエストはログイン前の画面だけだった。結果の解釈として最も適切なものはどれか。

    1. 指摘なしは、触れた範囲の結果にすぎない。ログインが必要な画面は認証情報を渡さないと届かない。

    2. DASTは触れた範囲しか分からない。ログインが必要な画面は、認証情報を渡さないと届かない。

    3. 正解。DASTは触れた範囲しか分からない。ログイン後の画面は、認証情報を渡さないと届かないので、未検査として扱う。

    4. SCAは利用部品の既知の脆弱性を調べる手法で、自社コードの誤りは対象外。DASTの未検査分の代わりにはならない。

  4. 脅威モデリングでデータの流れを図にしたところ、信頼境界をまたぐ通信が複数見つかった。対応として最も適切なものはどれか。

    1. 脅威モデリングは設計の段階で行う。設計の段階なら、直す手間が小さい。

    2. 正解。信頼境界をまたぐ通信は特に注意して考え、STRIDEの観点で脅威を洗い出して設計に反映する。

    3. 設計上の不備はツールでは見つけにくい。ツールを入れただけでは安全にならない。

    4. STRIDEは、なりすまし・改ざん・否認・情報漏えい・サービス拒否・権限昇格の六つの観点で考える。二つだけでは足りない。

  5. SASTの結果に指摘が多数並んだ。担当者は「ツールが出したものだから全部本物だ」として、機械的に直し始めた。見直しとして最も適切なものはどれか。

    1. SASTは早期に使えるが、誤検知も出る。指摘をすべて本物と扱うのは誤り。

    2. 指摘は放置しない。毎回のビルドで確認し、誤検知を確かめて優先度をつけて直す。

    3. DASTは触れた範囲しか分からず、手法ごとに見える範囲が違う。DASTで指摘が出ないことは、SASTの指摘を無視してよい根拠にならない。

    4. 正解。結果は誤検知を確認し、優先度をつけて直す。

  6. 開発の初期で、アプリはまだ動作せず、実行環境も整っていない。この段階で自社コードの誤りを探す手法として最も適切なものはどれか。

    1. DASTは動作中のアプリに外から入力する手法。アプリがまだ動かない段階では使えない。

    2. 正解。SASTはコードを実行せずに解析し、早期に使える。ただし誤検知も出るので、確認が要る。

    3. SCAは利用部品の既知の脆弱性を調べる手法で、自社コードの誤りは対象外。

    4. 脅威モデリングは設計の段階で、資産・データの流れ・信頼境界から脅威を洗い出す。コードの誤りを検出する手法ではない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. SASTで指摘がなくても脆弱性が残りうる理由を、手法の見える範囲の違いから説明してみよう。

    答えを開く

    SASTはコードを実行せずに解析する手法で、早期に使えるが誤検知もある。利用部品の既知の脆弱性はSCAの範囲、実行時の挙動はDASTの範囲。設計上の不備はツールでは見つけにくく、脅威モデリングで設計段階に洗い出す。ツールは入れただけでは安全にならない。

    思い浮かんだ要素にチェック

  2. DASTで「指摘なし」が出たときに、結果をそのまま信じてよいかを検討する観点を説明してみよう。

    答えを開く

    DASTは動作中のアプリに外から入力する手法で、触れた範囲しか分からない。ログインが必要な画面は認証情報を渡さないと届かない。指摘なしは届いた範囲の結果なので、検査の範囲を確認し、手法を組み合わせる。
