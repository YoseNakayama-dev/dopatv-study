#49 ・ 第5章 情報セキュリティ対策技術（1）予防・検知・防御

TLPTの概要 脅威に基づく侵入テスト

  1. TLPTは、実際の攻撃者の手口（脅威情報）を元に攻撃を模擬し、検知・対応を含む防御力を評価する。
  2. レッド・ブルー・ホワイトの役割があり、ブルーは通常実施を知らされない。範囲と緊急停止は事前に合意する。
  3. 診断などの基礎が整った組織が行う。費用と期間が大きく、1回のシナリオで全体の安全は示せない。

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題TLPTの説明として、適切なのは？

    1. それは、脆弱性診断の説明

    2. それは、ファジングの説明

    3. それは、ASMの説明

    4. 手口を模擬し、検知と対応も評価

  2. 決済事業者が脆弱性診断を毎年行い、指摘は対処済みである。次に、監視・対応の担当者が実際の攻撃に気づいて動けるかを確かめたい。最も適切な方法はどれか。

    1. 正解。実際の手口を模擬し、検知・対応を含む防御力を評価するのがTLPTの狙い。

    2. 診断は脆弱性の列挙が狙いで、検知・対応が機能するかは評価できない。件数が減ることと検知力は別の話。

    3. ブルーチームは本当の検知力を見るため、通常は実施を知らされない。全員に知らせると実態を見られない。

    4. 実際に攻撃を模擬していないので、検知・対応が機能するかは確かめられない。

  3. TLPTの実施中、模擬攻撃の操作で本番の業務システムに想定外の負荷が出た。実施を事前に知っているのは少数の責任者だけである。中止の判断を担うのはどれか。

    1. ブルーチームは通常、実施を知らされない。中止の判断を担う役割ではない。

    2. レッドチームは攻撃を模擬する側。運営・調整・中止の判断はホワイトチームの役割。

    3. 正解。ホワイトチームが運営・調整・中止の判断を担い、緊急停止の手順は事前に文書で合意しておく。

    4. 委託先やクラウドの同意は事前に取るもので、実施中の中止判断を担うのはホワイトチーム。

  4. TLPTで、模擬の攻撃チームが設定された目的に到達できなかった。結果の解釈として最も適切なものはどれか。

    1. TLPTは診断などの基礎が整った組織が行うもので、基礎を省く根拠にならない。1回で全体の安全は示せない。

    2. 正解。1回のシナリオで全体の安全は示せない。合格しても安全とは言えない。

    3. 知らされていない状況で試すのは検知力を見るためだが、1回の結果だけで十分と断定はできない。

    4. 結果は実施者の能力に左右される。同じ結果になると決めつけられない。

  5. 金融機関が本番環境でTLPTを計画している。基幹システムの一部は委託先のクラウドで稼働している。事前準備として最も適切なものはどれか。

    1. 範囲・禁止事項・緊急停止の手順は事前に文書で合意する。本番への影響に備えられなくなる。

    2. 全体を把握するのは少数の責任者だけで、ブルーチームは通常知らされない。全員に通知すると検知力を見られない。

    3. 流れは、脅威情報の収集、シナリオ作成、実施、報告と改善。シナリオは脅威情報を元に作る。

    4. 正解。本番への影響に備え、事前に文書で合意し、委託先やクラウドの同意も取る。

  6. 新任の担当者がTLPTの進め方を並べた。適切なものはどれか。

    1. 正解。脅威情報の収集、シナリオ作成、実施、報告と改善の順。

    2. シナリオは脅威情報を元に作るので、収集がシナリオ作成より後では実際の手口に基づけない。

    3. 実施の前にシナリオが必要。実施が先頭では脅威情報に基づく試験にならない。

    4. 実施の前にシナリオを作る。実施中に筋書きを決める順ではない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 脆弱性診断を毎年行い指摘も対処済みの組織が、それでもTLPTを行う意義を、頭の中で説明してみよう。

    答えを開く

    診断は脆弱性の列挙が狙い。TLPTは実際の攻撃者の手口を模擬して侵入を試み、検知と対応を含む防御力を評価する。診断で指摘が無くても、アラートに気づいて対応できるかは別なので、試す意義がある。

    思い浮かんだ要素にチェック

  2. ブルーチームに実施を知らせない理由と、本番環境で行うために事前に決めておくことを、頭の中で説明してみよう。

    答えを開く

    本当の検知力を見るため、ブルーチームは通常知らされず、少数の責任者だけが全体を把握する。一方で本番への影響に備え、範囲・禁止事項・緊急停止の手順を事前に文書で合意し、委託先やクラウドの同意も取る。

TLPTの実施記録（ダミー）
対象: 決済事業者の基幹システム（ダミー）。脆弱性診断は毎年実施し、指摘は対処済み
脅威情報に基づくシナリオで、模擬の攻撃チームが、本番環境への侵入を試みた
監視チームには、実施を事前に知らせていない
侵入に使われたのは、演習の前提として付与された、正規のアカウント情報。未修正の脆弱性は、使われていない
侵入から目的の達成まで、10日間。経路上で、監視のアラートが、3回発生した。3回とも、模擬の攻撃チームの操作が原因
3回とも、担当者が「定型の誤検知」と判断し、記録のみで処理した
