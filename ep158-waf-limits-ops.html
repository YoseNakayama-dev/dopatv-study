#58 ・ 第5章 情報セキュリティ対策技術（1）予防・検知・防御

WAFの限界と運用の課題 入れて終わりではない補助の守り

  1. WAFは根本対策ではなく、影響を低減する補助。通信が正常に見える認可・業務ロジックの不備は防げない場合がある。
  2. 導入初期は検知のみで動かし、誤検知を確認してから遮断。除外は最小限にし、アプリ変更時は見直す。
  3. 遮断・通過の両方のログを確認し、WAF自体の故障時の動作も決める。脆弱性診断と修正を併用する。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題WAFの運用として、適切なのは？

    1. 変更や新たな攻撃に合わせ、見直しが要る

    2. 全部無効だと、守れなくなる

    3. アプリの変更時はルールを見直す

    4. 通過した通信のログも確認する

  2. 「WAFを導入したので、Webアプリの脆弱性対策は完了した」と報告された。この評価として最も適切なものはどれか。

    1. 正解。WAFは根本対策ではなく、修正までの間を補う補助。脆弱性診断で見つけて修正する流れと組み合わせる。

    2. 遮断モードでも脆弱性そのものは残る。診断と修正は引き続き必要。

    3. 影響を低減しても脆弱性は残る。脆弱性診断と修正を併用する。

    4. 認可の確認や入力値の検証などアプリ側の対策も欠かせない。

  3. 誤検知で正常な入力が遮断される問い合わせが続いたため、該当する検査をすべてのURLで広く除外した。この対応への評価として最も適切なものはどれか。

    1. 除外を増やしすぎると、守れない範囲が広がる。

    2. 正解。誤検知を避ける除外ルールは必要最小限にする。

    3. ログは遮断したものも通過したものも確認する。除外を広げてもログ確認は省略できない。

    4. 見直しと更新は必要。アプリの変更や新たな攻撃に合わせて、ルールを見直す。

  4. Webアプリに画面と入力項目を追加する改修をリリースする。WAFの扱いとして最も適切なものはどれか。

    1. アプリを変更したときは、ルールが合っているかを見直す。無関係ではない。

    2. 新しい入力項目にルールが自動で追従するとは限らない。アプリを変更したときは、運用側がルールが合っているかを見直す。

    3. 停止すると検査されなくなる。必要なのはルールの見直しである。

    4. 正解。アプリの変更時にはルールを見直し、新たな攻撃に備えた更新も必要。

  5. WAFをWebサイトの手前の通信経路に1台置いている。可用性の観点で最も適切な考え方はどれか。

    1. 正解。WAF自身が障害点になりうるため、故障時の動作も決めておく。

    2. WAFは障害点になりうる。故障時の動作を考えなくてよいとは言えない。

    3. 「故障の心配はなくなる」は言い過ぎ。WAFは障害点になりうるので、故障時の動作は決めておく。

    4. 故障時の動作は決めておく対象で、必ずこうと決まっているわけではない。

  6. 注文手続きで、個々の通信は正しい形式で通常の操作と同じ形のまま、業務ロジックの不備により不正な結果が得られると分かった。対策の評価として最も適切なものはどれか。

    1. 通常の操作と同じ形の通信は、パターンに当たらず判断できないことが多い。

    2. 正解。通信が正常に見える業務ロジックの不備は、WAFでは防げない場合がある。アプリ側の対策が欠かせない。

    3. WAFは根本対策ではない。脆弱性そのものは残るので、アプリの修正が本筋。

    4. 暗号化通信は復号できる位置が必要だが、それとは別の限界。正常に見える通信の不備は復号しても判断できないことが多い。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. WAFを遮断モードで運用しているのに、会員サイトで他人の情報が見られてしまった。なぜWAFで防げなかったか、頭の中で説明してみよう。

    答えを開く

    他人の情報が見られる認可の不備は、通信自体が正常に見えるため、WAFは判断できないことが多い。WAFは根本対策ではなく補助なので、サーバ側で本人の情報かを確認する対策が要る。

    思い浮かんだ要素にチェック

  2. WAFの導入から運用までの流れを、誤検知と除外ルールに触れながら頭の中で説明してみよう。

    答えを開く

    導入初期は検知のみで動かし、誤検知を確認してルールを調整してから遮断にする。除外ルールは必要最小限にし、アプリの変更や新たな攻撃に合わせて見直し・更新する。遮断・通過の両方のログを確認する。

会員サイトの情報漏えいの調査記録（ダミー）
会員サイトの前段にWAFを導入済み。遮断モードで稼働中
ある利用者が、URLの会員番号を変え、他人の情報を閲覧した
会員番号は正しい形式で、要求は、通常の操作と同じ形だった
サーバは、ログイン済みであることだけを確認して、返していた
要件: 他の利用者の情報は返さない。アプリの改修は可能

情報漏えいを防ぐ対策として、適切なのは？

答えを開く

サーバ側で、要求された情報が本人のものか確認して返す

よくある誤答

  • WAFに攻撃パターンを追加して、不審な通信を遮断する … 要求は通常の操作と同じ形で、パターンに当たらない
  • WAFで会員番号の形式を厳しく検査して、不正な要求を遮断する … 番号は正しい形式で、形式では区別できない

本で読む

  • 5.8.2 WAFの機能上の限界及び運用上の課題

WAFで防げない場合と、運用（検知のみ→遮断、除外の最小化、見直し、ログ確認）を、アプリ修正との併用という位置づけとあわせて読む。
