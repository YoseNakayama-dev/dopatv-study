#56 ・ 第5章 情報セキュリティ対策技術（1）予防・検知・防御

IPSの構成例と限界 故障時に止めるか通すか

  1. IPSは通信の経路上に置く。FWの内側が多く、重要なサーバ群の手前で重点的に守る構成もある。
  2. 経路上にあるので故障すると通信が止まりうる。故障時は通す（フェイルオープン）か止めるかを決め、二重化で備える。
  3. 誤検知・未知の攻撃・復号していない暗号化通信・処理能力の超過が限界。更新とログ監視などの運用が要る。

用語カード

クイズ

  1. 動画で出た問題IPSの「フェイルオープン」の説明として、適切なのは？

    1. それは、フェイルクローズ

    2. 検知のみの運用

    3. それは、冗長化

    4. 故障時に通信を通す

  2. FWの外側に置いたIPSのアラートが多すぎて、運用担当が対応しきれていない。配置の見直しとして最も適切なものはどれか。

    1. 正解。内側はFWを通過した通信のみを検査するのでノイズが少なく、運用しやすい。

    2. 外側は外部からの攻撃をすべて見られる反面、アラートが多くなる。減るわけではない。

    3. 内側はノイズが少なく運用しやすいので、FWの内側に置くことが多い。必ず外側という決まりはない。

    4. 重要なサーバ群の手前に置いて、重点的に守る構成もある。

  3. 受注システムの手前に、故障時にフェイルクローズとなるよう設定したIPSを1台置いている。このIPSが故障した場合に起きることとして最も適切なものはどれか。

    1. それはフェイルオープンの動作。フェイルクローズは故障時に通信を止める。

    2. 正解。フェイルクローズは故障時に通信を止める。安全側だが、業務が止まる。

    3. この設定はフェイルクローズなので、故障時は検査も通信も止まる。検査と通信を続けるには二重化などの備えが要る。

    4. 故障時の動作は、通信を通すか止めるかのどちらか。通知のみへの切替は示されていない。

  4. IPSの処理能力を超える量の通信が流れ続けた。起こりうる事象として最も適切なものはどれか。

    1. 処理能力を超えると遅延や取りこぼしが起きる。誤検知が減り、性能の問題が起きなくなるわけではない。

    2. IPSは経路上（インライン）に置く。処理が追いつかないと通信に遅延が出うる。

    3. 正解。処理能力を超えると、遅延や通信の取りこぼしが起きる。

    4. すべてが遮断されるわけではなく、取りこぼしが起きうる。攻撃が成立しなくなるとは言えない。

  5. 暗号化通信の中身まで検査して、不正な通信を止めたい。IPSの設計上の考え方として最も適切なものはどれか。

    1. 復号していない暗号化通信は止められない。中身を検査するには復号が要る。

    2. 正解。復号して検査する方法もあるが、処理の負荷が増える。

    3. 復号して検査しても、誤検知がなくなるとは言えない。誤検知は調整して減らす。

    4. 復号して検査する方法がある。検査対象から外すと、その通信は止められないままになる。

  6. 業務システムの変更後、IPSが正常な通信を遮断して業務が止まった。パターンの更新とログの監視は行われていた。運用上の不足として最も適切なものはどれか。

    1. 正解。IPSの運用には、更新・ログの監視・例外の手続きに加え、変更時の影響確認が要る。

    2. フェイルオープンは故障時に通信を通す動作で、正常な通信の遮断の原因にはならない。

    3. 未知の攻撃を止められないのは見逃しの限界。今回の事象は正常な通信の遮断で、影響確認などの運用で備える。

    4. 検知のみの運用は遮断しない。正常な通信を止めたのは、遮断が有効なためである。

頭の中で考える

  1. 受注業務は止めたくないが、不正な通信はサーバの手前で止めたい。IPSの故障時の動作と備えを、頭の中で説明してみよう。

    答えを開く

    IPSは経路上にあるので故障すると通信が止まりうる。故障時に通すと業務は止まらないが検査されず、止めると安全だが業務が止まる。どちらも一長一短なので、二重化して故障時も検査と通信を続ける。

    思い浮かんだ要素にチェック

  2. IPSを導入して終わりにしてはいけない理由を、限界と運用の両面から頭の中で説明してみよう。

    答えを開く

    誤検知で正常な通信を止めうるので、検知のみで調整してから遮断にする。未知の攻撃や復号していない暗号化通信は止められず、処理能力を超えると取りこぼしも起きる。更新・ログ監視・例外の手続き・変更時の影響確認が要る。

午後問題にチャレンジ

受注サーバ群のIPS故障の調査記録（ダミー）
対象: 受注サーバ群（ダミー）の手前にIPSを設置。通信の経路上に置いている
設定: 故障時は、通信を通す動作。IPSは1台構成
ある日、IPSが故障し、検査されないまま、通信が受注サーバに届いた
その間、不正な通信の一部が通過した。受注業務は止まらなかった
要件: 受注業務の停止は避ける。不正な通信は、サーバの手前で止めたい

故障時の対策として、適切なのは？

答えを開く

IPSを二重化し、故障時にも、検査と通信を続けられるようにする

よくある誤答

  • 故障時は通信を止める設定にする … 要件は、受注業務の停止を避けること
  • 経路の外に移し、故障の影響をなくす … 要件は、サーバの手前で止めること
