#6 ・ 第2章 情報セキュリティにおける脅威

SSRF サーバを踏み台にされると何が起こる？

  1. SSRFは、利用者指定のURLをサーバが取得する機能で、送信先を限定しないと内部へ届いてしまう。
  2. 許可リストが最優先。送信先が決まるなら、スキームやパスは固定し、リダイレクトの追従を無効にする。
  3. 拒否リストや名前の検査だけでは回避されうる。解決IPの検証、ネットワーク制限、クラウド設定で重ねる。

  1. 動画で出た問題SSRFの対策として最も適切なのは？

    1. XSSの対策

    2. 送信先を許可リストで限定する

    3. CSRFの対策

    4. SQLインジェクション向けの対策

  2. アイコン画像は自社の画像配信サーバ（img.cdn.example）からだけ取得する仕様である。URLを利用者から受け取る機能の方針として最も適切なものはどれか。

    1. 拒否リストは回避されやすい。送信先が既知なら許可リストを使う。

    2. 正規表現だけのURL検証は、頼るべきでない方法の一つ。

    3. 正解。送信先が既知なら許可リストと照合し、完全なURLは受け取らず固定部分を組み立てる。

    4. ブラウザ側の検査は、攻撃者が迂回できる。サーバ側で限定する必要がある。

  3. ホスト名の検証は許可リストと一致して通過したが、取得時に名前が内部IPへ解決され、内部に接続された。見直しとして最も適切なものはどれか。

    1. 正解。DNSリバインディングは名前の検証だけでは防げない。解決したIPを検証し、そのIPへ接続する。

    2. 検証と接続が別のDNS解決だと、間に解決結果が変わる。頼るべきでない実装。

    3. 名前の比較をいくら厳密にしても、解決先IPの変化は防げない。

    4. リダイレクトの自動追従は無効にする。有効化は逆の対応。

  4. 許可リストにあるホストのURLだけ取得している。許可先が内部アドレスへのリダイレクトを返す場合に備える対策として最も適切なものはどれか。

    1. 許可先を増やすほど、リスクの入り口が増える。リダイレクトの対策にならない。

    2. 追従した時点で、内部へのリクエストはすでに送られている。

    3. 最終的な応答の種類を見ても、内部への接続自体は防げない。

    4. 正解。許可先から内部へ転送されないよう、リダイレクトは自動で追わない。

  5. AWS上のWebサーバにSSRFの懸念がある。アプリの対策に加え、多層防御としてメタデータサービスに行う設定として最も適切なものはどれか。

    1. アプリ側の検査だけでは単一の層になる。IMDSv1は無効化する。

    2. 正解。IMDSv2は多層防御として有効で、IMDSv1は無効化する。アプリ側の対策の代わりにはならない。

    3. 拒否リストだけに頼るのは避ける。回避されうる。

    4. 権限を広げると、認証情報を取られたときの被害が増える。

  6. 画像取得機能がhttpとhttpsのURLを想定しているが、実装はHTTPクライアントが対応するスキームを全て受け付ける。評価として最も適切なものはどれか。

    1. 画像を返せなくても、file:// などを通じて内部の情報に届く場合がある。

    2. スキームによっては、HTTP以外の経路で別のサービスにも届く。

    3. スキームの限定は一つの層にすぎない。送信先の限定とネットワークでの制限も要る。

    4. 正解。file:// gopher:// dict:// なども悪用されうる。必要なスキームだけ許可する。

頭の中で考える

  1. 外から届かない内部システムの情報が、SSRFで利用者に返ってくる仕組みを、頭の中で説明してみよう。

    答えを開く

    利用者が指定したURLを、サーバが送信先を限定せずに取得し、その結果を返すため。外から届かなくても、サーバから届く構成なら内部に届き、サーバが踏み台になる。

    思い浮かんだ要素にチェック

  2. 「内部アドレスを拒否リストに入れたので大丈夫」と言えない理由と、代わりの方針を、頭の中で説明してみよう。

    答えを開く

    拒否リストや単純な文字列の検査は回避されやすい。許可リストが作れるなら最優先とし、解決したIPの検証、リダイレクトの無効化、ネットワーク制限も重ねる。

// プレビューAPIは、指定URLをそのまま取得して返す

ログの現象を生んだ、設計上の不備は？

答えを開く

送信先を限定せず、利用者指定のURLを取得した

よくある誤答

  • 内部に認証が無い … 到達可否の話。今回は送信先を限定しない点が不備
  • ログの出力レベルが低い … 記録の話で、現象の原因ではない
