#37 ・ 第3章 情報セキュリティにおける脆弱性

DNSの脆弱性への対策 弱点ごとに塞ぐ

  1. 仕様の弱点にはDNSSECと識別子・ポートのランダム化。署名と検証の両方が要り、ランダム化は確率を下げるだけ。
  2. 設定の弱点には、再帰とゾーン転送の限定、内部名を載せない、権威とキャッシュの分離で対応する。
  3. 実装の弱点は更新で塞ぐ。バージョン非表示は補助。どれか1つでは足りず、弱点ごとに重ねる。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題DNSキャッシュポイズニングへの対策として、適切なのは？

    1. 長いほど、偽の答えも長く残る

    2. 登録情報が、丸ごと見える

    3. 攻撃を受ける面が、広がる

    4. 署名の検証で、偽の応答を見抜く

  2. 自社ドメインのゾーンに、DNSSECの署名をしていない。検証側のキャッシュサーバがDNSSECの検証を有効にしている場合、自社ドメインの名前解決の評価として最も適切なものはどれか。

    1. 正解。DNSSECはドメイン側が署名していなければ検証できず、検証側が有効でなければ効かない。両方が必要。

    2. 署名がないドメインは、そもそも検証できない。

    3. 署名は通信の秘匿ではない。

    4. ランダム化は偽の応答が通る確率を下げるだけで、署名の代わりに検証を可能にするものではない。

  3. キャッシュサーバで、問い合わせの識別子とソースポートのランダム化を実施した。この対策の評価として最も適切なものはどれか。

    1. ランダム化は確率を下げるだけで、完全には防げない。重ねて使う。

    2. 電子署名で正当性を確かめるのはDNSSECの役割。

    3. 正解。ランダム化は偽の応答が当たる確率を下げるが、ゼロにはならない。

    4. 通信の秘匿を行う対策ではない。

  4. セカンダリのDNSサーバにだけゾーンを渡したい。ゾーン転送の設定方針として最も適切なものはどれか。

    1. 誰にでも許すと、登録情報が丸ごと見える。

    2. 正解。ゾーン転送は許可した相手だけに限定する。アドレスの制限に加えて、署名付きの認証も使える。

    3. バージョン情報の非表示は実装の弱点への補助で、転送の許可範囲の対策にはならない。

    4. 権威サーバとキャッシュサーバは分離する。兼用は攻撃を受ける面を広げる。

  5. DNSサーバソフトの脆弱性が公表された。「バージョン情報を外部に見せない設定にして対応を終えた」という報告への評価として最も適切なものはどれか。

    1. 正解。バージョン情報の非表示は補助で、更新の代わりにはならない。更新が遅れるほど公開済みの穴が長く残る。

    2. 更新が遅れるほど、公開済みの穴は長く残る。

    3. 設定の限定は設定の弱点への対策で、ソフトの脆弱性は更新で塞ぐ。

    4. 非表示は実装の弱点への補助。設定の弱点は、許可範囲の限定などで別に対応する。

  6. 公開ゾーンに内部の名前を載せている設定を改めたい。方針として最も適切なものはどれか。

    1. 載せたままでは構成が見える。見せない形にするのが対策。

    2. DNSSECは正当性の確認で、通信の秘匿や構成の隠蔽をするものではない。

    3. 正解。公開ゾーンには内部の名前を載せず、内外で見せる情報を分ける。

    4. 兼用は攻撃を受ける面を広げる。権威とキャッシュは分離する。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 再帰問い合わせを誰にでも許すキャッシュサーバが、第三者へ大きな応答を大量に送りつける踏み台にされる流れと、その対策を頭の中で説明してみよう。

    答えを開く

    再帰を誰にでも許すと、外部から送られた問い合わせに応答する。UDPは送信元を偽れるため、第三者の送信元を装った問い合わせで、問い合わせより大きい応答がその第三者へ届く。再帰を許可したクライアントだけに限定し、外から使えないようにする。

    思い浮かんだ要素にチェック

  2. DNSSECとランダム化を導入しても「完全には防げない」と言われる理由を、頭の中で説明してみよう。

    答えを開く

    DNSSECはドメイン側が署名していなければ検証できず、検証側が有効でなければ効かない。ランダム化は偽の応答が通る確率を下げるだけでゼロにはならない。だから弱点ごとに対策を重ねる。

キャッシュDNSサーバの調査記録（ダミー）
対象: 社内のキャッシュDNSサーバ（ダミー）。外部の第三者から、大量の応答が届いたと苦情
このサーバは、インターネット上のどのアドレスからの再帰問い合わせにも応答していた
外部から届いた問い合わせの送信元は、第三者のアドレスで、応答はそこへ送られていた
各応答は、問い合わせより大きく、問い合わせは通常の名前解決の要求のみ
// キャッシュの登録値は、権威サーバの値と一致 / ゾーン転送の要求は0件

この事象の原因として、適切なのは？

答えを開く

再帰問い合わせを誰にでも許す設定のため、第三者への応答の踏み台にされた

よくある誤答

  • キャッシュポイズニング … キャッシュの値は、権威サーバの値と一致
  • ゾーン転送による漏えい … 要求はすべて通常の名前解決で、転送は0件
