#107 ・ 第3章 情報セキュリティにおける脆弱性

TCP/IP共通の脆弱性 平文・偽装・資源枯渇

  1. TCP/IPは相手を信頼する前提の設計。平文は盗聴・改ざんされ、送信元アドレスは申告で偽れ、認証は含まれない。
  2. 接続状態に資源を使うためSYNフラッドで枯渇しうる。番号の推測は割込みを、偽の送信元は反射を招く。
  3. 暗号化・送信元の遮断・接続数の制限で備える。ただし暗号化は偽装や過負荷を止めず、多層で備える。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題TCP/IPの弱点の説明として、適切なものは？

    1. 送信元は申告で、検証されない

    2. TCP自体に暗号化はない

    3. SYNフラッドは資源を使い果たさせる

    4. 送信元アドレスは偽ることができる

  2. 外部から境界に届いたパケットの送信元が、自社内のアドレスになっていることがファイアウォールのログで分かった。最も適切な解釈と対応はどれか。

    1. 送信元アドレスは申告で偽れる。外部から届いた通信が社内のアドレスを名乗るのは、不自然な送信元にあたる。

    2. 正解。境界で、不自然な送信元（自組織のアドレスを名乗る外部からの通信など）を遮断する。

    3. 暗号化は盗聴と改ざんへの対策で、送信元の偽装を使う攻撃は止めない。

    4. 接続数の上限は資源の消費を抑える対策で、送信元の偽装を見抜いて排除するものではない。

  3. 公開Webサーバで、SYNを受けて確認待ちになった接続が大量に残り、新規の接続を受け付けられない。原因と対策として最も適切なものはどれか。

    1. 平文は盗聴・改ざんの弱点。資源の枯渇は暗号化では止まらない。

    2. シーケンス番号の推測は通信への割込みの話で、確認待ちの接続が溜まる現象とは別。

    3. 正解。接続の管理に資源を使い果たさせるSYNフラッド。接続数の上限やSYNクッキーで消費を抑える。

    4. ポートスキャンは偵察で、別の話。公開しているポート宛ての大量のSYNは、不要なポートを閉じても受けてしまう。

  4. 公開サーバの全通信をTLSに置き換えた後も、送信元を偽った大量のパケットで応答が遅くなる事象が起きた。置き換えの評価として最も適切なものはどれか。

    1. 正解。暗号化は偽装や過負荷を止めない。接続数の上限やSYNクッキー、不自然な送信元の遮断などと多層で備える。

    2. 暗号化は盗聴・改ざん対策で、送信元の偽装を使う攻撃は止められない。

    3. 暗号化の強さと資源の枯渇は別の問題。暗号化は反射やSYNフラッドを止めない。

    4. 平文に戻すと盗聴と改ざんを受けうるだけで、偽装や過負荷への対策にはならない。

  5. ある機器のTCP実装は、接続ごとの初期シーケンス番号が規則的で、外部から予測できる。この状態への対応として最も適切なものはどれか。

    1. 問題は番号の推測のしやすさで、通信が暗号化されているかとは別の観点。初期値は推測されにくくする必要がある。

    2. 接続数の上限は資源の消費を抑える対策で、番号の推測による割込みを防ぐものではない。

    3. 送信元アドレスは申告で偽れる。アドレスが正しく見えても、割込みの恐れは消えない。

    4. 正解。シーケンス番号を推測されると通信に割り込まれうる。初期値は推測されにくくする。

  6. 自社が公開するUDPのサービスが、送信元を偽られた小さな要求に対し、大きな応答を第三者へ送っていた。起きていることの説明として最も適切なものはどれか。

    1. 割込みは、確立した通信の番号を推測される場合の話。ここでは偽った送信元宛てに応答が送られている。

    2. 正解。偽った送信元へ応答を返させる反射。UDPなどでは応答が大きいと増幅にもなる。

    3. SYNフラッドは接続状態の資源の枯渇。UDPの大きな応答が第三者へ送られる現象とは別。

    4. 盗聴は平文の通信の弱点。ここでは応答が偽った送信元へ送られていることが問題。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 暗号化を導入しても残るTCP/IPの弱点と、それぞれの対策を、頭の中で整理してみよう。

    答えを開く

    TLS・SSH・IPsecは盗聴と改ざんを防ぐが、送信元の偽装を使う反射やSYNフラッドは止めない。偽装には、境界で不自然な送信元を遮断する。資源の枯渇には、接続数の上限やSYNクッキーで備える。一つに頼らず、多層で備える。

    思い浮かんだ要素にチェック

  2. SYNクッキーが資源の消費を抑えられる理由を、頭の中で説明してみよう。

    答えを開く

    SYNフラッドは、接続の管理に資源を使い果たさせる攻撃。SYNクッキーは、確認が済むまで接続の情報を持たないので、確認が済まない大量の要求を受けても資源を消費しにくい。接続数の上限とあわせて、資源の消費を抑える対策として挙げられる。

午後問題にチャレンジ

動画の午後問題です。ログを読んで、答えを頭の中で決めてから開いてください。

通信の調査記録（ダミー）
サーバの管理に、Telnetを使っている（社内LAN）
同じLAN上の端末で、パケットを取得して確認した
取得内容に、管理者のIDとパスワードが読み取れた
要件: 認証情報を、通信中に読み取られないようにする

適切な対策は、どれ？

答えを開く

管理の通信を暗号化する（代表がSSH）

よくある誤答

  • 外部からのTelnetをFWで遮断する … 取得は同じLAN内で、通信は境界のFWを通らない
  • パスワードを長く複雑にする … 平文で流れるため、長くても通信中にそのまま読み取られる
