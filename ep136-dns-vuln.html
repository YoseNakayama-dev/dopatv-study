#36 ・ 第3章 情報セキュリティにおける脆弱性

DNSの脆弱性 仕様・設定・実装のどこが弱いか

  1. DNSは標準では応答が本物かを確かめず、照合の要素が予測しやすいと偽の応答が通る余地がある。
  2. 答えはTTLの間キャッシュされるので、偽の答えが入ると影響が続く。弱点は仕様・設定・実装に分ける。
  3. 設定の弱点は再帰やゾーン転送の開けすぎ、内部名の載せすぎ、兼用。実装はソフトの更新遅れ。

  1. 動画で出た問題DNSの仕様上の弱点として、適切なのは？

    1. 設定の弱点（仕様ではない）

    2. 実装の弱点（仕様ではない）

    3. 標準では出どころを確かめない

    4. 設定の弱点（仕様ではない）

  2. キャッシュDNSサーバに偽の答えが入ると、その後も利用者への影響が続く。主な理由として最も適切なものはどれか。

    1. 偽の答えが入った場合でも、権威サーバの登録内容は正しいままのことがある。影響が続くのはキャッシュの性質による。

    2. 正解。有効期間の間は問い合わせなくても同じ答えが返るので、偽の答えが入ると影響が続く。

    3. 端末の設定が正規のままでも、キャッシュの偽の答えによる影響は起きる。

    4. ゾーン転送は登録情報を渡す機能で、キャッシュの偽の答えを複製するものではない。

  3. キャッシュDNSサーバが、どのアドレスからの再帰問い合わせにも応答する設定になっている。この弱点の分類として最も適切なものはどれか。

    1. 正解。再帰問い合わせを誰にでも許すのは設定の弱点で、踏み台にされうる。

    2. 許可範囲は設定で決められる。仕様の弱点は、応答が本物かを確かめにくい点など。

    3. ソフトの脆弱性とは別の話。許可範囲を設定で見直す必要がある。

    4. 再帰は通常の動作だが、誰にでも許す点が設定の弱点になる。

  4. 古い版のDNSサーバソフトを使い続け、すでに公開されている脆弱性が残っていた。弱点の分類として最も適切なものはどれか。

    1. ソフト自体の脆弱性は実装の弱点。仕様の弱点とは分けて考える。

    2. 許可範囲の見直しは設定の弱点への対応で、ソフトの脆弱性は残る。

    3. 兼用は設定の弱点の1つで、ソフトの更新遅れとは別。

    4. 正解。ソフトウェア自体の脆弱性は実装の弱点で、更新が遅れると公開済みの弱点が残る。

  5. 公開ゾーンに、社内サーバの名前を載せている。この評価として最も適切なものはどれか。

    1. TTLは答えを保持する期間で、外部に見えるかどうかとは関係しない。

    2. 正解。内部の名前が見えると、構成が漏れ、攻撃の前段の情報収集に使われうる。

    3. 内部の名前が見えると、情報収集に使われうる。

    4. 載せすぎは情報の漏えいの問題で、登録内容の改ざんとは別。

  6. 権威サーバとキャッシュサーバを1台で兼用している。この構成の評価として最も適切なものはどれか。

    1. 正解。兼用は攻撃を受ける面を広げる設定の弱点。

    2. 兼用は攻撃を受ける面を広げる。

    3. 兼用は攻撃を受ける面を広げる構成の問題で、ソフトの脆弱性を直す更新とは別。更新しても兼用による面の広がりは残る。

    4. どの役割を同じサーバに置くかは運用者が決める構成で、兼用が仕様で求められるわけではない。攻撃を受ける面を広げるので設定の弱点に入る。

頭の中で考える

  1. DNSの弱点を「仕様・設定・実装」に分けて考えると、何が嬉しいか。頭の中で説明してみよう。

    答えを開く

    弱点ごとに原因の種類が違うので、対策も対応づけて整理できる。仕様は応答が本物かを確かめにくい点、設定は開けすぎ・載せすぎ・兼用、実装はソフトの更新遅れ。

    思い浮かんだ要素にチェック

  2. 偽の応答が通る余地が生まれる条件と、通った後に影響が長引く理由を頭の中で説明してみよう。

    答えを開く

    標準では応答の真偽を確かめる仕組みがなく、問い合わせの内容や識別子などとの照合に頼る。照合の要素が予測しやすいと偽の応答が通る。通ると答えがTTLの間キャッシュされ、影響が続く。
