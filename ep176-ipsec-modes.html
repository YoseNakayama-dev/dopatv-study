IPsecの概要と二つのモード ヘッダを残すか包むか

  1. IPsecはIP層でパケットを守る。トランスポートは元のIPヘッダを残し、トンネルは全体を包んで新ヘッダを付ける。
  2. 保護されるのはトンネルの外側の区間だけ。トランスポートはIPヘッダが見え、通信相手のアドレスが分かる。
  3. 両端の方式・モード・設定をそろえ、長い鍵か証明書で認証し、NAT越えの可否を事前に確認する。

  1. 動画で出た問題IPsecのトンネルモードの説明として、適切なのは？

    1. ヘッダを残すのはトランスポートモード

    2. ゲートウェイ間で使われる

    3. 全体を保護し新ヘッダを付加

    4. 暗号化もでき、拠点間VPNに使われる

  2. 本社と支社のVPN装置の間にIPsecのトンネルを張った。支社の端末から支社のVPN装置までのLAN区間の通信について、適切な説明はどれか。

    1. 正解。保護されるのはトンネルの外側の区間だけで、拠点内のLANはそのままの通信になる。保護区間を把握し、拠点内は別に守る。

    2. トンネルモードでも保護されるのはトンネルの外側の区間だけ。端末からVPN装置までのLAN区間は保護外。

    3. 拠点内のLANではそのままの通信になるので、拠点内の対策は別に必要。

    4. ESPで暗号化されるのはトンネルの区間。拠点内のLANは保護外なので、盗聴のおそれは残る。

  3. 本社のVPN装置でIPsecの暗号方式の設定を変更した直後から、支社とつながらなくなった。支社の装置の設定は変えていない。最初に確認すべき点はどれか。

    1. 変更したのは本社側で支社側は未変更なので、疑うのは両端の不一致。トンネルモードでも、両端で方式や設定が合わないとつながらない。

    2. 正解。両端で方式とモードをそろえて設定する必要がある。片側だけの変更は障害の原因になりやすい。

    3. モードを切り替えても、両端の設定が合わなければつながらない。方式とモードは両端でそろえる。

    4. 事前共有鍵が弱いと破られるおそれがある。十分に長い鍵を使うのが対策で、短くするのは逆。

  4. 社内の二台の端末間を、IPsecのトランスポートモード（ESPで暗号化）で保護している。経路上の機器で通信を観測する者から見える情報として、適切なものはどれか。

    1. トランスポートモードは元のIPヘッダを残す。IPヘッダは見える。

    2. 元のパケット全体を保護して新しいヘッダを付けるのはトンネルモードの説明。

    3. トランスポートモードは中身（ペイロード）を保護する。ESPで暗号化していれば、内容はそのままは読めない。

    4. 正解。トランスポートモードは元のIPヘッダを残して中身を保護する。通信相手のアドレスは外から分かる。

  5. 拠点間のIPsecで、事前共有鍵に短い単語を設定していた。評価と対策の組合せとして適切なものはどれか。

    1. 正解。事前共有鍵が弱いと破られるおそれがある。十分に長い鍵を使うか、証明書で認証する。

    2. 暗号化の有無とは別に、事前共有鍵が弱いと破られるおそれがある。

    3. モードの選択で隠れるのはアドレスの見え方。事前共有鍵が弱い問題は残る。

    4. NAT越えの確認は通信の通り道の話で、鍵の強さとは別の確認事項。

  6. 拠点間IPsecを構築する。支社側のルータはNATを行っている。構築前の対応として適切なものはどれか。

    1. NATを越えられるかの確認が要る。NATがあると通信方法の調整も必要になる。

    2. 正解。NATがある場合は、越えられるか事前に確認する。NAT越えの対応は機器によって異なる。

    3. 使えなくなると決まるわけではなく、越えられるかを確認する。対応は機器によって異なる。

    4. 鍵の長さはNAT越えとは別の確認事項。NAT越えの可否は事前に確認する。

頭の中で考える

  1. トランスポートモードとトンネルモードの違いを、IPヘッダの扱いと通信相手のアドレスの見え方に着目して頭の中で説明してみよう。

    答えを開く

    トランスポートモードは元のIPヘッダを残して中身だけを保護するので、通信相手のアドレスは外から見える。トンネルモードは元のパケット全体を保護して新しいヘッダを付けるので、ESPで暗号化すれば元のアドレスも外から見えない。

    思い浮かんだ要素にチェック

  2. 拠点間にIPsecトンネルを張ったのに、情報漏えいが起こりうる場所と対策を頭の中で説明してみよう。

    答えを開く

    保護されるのはトンネルの外側の区間だけで、拠点内のLANはそのままの通信になる。保護される区間とされない区間を把握し、拠点内の通信は別に守る。

午後問題にチャレンジ

拠点間VPNの構成に関する調査記録（ダミー）
現状: 本社と支社のLANを、インターネット越しに接続したい
各端末の設定は、変更できない
各拠点の境界に、VPN装置を置くことができる
要件: 拠点内部のアドレスを、インターネット上に見せない

要件を満たす構成として、適切なのは？

答えを開く

拠点の境界のVPN装置同士で、ESPを使ったIPsecのトンネルモードにする

よくある誤答

  • 各端末で、トランスポートモードを設定する … 端末の設定を変更できない
  • 境界のVPN装置同士で、トランスポートモードを使う … 装置自身の通信向けで、LAN内の通信全体を保護できず、内部アドレスも隠せない
