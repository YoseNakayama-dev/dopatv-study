#15 ・ 第2章 情報セキュリティにおける脅威

BOF攻撃への対策 カナリア・DEP・ASLRの守備範囲と限界

  1. BOFが成功すると、脆弱なプロセスの権限で任意のコードが動く。影響の大きさは動いていた権限で決まる。
  2. 根本は長さの確認と修正。カナリア・DEP/NX・ASLRは緩和で、それぞれ防げる範囲に限界がある。
  3. setuidの最小化はBOFを消さず被害を抑える。どれか1つで完全には防げないので、多層で守る。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題DEP／NXが防ぐのは、次のうちどれ？

    1. 安全な関数・境界チェックの役割

    2. ASLRの役割

    3. データ領域上のコードの実行

    4. 権限の話で、DEPは無関係

  2. BOFのある管理コマンドを、コードは修正せず、ビルド設定でスタック保護だけ有効にした。評価として最も適切なものはどれか。

    1. コードは直っていない。カナリアは緩和で、脆弱性は残る。

    2. 正解。復帰時に番兵の値を検査し、変化があれば止める。止まるので可用性への影響もある。

    3. 書き込み自体は起きる。それを検知する仕組み。

    4. 属性はそのまま。スタック保護はsetuidの設定を変えない。

  3. DEP／NXが有効な環境で、攻撃者が、入力に仕込んだコードではなく、プロセス内に既にあるコードを使い回す手口を使った。DEP／NXの評価はどれか。

    1. 正解。DEP／NXは注入コードの実行を防ぐ。既存コードを使い回す手口には別の対策が要る。

    2. 防げるのは注入されたコードの実行。既存コードの再利用は実行可能な領域のコード。

    3. 配置をランダム化するのはASLR。DEP／NXは領域を実行不可にする。

    4. 長さの確認は安全な関数・境界チェックの役割。DEP／NXでは代わりにならない。

  4. ASLRが有効な環境で、別の不備からアドレス情報が漏れていた。評価として最も適切なものはどれか。

    1. 確率的ではあるが、「常に突破される」は言い過ぎ。決め打ちを難しくする効果はある。

    2. 漏えいがあると配置を知られるので、影響がないとは言えない。

    3. DEP／NXは領域を実行不可にする仕組みで、アドレスの漏えいを防ぐものではない。

    4. 正解。アドレスの漏えいなどがあると、ASLRの効果は落ちる。

  5. BOFのあるsetuid rootの管理コマンドについて、被害を抑える方針として最も適切なものはどれか。

    1. 緩和策だけでは脆弱性が残る。権限そのものの見直しも要る。

    2. 正解。不要なsetuidを外し、root以外の低権限ユーザーで動かす。BOFは消えず、被害を抑える。

    3. 特権が不要になったら、すぐ手放す。保持し続けると影響が大きいまま。

    4. ファイルの改ざん監視は、入力の処理で起きるBOFの悪用への対策ではない。

  6. 同じ種類のBOFが、一般ユーザー権限のサービスと、setuid rootのコマンドの両方にある。悪用されたときの被害の判断として最も適切なものはどれか。

    1. 正解。影響の大きさは、脆弱なプロセスが動いていた権限で決まる。

    2. 入力の長さは成立の条件で、被害の大きさを決めるものではない。

    3. 得られるのは脆弱なプロセスの権限なので、権限により影響は変わる。

    4. カナリアは検知して止める仕組みで、権限を下げるものではない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. スタックカナリア・DEP/NX・ASLRを入れても、BOFの対策として十分とは言えない理由を、頭の中で説明してみよう。

    答えを開く

    これらは緩和策で、脆弱性そのものは直らない。カナリアは値の漏えいなどで、DEP/NXは既存コードの再利用で、ASLRはアドレスの漏えいで効果が落ちる。根本は長さの確認と修正パッチで、緩和策は組み合わせて使う。

    思い浮かんだ要素にチェック

  2. setuid root のコマンドのBOFに対し、層をどう重ねるかを、頭の中で説明してみよう。

    答えを開く

    根本として長さの確認と修正を行い、緩和としてカナリア・DEP/NX・ASLRを有効にする。さらに不要なsetuidを外す、root以外の低権限ユーザーにする、特権を早く手放すことで、悪用されても被害を抑える。
