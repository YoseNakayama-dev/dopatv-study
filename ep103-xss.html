#3 ・ 第2章 情報セキュリティにおける脅威

XSS 出力の扱いで起きる攻撃と防御

  1. XSSは、入力を適切な処理なしにHTMLへ出力し、ブラウザがコードとして解釈することで起きる。
  2. 種類は反射型・格納型・DOM Based。HTMLの入力を許さない場合の根本対策は出力時のエスケープで、出力位置ごとに処理を変える。
  3. HttpOnly・CSPは影響や実行を抑える追加の層、WAFは見逃しもある補助。原因は直らない。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題XSSの根本的な対策は？

    1. 入力の検査は限定的（属性やURLでは < が無くても成立）

    2. 出力時に、HTMLエスケープする（位置に合わせる）

    3. HttpOnlyは影響を減らす保険

    4. SQLインジェクション向けの対策

  2. < > & " ' をHTMLエスケープしたうえで、<input value=（入力値）> のように属性値をクォートで囲まずに出力している。正しい評価はどれか。

    1. 正解。クォートが無いと、空白の後ろが別の属性として解釈されうる。属性値はクォートで囲む。

    2. 出力位置ごとに必要な処理が違う。属性値はクォートで囲むことも必要。

    3. 属性を追加されればスクリプトが動きうる。影響はCookieに限らない。

    4. HttpOnlyは影響を減らす保険で、XSSは防げない。

  3. 利用者が登録したWebサイトのURLを、プロフィールのリンク先（href）にHTMLエスケープして出力している。残る問題として最も適切なものはどれか。

    1. 見た目の話で、XSSの成立条件とは関係しない。

    2. スキームの問題はエスケープでは防げない。

    3. SQLインジェクションとは別の話。

    4. 正解。入力から作るURLは http か https で始まるものだけを許可する。

  4. ブラウザ側のJavaScriptが、URLから取り出した値を innerHTML で画面に書き込んでいる。サーバ側のWAFのログには攻撃の痕跡が無かった。最も適切な説明はどれか。

    1. 痕跡が無いことは遮断の証拠にならない。

    2. 格納型はサーバに保存される型で、むしろサーバ側に入力が残る。

    3. 正解。DOM Based XSS はブラウザ側の書き込みで起き、サーバ側のフィルタやWAFでは見逃しやすい。

    4. 反射型はリクエストの内容がサーバの応答にそのまま返る型。

  5. 掲示板で、太字やリンクなど一部のHTMLによる装飾を利用者に許したい。XSS対策として最も適切なものはどれか。

    1. ブラックリストの置換は保険にとどまり、回避されうる。

    2. XSSは防げるが、装飾を許すという要件を満たせない。

    3. 正解。HTMLを許す場合は、構文解析して許可リストの要素だけを抽出する（実装は複雑）。

    4. CSPは追加の層で、主防御ではない。

  6. XSSが残っているページで、セッションIDを入れたCookieに HttpOnly 属性を付けた。これで抑えられる被害として最も適切なものはどれか。

    1. 正解。HttpOnlyはスクリプトからのCookie参照を禁止する。ただしXSSの全脅威を防ぐものではない。

    2. 偽ページの表示はCookieと関係なく起こりうる。

    3. Cookieを読めなくしても、書き込ませる攻撃は別の問題。

    4. 誘導はスクリプトの実行で起こせるので、HttpOnlyでは抑えられない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. XSSの対策を「入力時に < を削除する」で済ませてはいけない理由を、頭の中で説明してみよう。

    答えを開く

    入力の検査は効果が限定的で、属性値やURLの位置では < が無くても成立しうる。原因は出力の扱いなので、出力時に出力位置に合わせてエスケープするのが本筋。

    思い浮かんだ要素にチェック

  2. プロフィールの自己紹介をそのままHTMLに出しているページ。原因・型・直し方を頭の中で説明してみよう。

    答えを開く

    原因は、保存された入力をエスケープせずにHTMLへ出力していること。保存された内容が他の閲覧者に届くので格納型。出力時にHTMLエスケープを入れて直す。

よくある誤答

  • 入力欄で < を禁止しなかった … 正当な入力も壊し、属性やURLでは < 無しでも成立。出力時の対処が本筋
  • HttpOnly が無かった … 影響を減らす話で、原因ではない
