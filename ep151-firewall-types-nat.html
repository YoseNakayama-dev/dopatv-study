#51 ・ 第5章 情報セキュリティ対策技術（1）予防・検知・防御

FWの種類とアドレス変換 状態を見るか中身を見るか

  1. パケットフィルタ型は高速で単純だが状態も中身も見ない。ステートフル型は状態表で応答を許可するが、状態表は有限。
  2. アプリケーションゲートウェイ型は中身まで検査できるが、処理が重く、対応するアプリが限られる。
  3. NATはアドレス変換、NAPTはポートも変換して1つのアドレスを共有する。NATはFWの代わりにならない。

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題NAPT（IPマスカレード）の説明として、適切なのは？

    1. それは、1対1のNAT

    2. それは、ゲートウェイ型の機能

    3. ポート番号も変換し、共有

    4. 通信を許可する機能ではない

  2. パケットフィルタ型のFWで、内部PCから外部のWebサイト（宛先ポート443）への要求を許可する規則だけを置いたところ、応答が内部PCに届かない。原因として最も適切なものはどれか。

    1. 正解。パケットフィルタ型は通信の状態を見ないので、戻りの通信を通すには戻り用の規則が別に要る。

    2. 応答を自動で許可するのは、状態を記憶するステートフル型の特徴。パケットフィルタ型にはない。

    3. 状態表を持つのはステートフル型。パケットフィルタ型は状態を見ない。

    4. パケットフィルタ型はアプリケーションの中身を見ない。アドレスやポート等の規則で判断する。

  3. 社内の業務アプリの通信を、内部と外部を分断した状態で、アプリケーション層の中身まで検査したい。処理が重くなる点は許容できる。選択と留意点として適切なものはどれか。

    1. パケットフィルタ型は高速で単純だが、アプリケーションの中身は見ない。

    2. 正解。アプリ層で中継して中身まで検査できる。処理は重く、対応するアプリが限られる。

    3. 中身まで検査できると整理されるのはアプリケーションゲートウェイ型。ステートフル型の要点は、状態の記憶と応答の許可。

    4. NATはFWの代わりにならず、中身の攻撃は防げない。

  4. 社内の複数PCが、1つのグローバルアドレスを共有して外部のサイトへ同時に接続している。NAPT（IPマスカレード）で応答が正しいPCへ戻る仕組みとして適切なものはどれか。

    1. アドレスだけを1対1で変えるのはNAT。NAPTはポート番号も変換して、1つのアドレスを共有する。

    2. NATは内部のプライベートアドレスを外に見せない。外にはそのまま出ない。

    3. 応答は変換表で内部に戻す。中身の検査で判断するのではない。

    4. 正解。アドレスとポート番号を変換し、変換表に従って応答を内部へ戻す。

  5. NAPTを導入したので、プライベートアドレスは外から見えず、専用のFWは要らないと提案された。評価として適切なものはどれか。

    1. 隠蔽は副次効果で、NATはFWの代わりではない。規則による許可・拒否は別に要る。

    2. 変換表は応答を内部に戻すためのもので、通信の許可・拒否の規則の代わりではない。NATはFWの代わりにならない。

    3. 正解。NATの目的はアドレスの節約と隠蔽で、FWの代わりではない。中身の攻撃も防げない。

    4. 静的NATは公開サーバ用に固定で対応づける仕組み。攻撃を防ぐものではなく、FWの代わりにもならない。

  6. ステートフルインスペクション型FWの説明として適切なものはどれか。

    1. 正解。状態表に通信の状態を記憶して応答を自動で許可する。状態表は有限で、大量の接続で枯渇しうる。

    2. 戻り用の規則が別に要るのはパケットフィルタ型。ステートフル型は応答を自動で許可する。

    3. 状態表は有限で、大量の接続で枯渇しうる。受け付け続けられるとは言えない。

    4. 中身まで検査できるのはアプリケーションゲートウェイ型。ステートフル型の特徴は状態の記憶。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 要件が「中身の検査は不要、処理は高速に保つ、応答は届く」のとき、どの方式を選び、何に注意するか、頭の中で説明してみよう。

    答えを開く

    ステートフルインスペクション型を選ぶ。通信の状態を状態表に記憶して応答だけを自動で許可でき、戻り用の規則が要らない。中身の検査は要件にないので、中身まで検査するゲートウェイ型は不要。注意点は、状態表が有限で大量の接続で枯渇しうること。

    思い浮かんだ要素にチェック

  2. NAPTを使っているのにFWが必要な理由を、頭の中で説明してみよう。

    答えを開く

    NAPTの目的はアドレスの節約と隠蔽で、内部のアドレスが見えにくくなるのは副次効果。通信の許可・拒否の規則を担うものではなく、中身の攻撃も防げないので、FWの代わりにならない。

通信障害の調査記録（ダミー）
対象: 社内PCから外部Webサイトへの通信（ダミー）。要件は、中身の検査は不要で、処理を高速に保つこと
FWの方針は、外部から始まる通信（新規接続）を、すべて拒否
FWの種類は、パケットフィルタリング型。パケット1つ1つを、アドレスとポート番号の規則で判断
PCが送った要求は、FWを通って、外部のWebサイトに届いている
Webサイトからの応答は、外部の443番ポートから、PCの一時的なポート番号へ戻るが、FWで遮断された

高速を保ち、応答も届く方式として、適切なのは？

答えを開く

通信の状態を記憶し、応答の戻りだけを許可する方式

よくある誤答

  • 内部から外部への通信を禁止する … 要求は、FWを通って届いている
  • 外部→内部のポートを全開にする … 方針は、外部から始まる通信を全拒否
