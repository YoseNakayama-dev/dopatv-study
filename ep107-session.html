#7 ・ 第2章 情報セキュリティにおける脅威

セッション管理の不備 IDの扱いを誤るとなりすまされる

  1. セッション管理の不備は、IDの推測・盗用・固定化で、パスワードを知らなくてもなりすましが成立する。
  2. 対策は、暗号論的乱数のID、ログイン成功後の再発行と旧IDの無効化、URLにIDを載せないこと。
  3. HttpOnly・SameSiteや有効期限は補助。Secureは盗聴対策。XSSや盗聴の対策も別に必要になる。

用語カード

クイズ

  1. 動画で出た問題セッション固定化の根本的な対策は？

    1. 長くするほど、リスクが増えうる

    2. ログイン成功後にIDを再発行する

    3. XSS対策。固定化の根本対策ではない

    4. URLからIDが漏れるおそれ

  2. 自作のセッションID生成が「現在時刻＋連番」になっている。対策として最も適切なものはどれか。

    1. 元の値が予測できる規則では、ハッシュにしても根本の解決にならない。暗号論的乱数を使う。

    2. 規則が同じなら、桁数を増やしても予測の手がかりは残る。

    3. IDは不透明であるべきで、個人情報を含めてはいけない。

    4. 正解。サーバ製品のセッション管理機能を使い、暗号論的乱数で予測困難なIDにする。

  3. Cookieを使えない旧端末向けに、セッションIDをURLに含めて引き回している。見直すべき理由として最も適切なものはどれか。

    1. 正解。URLのIDはRefererなどから漏れるおそれがあるため、URLに含めない。

    2. URLの長さの制限は、セキュリティ上の理由ではない。

    3. 有効期限はサーバ側の設計の話で、URLかどうかとは関係しない。

    4. HTTPSならURLの経路上の内容も保護される。問題はRefererなどでの漏えい。

  4. ログアウトボタンが、ブラウザ側のCookieを削除するだけの実装になっている。ログアウト前にIDを盗まれていた場合の評価として最も適切なものはどれか。

    1. 削除されるのは利用者のブラウザの中だけ。盗んだ側が持つIDは残る。

    2. Secureは送信をHTTPSに限る属性で、サーバ側の有効性とは関係しない。

    3. 正解。ログアウトはサーバ側でも無効化する。Cookie削除だけでは盗まれたIDは無効にならない。

    4. ブラウザ側の操作は、サーバ側のセッションの状態を変えない。

  5. XSSの脆弱性が残るサイトで、セッションCookieにHttpOnly属性を付けた。この属性の説明と評価として最も適切なものはどれか。

    1. 盗用の経路を限定するだけで、XSS自体は防げない。問題が全て解消するとは言えない。

    2. 正解。HttpOnlyはXSS経由の盗用を限定する。XSS自体は防げないので、XSS対策が別に要る。

    3. それはSecure属性の説明。取り違えやすい。

    4. それはSameSite属性の説明。取り違えやすい。

  6. セッションの有効期限を、CookieのExpiresだけで管理していて、サーバ側にタイムアウトが無い。改善として最も適切なものはどれか。

    1. 有効期限は必要以上に長くしない。長いほどリスクが増えうる。

    2. 期限の判定をクライアントに任せると、改変された場合に守れない。サーバ側で判定する。

    3. ブラウザ側の処理に頼る点は同じで、IDをURLに載せる点も不適切。

    4. 正解。タイムアウトはサーバ側（アイドル・絶対）で管理し、期限切れのIDを拒否する。

頭の中で考える

  1. ログイン前から同じセッションIDを使い続けると、なぜ固定化を許してしまうのか。頭の中で説明してみよう。

    答えを開く

    攻撃者が先に用意したIDを利用者が使ったままログインすると、そのIDがログイン済みの状態に紐づく。IDが変わらないので、同じIDを知る攻撃者もログイン状態になる。ログイン成功後にIDを再発行し、旧IDを無効にして防ぐ。

    思い浮かんだ要素にチェック

  2. 「IDを暗号論的乱数で作っているから、セッション管理は安全」と言えない理由を、頭の中で説明してみよう。

    答えを開く

    乱数で推測は防げても、盗用（XSS・盗聴・Referer漏えい）や固定化は別の経路で起きる。ログイン後の再発行、URLにIDを載せない、Secure等の属性、サーバ側の無効化・期限管理、XSS対策やHTTPSを重ねる。

    思い浮かんだ要素にチェック

→ 同じIDで、別の端末からもアクセスできた
// 通信はHTTPSのみ。IDはURLに含まれず、漏えい経路は無い

固定化を許した根本原因は？

答えを開く

ログイン成功後に、セッションIDを再発行していない

よくある誤答

  • IDが推測しやすい … 前提は暗号論的乱数。固定化は予測が不要
  • 盗聴で漏れた … 前提では漏えい経路は無い。原因はID据え置き
