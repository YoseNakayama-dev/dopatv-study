#45 ・ 第5章 情報セキュリティ対策技術（1）予防・検知・防御

ホストの要塞化の概要 入口を減らす考え方

  1. 要塞化は設定を見直し、攻撃される入口（攻撃対象領域）を減らす。初期状態は使いやすさ優先。
  2. 基本は最小構成・最小権限・既定値の見直し・維持。基準を決め、適用前に検証環境で確認する。
  3. 運用中の構成のずれが起きうる。未知の脆弱性は防げないので、多層防御の一部として使う。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題ホストの要塞化に沿った対応として、適切なのは？

    1. 権限が大きいほど、被害も広がる

    2. 初期値は広く知られている

    3. 入口が増える

    4. 必要なものだけ残す

  2. 新規サーバの要塞化を、チェックリストを使って進める。手順の組み立てとして最も適切なものはどれか。

    1. 基準は公開された指針を参考にできるが、適用の前に検証環境で業務への影響を確認する。本番に一括適用してはいけない。

    2. 正解。構成基準を決める、適用する、検査する、維持する、の順。適用前に検証環境で業務への影響を確かめる。

    3. 基準を決めるのは適用の前。後から作ると何に沿って適用したのかが定まらない。

    4. 最初に決めるのは構成基準で、検査は適用のあと。検査から始める順序ではない。

  3. 障害対応のため、運用担当に管理者権限を付けたままにする運用が提案された。最小権限の考え方に沿った案はどれか。

    1. 正解。管理者権限は、必要な人に、必要な間だけ与える。

    2. ログは事後の調査に役立つが、権限が大きいほど侵害されたときの被害も広がる。権限を絞る対策の代わりにならない。

    3. 権限が大きいほど被害も広がる。全員に強い権限を与えるのは最小権限の逆。

    4. 通信を絞るのは別の対策で、権限の範囲は変わらない。最小権限の対策にはならない。

  4. 全サーバに構成基準を適用済みの組織で、「要塞化したので、未知の脆弱性による侵害も起きない」との説明があった。最も適切な評価はどれか。

    1. 入口を減らしても、残った機能に未知の脆弱性があれば防げない。「成立しない」は言い過ぎ。

    2. 未知の脆弱性を防げないのは限界だが、入口を減らす効果はある。「意味がない」は言い過ぎ。

    3. 正解。要塞化では未知の脆弱性までは防げない。多層防御の一部として使う。

    4. 検証環境での確認は、業務を止めないための手順。未知の脆弱性を防ぐ根拠にならない。

  5. 半年前に構成基準を適用して検査も済ませたサーバで、保守時に変更された設定が基準から外れたまま残っていた。対策として最も適切なものはどれか。

    1. 運用中に設定が変わって基準から外れる恐れがある。定期的な確認が要る。

    2. 維持には修正プログラムの適用も含まれる。適用を止めると脆弱性が残る。

    3. 基準に合わせて設定を保つのが目的。基準を現状に合わせると、入口を減らす意味が失われる。

    4. 正解。維持は、修正プログラムの適用と、設定の定期的な確認で行う。

  6. サーバ導入時の管理用アカウントを初期パスワードのまま運用開始し、「変更は余裕のあるときに」という計画が出された。この計画への評価として最も適切なものはどれか。

    1. 初期状態は使いやすさ優先で、不要な機能が有効なことが多い。だからそのままにしない。

    2. 正解。初期値は広く知られているため、最初に変える。

    3. 修正プログラムの適用は維持の項目で、初期値を変える代わりにはならない。

    4. 既定値の見直しは、初期アカウント・初期パスワード・既定の設定のすべてが対象。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 要塞化を進める手順と、適用の前に検証環境で確認する理由を、頭の中で説明してみよう。

    答えを開く

    構成基準を決める、適用する、検査する、維持する、の順に進める。適用前に検証環境で業務への影響を確認するのは、止めすぎると業務が止まるため。

    思い浮かんだ要素にチェック

  2. 要塞化を実施しても安全とは言い切れない理由と、その位置づけを、頭の中で説明してみよう。

    答えを開く

    未知の脆弱性までは防げず、運用中に設定が基準から外れる恐れもあるため。要塞化は多層防御の一部として使う。
