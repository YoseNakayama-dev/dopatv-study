#83 ・ 第8章 システム開発におけるセキュリティ対策

システム開発とセキュリティ 後付けせず作り込む

  1. 脆弱性の多くは、設計の考慮漏れや実装の誤りとして、開発の中で作り込まれる。
  2. 一般に工程が進むほど修正の手間・費用・影響範囲は大きい。要件・設計の不備は実装では直せない。
  3. セキュリティバイデザインで上流から組み込む。委託では書いた対策だけが作られ、ゼロにはならず運用で修正を続ける。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題セキュリティバイデザインの説明として、適切なのは？

    1. 公開後に直すのは、後付けの考え方

    2. 直前の一括修正は、手戻りが大きい

    3. 企画・設計の段階から対策を組み込む

    4. 委託しても、発注側の責任は残る

  2. テスト工程で、機能ごとの権限チェックが設計に無いため、権限のない操作ができると判明した。原因は設計の不備である。最も適切な対応はどれか。

    1. 要件や設計の不備は、実装では直せない。仕様の見直しが必要になる。

    2. 正解。設計の不備は仕様の見直しが必要で、実装やテストにも影響する。

    3. 公開後の修正は、修正の配布や利用者への影響が大きい。見つかった不備は公開前に直す。

    4. 脆弱性がゼロにならないので運用で修正を続けるのであり、見つかった設計不備を放置する理由にならない。

  3. 委託開発の仕様書にはセキュリティ対策の記載が無い。受託側は仕様どおりに完成させたが、検収後に脆弱性が見つかった。本質的な原因はどれか。

    1. 正解。委託開発では、要件に書かれた対策しか作られない。必要な対策は仕様書や契約に明記する。

    2. 委託しても、発注側の責任は残る。

    3. 要件に書かれていない対策は作られない。

    4. 脆弱性の多くは、設計の考慮漏れや実装の誤りとして開発の中で作り込まれる。

  4. 全工程で対策を組み込み、診断でも指摘がないままサービスを公開する。運用の方針として適切なものはどれか。

    1. すべて対策しても、脆弱性はゼロにならない。指摘がないことは、残っていない証明にならない。

    2. 公開後の修正は、修正の配布や利用者への対応が要り、影響が大きい。

    3. 上流で組み込んでも、脆弱性はゼロにならない。公開後も修正を続ける。

    4. 正解。対策を尽くしてもゼロにはならないので、運用で情報を集めて修正を続ける。

  5. 設計の不備が公開後に見つかった場合、設計段階で見つかった場合と比べて増えることとして適切なものはどれか。

    1. 一般に、工程が進むほど修正の手間・費用・影響範囲は大きい。

    2. 正解。公開後は修正の配布や利用者への対応も要り、影響範囲が広がりやすい。

    3. 設計の不備は実装では直せず、仕様の見直しが必要になる。公開後は利用者への連絡も要る。

    4. 一般に工程が進むほど費用は大きくなる。公開後は、修正の配布や利用者への影響が大きい。

  6. 会員Webの設計レビューで、画面とDBの設計は終わったが、脅威の洗い出しをしていないと分かった。セキュリティバイデザインに沿う進め方はどれか。

    1. 正解。設計では脅威を洗い出し、対策を入れ込む。企画・設計の段階から対策を組み込む考え方。

    2. 気付いた分だけ足すのは後付けの発想。設計の不備は作り直しになりやすい。

    3. 設計では脅威を洗い出して対策を入れ込む。運用で行うのは、脆弱性情報を集めて修正を続けること。

    4. 設計の段階で脅威を洗い出して対策を入れ込む。実装後に回すと、設計の不備は作り直しになりやすい。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 公開後に設計の不備が見つかり、作り直しになった。実装で直せない理由と、今後どの工程で何を決めておくべきかを頭の中で説明してみよう。

    答えを開く

    要件・設計の不備は実装では直せず、仕様の見直しが必要になる。工程が進むほど修正の手間・費用・影響範囲は大きい。要件定義で守る対象と必要な対策を決め、設計で脅威を洗い出して対策を入れ込む。

    思い浮かんだ要素にチェック

  2. セキュリティ対策を受託側に任せきりにしてはいけない理由と、発注側がすべきことを頭の中で説明してみよう。

    答えを開く

    委託開発では、要件・仕様書・契約に明記した対策しか作られず、委託しても発注側の責任は残る。必要な対策を仕様書や契約に明記する。それでも脆弱性はゼロにならないので、運用で修正を続ける。

設計の開始前に行う対策として、適切なのは？

答えを開く

よくある誤答
