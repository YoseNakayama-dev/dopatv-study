#34 ・ 第3章 情報セキュリティにおける脆弱性

SMTPの脆弱性と対策 送信者を確かめない仕組みの弱点

  1. SMTPは送信者を確かめず、差出人の表示も自由に書け、そのままでは暗号化されない。
  2. 第三者中継は仕様ではなく設定の不備で成立し、踏み台化とブロックリスト登録を招く。
  3. 対策は送信者認証の必須化・TLS・送信ドメイン認証。TLSは強制しないと戻され、認証結果の扱いは運用次第。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題第三者中継を防ぐ対策として、適切なのは？

    1. 認証のない中継を拒否

    2. POP3は受信用で、送信の許可と無関係

    3. 圧縮は、送信者の確認と無関係

    4. 中継を許す設定は、変わらない

  2. 調査記録: 外部の1つのIPが、SMTP-AUTHなしで、自社ドメインではない差出人・宛先のメールの転送を依頼し、サーバはすべて受理していた。最も適切な対処はどれか。

    1. ログイン(SMTP-AUTH)を経ていないので、アカウントの漏えいが原因ではない。

    2. 正解。原因は認証なしの第三者中継を許す設定。SMTP-AUTHを必須にして拒否し、利用者の送信は認証つきのサブミッションポートへ分ける。

    3. SPFなどは送信ドメインを確かめる、なりすましへの備え。中継の防止とは別の話。

    4. ポートを変えても、中継を許す設定はそのまま残る。

  3. メールサーバにSTARTTLSを設定したが、TLSの利用は必須にしていない。盗聴・改ざんに関する評価として最も適切なものはどれか。

    1. 強制しないと暗号化なしに戻される余地がある。「必ず」とは言えない。

    2. 暗号化できる通信では、盗聴や改ざんの余地は小さくなる。効果がないわけではない。

    3. DMARCは送信ドメインを確かめる仕組みで、通信の暗号化とは別。

    4. 正解。TLSは強制しないと戻される余地があり、強制やMTA-STS等で補う。

  4. 自社のメールサーバでSPF・DKIM・DMARCによる送信ドメインの確認を導入した。認証なしの中継を許す設定が残っている場合の評価として最も適切なものはどれか。

    1. 送信ドメイン認証は、なりすましへの備え。中継の防止とは別の話。

    2. 確認結果をどう扱うかは運用で決める必要があり、完全に防げるとは言えない。

    3. 正解。中継の拒否はSMTP-AUTHの必須化で行い、送信ドメイン認証はそれとは別の備え。

    4. SMTP-AUTHは中継の拒否の対策。確認結果の扱いは運用で決める必要があり、無視してよいわけではない。

  5. OP25Bの説明として最も適切なものはどれか。

    1. 正解。OP25Bは事業者が行う、迷惑メール対策としての25番の出口の制限。

    2. これはSPF・DKIM・DMARCの説明。

    3. これはSMTP-AUTHを必須にして中継を拒否する対策。OP25Bは別物。

    4. これはTLS（STARTTLS等）の説明。

  6. 第三者中継を許す設定のため迷惑メールの踏み台にされ、自社のIPアドレスがブロックリストに載った。この影響として最も適切なものはどれか。

    1. 起きているのは送信の依頼の悪用で、受信箱の読み出しではない。

    2. 正解。ブロックリストに載ると、正規のメールまで他社に届かなくなる恐れがある。

    3. ここで起きているのは中継の悪用で、アカウントの漏えいとは別の問題。

    4. 暗号化の有無は中継の悪用とは別の弱点。ブロックリスト登録の影響ではない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 第三者中継が「仕様の弱点」ではなく「設定の不備」と言われる理由と、直し方を頭の中で説明してみよう。

    答えを開く

    SMTPが送信者を確かめない点は仕様だが、自社と無関係なメールまで受理して転送するのはサーバの設定で成立する。SMTP-AUTHを必須にして、認証のない中継を拒否する。

    思い浮かんだ要素にチェック

  2. 外部のIPがログインなしで送信を依頼し、読み出しはない調査記録。「パスワード漏えい」「盗聴」を原因から外せる根拠を頭の中で説明してみよう。

    答えを開く

    ログイン(SMTP-AUTH)を経ていないので、アカウントの漏えいは原因でない。盗聴はサーバの記録に残らないが、仮にあっても認証なしの送信依頼を受理した事象の説明にならない。原因は認証なしの中継を許す設定。

    思い浮かんだ要素にチェック

メールサーバの調査記録（ダミー）
対象: 自社のメールサーバ（ダミー）。外部へ大量送信している
接続元は外部の1つのIP。ログイン(SMTP-AUTH)なしで依頼
依頼は、宛先指定と本文の送信。受信箱の読み出しはなし
差出人も宛先も自社ドメインではなく、サーバは全て受理して転送
結果: 他社のブロックリストに、自社のIPが登録された

この事象の原因として、適切なのは？

答えを開く

認証なしの第三者の中継を許可する、サーバの設定

よくある誤答

  • 利用者アカウントの漏えい … ログインを経ていない
  • メール本文の盗聴 … 盗聴は読み取る行為。読み出しはなし
