コンテナ・Kubernetesのセキュリティ 分離の弱さと設定の落とし穴

  1. コンテナはホストのカーネルを共有するので、VMより分離は弱め。設定しだいで壁はさらに薄くなる。
  2. 特権・root実行・ホスト領域のマウントは危険。古い部品の脆弱性や焼き込んだ秘密情報も響く。
  3. Kubernetesは既定のままでは守れない。RBACの最小化、Secretの扱い、通信の制限が要る。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題コンテナとKubernetesの説明として、適切なものは？

    1. Secretは暗号化ではない

    2. カーネルを共有する

    3. 特権は分離を弱める

    4. latestは可変で安全を保証しない

  2. ログ収集のため、特権コンテナとして起動し、ホストのルートディレクトリ全体をマウントしている。アプリの不備でこのコンテナが侵害された場合の評価と対策として、最も適切なものはどれか。

    1. コンテナはホストのカーネルを共有する。OSごと分けるVMより分離は弱く、特権やマウントでさらに薄くなる。

    2. 正解。特権・root実行・ホスト領域のマウントは分離の壁を薄くする。非rootで動かし、権限を削り、共有は必要な領域だけにする。

    3. 検査はイメージの部品の脆弱性を見つけるもの。特権やマウントといった実行時の設定の危険は、検査では解消しない。

    4. RBACはKubernetesのAPIに対する権限。ホスト領域をコンテナに共有する設定の危険は、RBACでは防げない。

  3. 半年前に構築して検査を通したイメージが稼働している。その後、含まれる部品に新しい脆弱性が公表された。最も適切な対応はどれか。

    1. 検査の時点で見つからなかった脆弱性は、あとから公表されうる。検査は構築時と運用中の両方で行う。

    2. イメージに古い部品が入っていれば、その脆弱性もそのまま入る。分離されていても、部品自体の問題は残る。

    3. RBACは権限を絞って被害を抑える対策の一つ。部品の脆弱性そのものをなくすものではない。

    4. 正解。構築時と運用中の両方で検査し、見つかれば更新する。

  4. データベースのパスワードをDockerfileに書き込んでイメージを作り、社内のレジストリで共有している。この運用の評価として最も適切なものはどれか。

    1. 社内限定でも、イメージを取得できる人や侵害された環境からは取り出されうる。焼き込み自体が問題。

    2. 非rootは実行時の権限を絞る対策。イメージに入っている秘密情報は、イメージ自体から取り出されうる。

    3. 正解。秘密情報はイメージに焼き込まない。取り出されうるので、別の手段で渡してアクセスを管理する。

    4. ネットワークポリシーはPod間の通信を制限するもの。イメージの中身の取り出しは防げない。

  5. アプリのPodが使うサービスアカウントに、クラスタ全体の管理者に近い権限が付与されている。このPodが侵害された場合の評価として、最も適切なものはどれか。

    1. ネットワークポリシーはPod間の通信を制限するもの。KubernetesのAPIの権限はRBACで絞る。

    2. 正解。RBACで利用者とPodの権限を最小限にする。広い権限は、奪われたときの被害を広げる。

    3. 検査はイメージの脆弱性を見つける対策。侵害された後に、広い権限で何ができるかは別の問題。

    4. 非rootは、コンテナの分離を強める対策の一つ。KubernetesのRBACの権限が広いままなら、奪われたときの被害は広がる。「広がらない」は言い過ぎ。

  6. ネットワークポリシーのマニフェストを作成して適用したのに、Pod間の通信は許可されたままだった。最も疑うべきものはどれか。

    1. RBACはAPIに対する権限の仕組みで、Pod間の通信は制御しない。通信の制限が打ち消される原因とは考えにくい。

    2. イメージの部品の脆弱性は、通信の制限の有効性とは別の話。

    3. Pod間の通信は既定では許可されている。既定で拒否という前提が誤り。

    4. 正解。ネットワークポリシーは、対応するネットワークの仕組みが無いと効かない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. コンテナをVMと同じ強さの分離だと考えてはいけない理由と、設定で壁を薄くしてしまう例を頭の中で説明してみよう。

    答えを開く

    コンテナはホストのカーネルを共有してプロセスを分けるだけで、OSごと分けるVMより分離は弱い。カーネルの弱点がホスト全体に響きうる。特権での実行、root実行、ホスト領域のマウントは、さらに壁を薄くする。

    思い浮かんだ要素にチェック

  2. Kubernetesで、既定のままだと危ない点を2つ挙げ、それぞれの対策を頭の中で説明してみよう。

    答えを開く

    Secretは既定ではBase64の符号化で暗号化ではないので、アクセス制御と保存時の暗号化で守る。Pod間の通信は既定で許可されているので、ネットワークポリシーで必要な通信だけを許可する。ただし対応するネットワークの仕組みが要る。
