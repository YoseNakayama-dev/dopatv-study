#11 ・ 第4章 情報セキュリティマネジメントの実践

インシデント対応 慌てないための流れと判断基準

  1. 流れは、検知／連絡受付、トリアージ、インシデントレスポンス、報告／公開（対応と並行）、事後の見直し。
  2. トリアージでは誤検知も疑い、状況を整理して優先順位を決める。原因の究明は後回しで、不要なら根拠を説明。
  3. 難しいときは経営層・IT部門・外部専門機関と連携する。資料は2015年版で、最新の指針とは差があるかもしれない。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題トリアージの段階で適切なのは？

    1. トリアージでは原因の究明は後回し。だから誤り

    2. 判断し、優先順位を決める

    3. 対応不要でも根拠を説明する。だから誤り

    4. 報告・公開は対応と並行して検討する。だから誤り

  2. 外部の報告者から異常の通報を受け、トリアージで調べたところ、誤検知で対応は不要と判断した。次の対応として最も適切なものはどれか。

    1. 正解。対応が不要と判断したら、その根拠を報告者に説明する。

    2. 誤り。連絡せず記録も残さないのは、根拠を説明するという扱いに反する。

    3. 誤り。トリアージでは原因の究明は後回し。誤検知でも、完全な究明を待たない。

    4. 誤り。対応不要と判断した件は、対応を続けず、根拠を説明して区切る。

  3. 組織のセキュリティ窓口 security@ 宛に外部から連絡が届いたが、メールは担当者個人の受信箱に埋もれ、対応部門に伝わらなかった。再発防止策として最も適切なものはどれか。

    1. 誤り。窓口は公開して外部の通報を受ける。

    2. 誤り。個人の確認頼みでは、届かない連絡が出る。転送の手順と判断基準が要る。

    3. 正解。窓口宛の連絡を速やかにCSIRTへ転送する手順と、判断基準を用意する。

    4. 誤り。検知には、自組織内の検知と外部からの通報の両方がある。

  4. 対応計画を実施した後に解決を確認したところ、同じ異常がまだ続いていた。次の動きとして最も適切なものはどれか。

    1. 誤り。未解決なら分析へ戻る。結果の回答は、解決の確認の後。

    2. 誤り。戻る先はトリアージでなく事象の分析。トリアージでは原因の究明は後回し。

    3. 誤り。難しい場合は外部の支援を頼めるが、自組織の対応を終える話ではない。

    4. 正解。解決の確認で未解決なら、事象の分析に戻って進める。

  5. 対応に取りかかったが、自組織の技術だけでは対応が難しいと分かった。この時点の動きとして最も適切なものはどれか。

    1. 誤り。難しいときは、外部の専門機関とも連携する。

    2. 正解。難しい場合は、経営層・IT関連部署・外部の専門機関と連携する。

    3. 誤り。難しさを理由に先送りせず、連携して対応を進める。

    4. 誤り。記録や計画に載せないと、事後の見直しに生かせない。

  6. 半年前の重大なインシデント対応のあと、手順書は変更されず、予行演習も予定されていない。JPCERT/CC の資料に沿った見直しとして最も適切なものはどれか。

    1. 誤り。再発を待たず、定期的に見直して手順や体制を直す。

    2. 誤り。経験はナレッジとして蓄積し、共有する。

    3. 正解。インシデントリストを目安として3〜6か月で見直し、予行演習を定期的に行って手順・体制・ポリシーを修正し、知見を蓄積する。

    4. 誤り。見直しは一度で終わらず、定期的に行う。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. トリアージの段階で、原因の究明を後回しにして先に行うことは何か。頭の中で説明してみよう。

    答えを開く

    そもそもインシデントか（誤検知でないか）を判断し、いつ・どこで・何が・どのように・誰がを整理して、優先順位を決める。原因（why）の究明は後回しにする。対応が不要なら、その根拠を報告者に説明する。

    思い浮かんだ要素にチェック

  2. 対応が終わったあと、次に同じことが起きても慌てにくくするために何をするか。頭の中で説明してみよう。

    答えを開く

    インシデントリストを3〜6か月を目安に見直し、予行演習を定期的に行って、手順・体制・ポリシーを修正する。経験は知見（ナレッジ）として蓄積する。
