#54 ・ 第5章 情報セキュリティ対策技術（1）予防・検知・防御

IDSの限界と運用の課題 誤検知と見逃しにどう向き合うか

  1. IDSには誤検知・見逃し・取りこぼしの限界があり、検知は事後の対応につながる。通信は止められない。
  2. 運用では、重要度の分類、環境に合わせた調整、パターンの更新、確認と対応の手順・連絡先が要る。
  3. 検知の厳しさは誤検知と見逃しのトレードオフ。ログの突き合わせと、IPSなど他の対策との併用で補う。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題IDSの「誤検知」の説明として、適切なのは？

    1. それは、見逃し

    2. IDSは、遮断しない

    3. 正常を不正と誤判定

    4. 運用上の不備

  2. 暗号化された通信の中に不正な通信が含まれていたが、IDSからアラートは出なかった。この事象の分類として最も適切なものはどれか。

    1. 正解。不正を検知できないのが見逃しで、未知の攻撃や暗号化された通信で起きやすい。

    2. 誤検知は正常な通信を不正と判定すること。今回は不正を検知できていないので向きが逆。

    3. 取りこぼしは通信量が多く監視が追いつかない場合。今回の事象は暗号化された通信で、原因が異なる。

    4. この限界は検知できても通信を止められないこと。今回はそもそもアラートが出ていない。

  3. 誤検知が多く重要なアラートが埋もれている。担当者が「件数を減らすため、検知を大幅に緩める」と提案した。この提案への評価として最も適切なものはどれか。

    1. 緩めると見逃しが増える。誤検知と見逃しはトレードオフの関係にある。

    2. 正解。厳しくすると誤検知が増え、緩めると見逃しが増える。環境に合わせた調整が必要になる。

    3. 厳しくすると誤検知が増える。両方が同時に減るという関係ではない。

    4. 件数が減っても、重要度の分類と確認・対応の手順は運用上の課題として残る。

  4. 夜間に重要度「高」のアラートが出たが、誰がいつ確認し、どう対応するかが決まっておらず、翌週まで放置された。最も根本的な不足はどれか。

    1. アラートは実際に出ているので、検知できていないという前提が誤り。

    2. 取りこぼしの記述はなく、アラート自体は出ている。放置の原因は別にある。

    3. パターンの更新は運用課題だが、今回はアラートが出ており、見逃しではない。

    4. 正解。誰が、いつ確認し、どう対応するかの手順と連絡先を決めておかないと、検知しても被害が進む。

  5. IDSが外部から内部サーバへの不審な通信を検知した。これが本物の攻撃かどうかを判断する方法として最も適切なものはどれか。

    1. 重要度だけで確定させず、ログを突き合わせて確かめる。

    2. 正解。相関分析として、FWやサーバのログと突き合わせて真偽を確かめる。

    3. 誤検知の可能性があっても、確認せず放置すると本物を見落とす。

    4. 再起動の再現だけでは真偽は分からない。ログとの突き合わせが必要。

  6. 「IDSだけを導入すれば、攻撃が来ても被害は出ない」という説明があった。この説明への指摘として最も適切なものはどれか。

    1. 正解。IDSは通信を止められず、対応が遅れると被害が進む。遮断はIPS、事後はインシデント対応と組み合わせる。

    2. IDSは基本的に通信を遮断しない。自動で遮断するのはIPS。

    3. 誤検知の多さとは無関係に、IDSは基本的に遮断しない。

    4. 未知の攻撃や暗号化された通信は見逃しが起きやすい。パターンの更新だけで漏れなく検知できるとは言えない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. アラートが毎日大量に出て、重要なものが埋もれている。原因の見立てと、改善の方向を頭の中で説明してみよう。

    答えを開く

    既定のままで環境に合わせた調整をしていないと、誤検知が多くなりやすい。調整で誤検知を減らし、重要度で分類して優先的に確認する。ただし検知を緩めすぎると見逃しが増える。

    思い浮かんだ要素にチェック

  2. IDSが重要なアラートを出していたのに、被害が進んだ。運用面の原因と対処を頭の中で説明してみよう。

    答えを開く

    IDSは通信を止められず、検知は事後の対応につながる。確認や対応の手順・連絡先が決まっていないと対応が遅れ、被害が進む。確認から連絡・対処までの手順を事前に決め、遮断はIPSと併用する。

IDS運用の調査記録（ダミー）
IDSのアラート: 1日に約3000件。大半は、定期バックアップの通信への反応
検知設定: 既定のまま。環境に合わせた調整は、導入後に一度も行っていない
アラートの確認: 担当者1名が、週に1回、まとめて確認している
先週、重要度「高」のアラートが出たが、確認されたのは4日後だった
その4日間、サーバから外部へ、データが送信され続けた

運用の改善として、優先すべきなのは？

答えを開く

誤検知を減らす調整と、重要度に応じた確認・対応の手順を整える

よくある誤答

  • IDSを増設し、監視範囲を広げる … 重要度「高」のアラートは、出ていた
  • アノマリ型に変更する … 誤検知が増えやすく、現状は1日3000件
