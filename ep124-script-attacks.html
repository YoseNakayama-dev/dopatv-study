#24 ・ 第2章 情報セキュリティにおける脅威

命令を実行させる攻撃の種類 解釈される場所で整理する

  1. 共通の原因は、外部入力が検証・無害化されず、受け取った側で命令として解釈されること。
  2. 攻撃の名前は解釈される場所で決まる。ブラウザ・DB・OS・ヘッダで被害が違う。
  3. 根本はデータと命令の分離。検証は補助、最小権限とWAFは被害軽減で原因は直らない。

用語カード

クイズ

  1. 動画で出た問題これらの攻撃に共通する、根本的な対策は？

    1. 暗号化は、盗聴への対策

    2. データと命令を分ける

    3. パスワード変更は、認証の話

    4. ログは、事後の調査用

  2. ある入力欄の値はブラウザ上でスクリプトとして、別の入力欄の値はDBでSQL文として解釈されていた。両者を別の攻撃名で呼び分ける基準として最も適切なものはどれか。

    1. 正解。原因は共通でも、どこで解釈されるかで攻撃の名前が決まる。

    2. 経路で名前が決まるのではなく、解釈される場所で整理する。

    3. 被害は場所によって違うが、名前を分ける基準そのものではない。

    4. 検証の不足や、データと命令の混在は共通する原因で、呼び分ける基準にならない。

  3. 新規の検索機能で、開発者が「入力値の検証を厳しくしたので、プレースホルダやエスケープは省く」と提案した。評価として最も適切なものはどれか。

    1. 検証だけでは取りこぼしが残る。根本はデータと命令を分けること。

    2. WAFは補助で、脆弱性そのものは直らない。

    3. 正解。入力値の検証は補助として組み合わせ、根本はデータと命令の分離。

    4. 検証は補助として組み合わせるもので、「一切不要」は言い過ぎ。

  4. HTML本文用のエスケープ関数を、DBへの問い合わせ文とOSのコマンド文字列の組み立てにもそのまま使い回している。評価として最も適切なものはどれか。

    1. エスケープの正しい方法は、解釈される場所ごとに違う。

    2. 解釈する場所が違えば必要な処理も違う。サーバ側かどうかでは決まらない。

    3. 検証は補助で、取りこぼしが残る。場所ごとの違いを解消するものではない。

    4. 正解。1つの方法ですべての場所は守れない。場所に合った方法を選ぶ。

  5. SQLインジェクションの脆弱性が見つかったが、改修に時間がかかるため、まずWAFを導入し、DB接続アカウントの権限を絞った。この対応の説明として最も適切なものはどれか。

    1. WAFは補助で、脆弱性そのものは直らない。

    2. 正解。最小権限やWAFは被害を軽くする役目。根本はデータと命令の分離。

    3. 権限を絞っても、入力が命令として解釈される原因は残る。

    4. 最小権限もWAFと同じく被害を軽くする補助で、根本対策ではない。

  6. 障害報告に「利用者の画面が書き換えられ、情報が盗まれた」とある。命令として解釈された場所と攻撃名の組み合わせとして最も適切なものはどれか。

    1. OSでは、サーバ上で意図しない操作が実行される被害になる。

    2. DBでは、情報の漏えい・改ざん・認証の回避になる。

    3. 正解。ブラウザで解釈される場合、利用者の画面の改ざんや情報の窃取になる。

    4. ヘッダでは、偽のヘッダの追加や宛先の追加などが起こる。

頭の中で考える

  1. 入力値の検証だけでは、これらの攻撃への対策として足りない理由と、根本の対策を頭の中で説明してみよう。

    答えを開く

    検証だけでは取りこぼしが残る。原因は入力が命令として解釈されることなので、根本はデータと命令をはっきり分けること。検証は補助として組み合わせる。

    思い浮かんだ要素にチェック

  2. あるエスケープ処理を、解釈される場所が違う別の箇所にも使い回してよいか。理由を頭の中で説明してみよう。

    答えを開く

    よくない。エスケープの正しい方法は解釈される場所ごとに違い、1つの方法ですべての場所は守れない。場所に合った方法やプレースホルダなどを選ぶ。

検索欄の入力が、SQL文の一部として連結されていた
ネットワーク診断画面の入力が、OSの命令に連結されていた
// どちらも、入力値の検証・無害化の処理がない

2つの不具合に共通する原因として、適切なのは？

答えを開く

入力値を検証せず、データと命令を区別せずに連結している

よくある誤答

  • 通信が暗号化されていない … どちらの記録にも無関係
  • パスワードが短い … 認証の問題ではない
