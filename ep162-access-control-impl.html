#62 ・ 第6章 情報セキュリティ対策技術（2）アクセス制御と認証

アクセス制御の実施 判定は画面でなくサーバ側で

  1. 実施の場所はファイルサーバ・アプリ・ネットワーク。判定は要求を受けるサーバ側で毎回行う。
  2. 画面の出し分けだけでは、直接送られた要求を止められない。ACLは許可したものだけ通し、他は拒否。
  3. 運用では特権IDの限定と非共有、権限変更の記録、期限付き付与、定期的な棚卸しを行う。
用語 10クイズ 6考える 2午後本

用語カード

クイズ

  1. 動画で出た問題アクセス制御の設定の考え方として、適切なのは？

    1. 禁止以外を許可は設定漏れが穴

    2. 全員同一扱いでは使い分けられない

    3. 共有IDは操作者を追えない

    4. 許可した操作だけ通す

  2. 障害対応のため、外部委託先に一時的に管理者権限を付与する。運用として適切なものはどれか。

    1. 期限がないと、障害対応が終わったあとも管理者権限が棚卸しまで残る。一時的に与える権限は、期限を決めて外し忘れを防ぐ。

    2. 正解。一時的な権限は期限を決めて与え、付与や変更は記録してあとから確認できるようにする。

    3. 特権IDは使う人と目的を限定し、共有しない。共有すると誰の操作か追えなくなる。

    4. 作業ログは操作の記録で、権限をいつ誰が付与・変更したかは残らない。付与や変更は別に記録して、あとから確認できるようにする。

  3. ファイルサーバのフォルダ権限は適切に設定済みだが、同じ情報を扱うWebアプリの管理機能には権限判定がない。評価として適切なものはどれか。

    1. 正解。アプリケーションでは、機能やデータごとに利用者の権限を判定する。判定は要求を受けるサーバ側で毎回行う。

    2. ファイルサーバの権限はファイル・フォルダ単位の制御。アプリの管理機能という機能単位の操作は、アプリ側で別に判定する必要がある。

    3. ネットワークは送信元や宛先で通信の通過を制御するもの。機能やデータごとの判定は、アプリで行う。

    4. 画面で隠すだけでは、直接送られた要求を止められない。判定はサーバ側で毎回行う。

  4. 権限を付与した覚えのない利用者が、機密フォルダに書き込める状態が見つかった。いつ誰が付与したかを調べるために、事前に必要だった運用はどれか。

    1. 棚卸しは付与した権限の現状を確認するもので、いつ誰が付与したかの履歴は分からない。付与や変更は別に記録する。

    2. 必要最小限から与えるのは与える権限の範囲の方針で、付与の履歴は残らない。記録がなければ、いつ誰が付与したかをあとから確認できない。

    3. 正解。権限の付与や変更は記録して、あとから確認できるようにする。

    4. 特権IDを共有すると、誰の操作か追えなくなる。

  5. ログイン直後に一度だけ権限を判定し、以降の操作ではその結果を画面側に持たせて使い回している。見直しとして適切なものはどれか。

    1. 正解。権限の判定は、要求を受けるサーバ側で毎回行う。

    2. 画面側に持たせた値では、直接送られた要求を止められない。判定はサーバ側で毎回行う。

    3. 判定は要求を受けるサーバ側で行う。画面側の処理だけでは、直接送られた要求を止められない。

    4. 識別、認証、認可は別の段階。本人確認ができていても、権限の判定は毎回サーバ側で行う。

  6. ACLでは営業部は読み取りのみ、管理者は読み書きと定めている。営業部から、特定の資料だけ更新したいとの要望が出た。対応として適切なものはどれか。

    1. 権限は必要最小限から与える。管理者グループへの追加は、要望の範囲を超える。

    2. 正解。必要な範囲の権限だけをACLに加え、付与や変更は記録してあとから確認できるようにする。

    3. 画面の表示を変えても、判定はサーバ側で行う。ACLが読み取りのままなら、更新は許可されない。

    4. IDを共有すると、誰の操作か追えなくなる。

頭の中で考える

  1. 特権IDを共有し、権限の変更も記録せず、一時的な権限に期限も付けていない運用で、何が困るかを頭の中で説明してみよう。

    答えを開く

    共有した特権IDでは誰の操作か追えなくなる。変更を記録していないと、あとから確認できない。期限がないと外し忘れが起きる。特権IDの限定と非共有、変更の記録、期限付きの付与、定期的な棚卸しで運用する。

    思い浮かんだ要素にチェック

  2. ACLの設定で、禁止したものだけを止める方式と、許可したものだけを通す方式の違いを、設定漏れの観点で頭の中で説明してみよう。

    答えを開く

    禁止したものだけ止める方式では、設定漏れがそのまま穴になる。許可したものだけを通しほかは拒否する既定で拒否なら、漏れたものは拒否される。権限は必要最小限から与え始める。

    思い浮かんだ要素にチェック

午後問題にチャレンジ

管理画面の権限に関する調査記録（ダミー）
現状: 管理画面へのリンクは、権限に応じて画面上で出し分けている
一般利用者が管理画面のURLを直接入力すると、管理機能が実行できた
URLは、共有や履歴を通じて、利用者に知られることがある
一般利用者も、管理者と同じ社内ネットワークから接続している
要件: URLを知られても、権限のない操作は確実に拒否したい

権限のない操作を確実に拒否する方法として、適切なのは？

答えを開く

操作を受け付けるサーバ側で、要求のたびに利用者の権限を確認する

よくある誤答

  • 管理画面のURLを、推測されにくい長い文字列に変更する … URLが知られても拒否する、という要件を満たさない
  • 管理者以外の画面では、リンクを隠し続ける … 現状がその方式で、URLの直接入力で実行できた
