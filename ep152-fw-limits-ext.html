#52 ・ 第5章 情報セキュリティ対策技術（1）予防・検知・防御

FWで防げないものと拡張機能 許可した通信の中身が盲点

  1. FWは、許可した通信の中身、内部同士の通信、FWを経由しない経路、暗号化された通信の中身を防げない。
  2. 拡張機能にはVPN、URLフィルタ・コンテンツ検査、IPS・アプリケーション識別、DoS対策がある。
  3. 機能を重ねると処理が重くなり、更新や誤検知の調整も要る。復号検査は配慮が要り、多層防御が前提。
用語 9クイズ 6考える 2午後本

用語カード

クイズ

  1. 動画で出た問題ファイアウォールだけでは防げないものは？

    1. 許可した通信の中身は、規則で判断できない

    2. 規則で拒否できる

    3. 宛先の規則で拒否できる

    4. 送信元の確認で拒否できる

  2. FWの拡張機能でコンテンツ検査を使っているが、HTTPSの通信が増えている。暗号化された通信の扱いとして適切なものはどれか。

    1. 暗号化された通信の中身は、復号しない限り検査できない。HTTPSが増えれば検査できない範囲が増える。

    2. 正解。復号しない限り中身は検査できない。復号検査は通信の秘密・プライバシーに配慮し、対象とルールを決める。

    3. 復号検査は通信の秘密・プライバシーに配慮し、対象とルールを決める。全通信を無条件に対象にはしない。

    4. 見えないことは安全であることを意味しない。検査できないだけである。

  3. 調査すると、従業員が持ち込んだモバイル回線の機器を端末に接続し、社内のサーバへつないでいた。境界のFWの規則は適切だった。この経路についての説明として適切なものはどれか。

    1. この経路はFWを通らないので、規則を厳しくしても判断の対象にならない。

    2. IPSもFWの拡張機能。FWを通らない通信は、機能を足しても検査の対象にならない。

    3. 正解。無許可の無線・持ち込み媒体・モバイル回線などは、FWを経由しないので規則では防げない。

    4. 問題は暗号化ではなく、FWを経由しない点。復号してもFWを通らない通信は検査できない。

  4. 公開サイトが、回線帯域そのものを埋める大量の通信で応答しなくなった。FWの接続数の制限を厳しくしたが改善しなかった。評価として適切なものはどれか。

    1. 接続数の制限などはDoS対策になるが、回線そのものを埋める通信には手前での対策が要る。

    2. 回線が埋まる通信はFWに届く前の問題。FWの性能で解決するとは言えない。

    3. 機能を重ねるほど処理が重くなる。回線そのものを埋める通信への対策は、FWの手前で行う。

    4. 正解。回線そのものを埋める通信は、FWの手前での対策が要る。

  5. FWにコンテンツ検査とIPSの機能を追加したところ、通信が遅くなり、正常な業務通信が遮断されたとの問い合わせが増えた。運用上の対応として適切なものはどれか。

    1. 正解。機能を重ねるほど処理が重くなる。シグネチャ更新と誤検知の調整も運用に含める。

    2. シグネチャ更新と誤検知の調整は運用に必要なこと。放置は適切ではない。

    3. FWだけに頼らず、多層防御で考える。許可した通信の中身は、FWの基本機能では防げない。

    4. 機能を重ねるほど処理は重くなる。遅さの原因を回線に決めつけられない。

  6. 同じセグメント内の端末から別のサーバへ不正アクセスが行われたが、境界のFWのログには該当する通信が無かった。解釈として適切なものはどれか。

    1. 境界を通らない通信は境界のFWに記録されない。ログに無いことは不正が無い根拠にならない。

    2. 境界を通らない通信には、境界FWの規則は適用されない。

    3. 正解。境界を通らない内部同士の通信や内部の不正は、境界のFWだけでは防げない。

    4. URLフィルタもFWの拡張機能で、境界を通らない通信は検査の対象にならない。

頭の中で考える

  1. FWの規則が正しく動いていても被害が出る典型的な場面を、3つ頭の中で挙げ、それぞれの理由を説明してみよう。

    答えを開く

    許可した通信の中身の攻撃（アドレス・ポートの規則では判断できない）、境界を通らない内部同士の通信や内部の不正、FWを経由しない経路（無許可の無線・持ち込み媒体・モバイル回線）。暗号化された通信の中身も復号しない限り検査できない。

    思い浮かんだ要素にチェック

  2. FWに拡張機能を重ねるときの注意点を、頭の中で説明してみよう。

    答えを開く

    機能を重ねるほど処理が重くなる。シグネチャの更新と誤検知の調整が要る。暗号化通信を復号して検査するなら、通信の秘密・プライバシーに配慮して対象とルールを決める。FWだけに頼らず多層防御で考える。

    思い浮かんだ要素にチェック

午後問題にチャレンジ

Webサイト被害の調査記録（ダミー）
FWの規則: 外部→DMZのWebサーバは、443番（HTTPS）のみ許可
FWのログ: 通信はすべて外部→DMZの443番で、許可された記録
結果: 通常と異なる値を含む要求が処理され、顧客情報が閲覧された
境界の機器は、証明書を登録すれば、HTTPSを復号して検査できる
要件: 公開は継続。アプリの修正は準備中で、当面は境界で対処

境界側で追加する対策として、適切なのは？

答えを開く

許可した通信の中身を調べ、不正なものを止める機能を追加する

よくある誤答

  • 443番を閉じる … 要件は、公開の継続
  • 外部→内部を拒否する規則を足す … 被害の通信は外部→DMZで、規則の対象外

本で読む

  • 5.5.5 ファイアウォールで防御できない攻撃
  • 5.5.6 ファイアウォールの拡張機能

FWが判断できるものとできないものの線引き、各拡張機能が補う範囲、機能を重ねたときの運用上の注意を確かめながら読む。
