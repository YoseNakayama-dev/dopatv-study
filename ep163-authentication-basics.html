#63 ・ 第6章 情報セキュリティ対策技術（2）アクセス制御と認証

認証とは 名乗りと確認は別もの

  1. 識別は名乗ること、認証は本人かを確かめること。流れは識別、認証、認可の順。
  2. 対象は利用者・機器・サーバ。目的はなりすましの防止と、操作した人の特定。
  3. 認証情報は暗号化した通信で送り、失敗の理由は教えすぎない。ロックは締め出しに悪用されうる。

クイズ

  1. 動画で出た問題識別と認証の説明として、適切なのは？

    1. 区別が識別、確認が認証

    2. 識別と認証の役割が逆

    3. 権限の判断は認可、履歴は記録

    4. IDは名乗りで本人確認ではない

  2. ログイン失敗が一定回数続いたら、アカウントを一時的にロックする設定を入れる。この方式の説明として適切なものはどれか。

    1. ロックは試行を抑える手段の一つで、推測を防ぎ切るものではない。認証情報を暗号化した通信で送るなど、ほかの実装のポイントも別に必要。

    2. 失敗の理由を詳しく示しても、締め出しの懸念は変わらない。かえって、IDが登録されているかが外部に分かってしまう。

    3. 正解。失敗回数に上限を設け一時的にロックする方法はあるが、ロックは利用者の締め出しにも使われうる。

    4. 回数の制限がないと、失敗を際限なく繰り返せる。ロックが締め出しに悪用されうる点は、使うときの注意点であり、制限を設けない理由にはならない。

  3. ログイン済みの利用者が、アカウントの設定を大きく変える重要な操作を行おうとしている。認証の面で適切な設計はどれか。

    1. ログイン時の認証は、その後の重要な操作を行う人が本人であることまでは確かめていない。重要な操作の前には、再度認証を求める。

    2. 正解。重要な操作は、実行の前に再度認証を求める。

    3. IDは名乗りにすぎず、本人かどうかを確かめたことにならない。

    4. 実行したあとに認証を求めても、操作はすでに完了している。再認証は、重要な操作を実行する前に求める。

  4. ログイン画面は、失敗回数の制限と、失敗時に同じメッセージを返す実装が済んでいる。ただ、認証情報は暗号化しない通信で送っている。評価として適切なものはどれか。

    1. 失敗回数の制限は、試行を抑える対策。通信路上で認証情報が読み取られることは防げないので、暗号化した通信で送る必要がある。

    2. 同じメッセージを返すのはIDの登録有無を知られないための対策で、通信の保護とは目的が別。

    3. 社内の通信でも、経路上で認証情報が読み取られるおそれは残る。社内向けでも、認証情報は暗号化した通信で送る。

    4. 正解。実装のポイントは個別に必要で、認証情報は暗号化した通信で送る。

  5. 利用者のブラウザが、接続先のサイトが本物のサーバかを確かめたい。これに当たるものはどれか。

    1. 利用者の認証は、操作する人が本人かを確かめるもの。接続先が本物かを確かめるものではない。

    2. 正解。サーバの認証は、接続先が本物かを証明書などで確かめる。

    3. 機器の認証は、接続してくる端末や機器を確かめるもの。ブラウザが接続先のサーバを確かめる向きとは逆。

    4. 認可は、認証のあとに権限があるかを確認すること。接続先が本物かを確かめるものではない。

  6. 複数の担当者が共通のIDとパスワードで管理画面を使っており、障害後に誰が操作したかを特定できなかった。認証の目的に照らした見直しはどれか。

    1. 共通のIDでは、パスワードを強くしても誰が操作したかは特定できない。認証の目的のひとつは操作した人の特定。

    2. 認証の目的は、なりすましの防止と、誰が操作したかを特定できるようにすることの二つ。

    3. 正解。IDを分けて識別し、認証で本人を確かめることで、なりすましを防ぎ、操作した人を特定できる。

    4. 認可は権限の範囲を決めるもの。範囲を狭めても、誰が操作したかを特定できるようにはならない。

頭の中で考える

  1. アカウントのロックを導入するときの狙いと、設計時に気をつける点を、頭の中で説明してみよう。

    答えを開く

    失敗の回数に上限を設け、一時的にロックする方法がある。ただし、ロックは利用者の締め出しにも使われうるので、その点を踏まえて使う。

    思い浮かんだ要素にチェック

  2. 認証の対象が利用者だけではない理由を、サーバの認証を例に、頭の中で説明してみよう。

    答えを開く

    認証の対象は利用者のほか、機器やサーバもある。サーバの認証では、接続先が本物かを証明書などで確かめる。目的はなりすましの防止で、利用者の認証が破られると他人の権限を使われる。
