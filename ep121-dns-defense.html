#21 ・ 第2章 情報セキュリティにおける脅威

DNSサーバへの攻撃への対策 守備範囲と限界

  1. DNS攻撃の対策は攻撃ごとに違い、DNSSECだけで全部は防げない。キャッシュと権威の役割を分けて層で守る。
  2. DNSSECは応答の出所と完全性を署名で検証するが、署名側と検証側の双方の対応と鍵の運用が必要。
  3. 再帰の制限・レート制限・冗長化は可用性、ゾーン転送は必要な相手だけに許す。制限しすぎは正規にも影響する。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題DNSSECによって確認できるのは、次のうちどれ？

    1. 応答の正当性と改ざんの有無

    2. DNSSECは暗号化の仕組みではない

    3. 問い合わせ数の制限は、レート制限

    4. 利用者の認証とは別

  2. 自社のDNSサーバは、再帰を内部の利用者に限定済みである。さらに、自社ネットワークの端末が、送信元を偽装した問い合わせの発信元にされるのを防ぎたい。追加の対策として最も適切なものはどれか。

    1. DNSSECは応答の正当性の検証で、送信元偽装の発信を止める対策ではない。

    2. 応答を制限しない方向は、踏み台としての悪用を助長する。レート制限は大量応答を抑える対策。

    3. ゾーン転送は別の攻撃への対策。全面禁止は副サーバの複製にも支障が出る。

    4. 正解。送信元を偽装したパケットを、ネットワークの出口側で止めるフィルタが該当する。

  3. 権威サーバのゾーンにDNSSECの署名を付けた。効果と限界の説明として最も適切なものはどれか。

    1. 検証する側（リゾルバ）の対応が無ければ、署名があっても検証されない。

    2. 正解。DNSSECは署名する側と検証する側の双方の対応と、鍵の運用が必要。

    3. DNSSECは応答を署名で検証する仕組みで、暗号化ではない。盗聴は防げない。

    4. 踏み台化は再帰の制限などの対策。DNSSECは可用性の対策ではない。

  4. ランダムサブドメイン攻撃への対策として、存在しない名前への問い合わせを強く制限したところ、正規の利用者の一部が名前解決できなくなった。この事例から言えることとして最も適切なものはどれか。

    1. 監視・制限と冗長化はどちらも対策の一つ。限界を踏まえて併用する。

    2. 正規の利用でも存在しない名前を問い合わせることはありうる。不具合と決めつけるのは言い過ぎ。

    3. 正解。正規のキャッシュサーバ経由だと区別しにくく、制限しすぎると正規の利用者に影響する。

    4. DNSSECは応答の正当性の検証で、負荷の急増への対策にはならない。

  5. 副サーバを使うDNS構成で、ゾーン転送を安全のため全面禁止にしようとしている。方針として最も適切なものはどれか。

    1. 副サーバへの複製に転送が必要。全面禁止ではなく、必要な相手だけに許す。

    2. 正解。転送を許す相手を副サーバに限り、共有鍵（TSIG）などで認証する方法もある。

    3. 認証は有効な手段だが、許可先を限定する対策と合わせて考える。不要になるとは言えない。

    4. 内部向けの名前は、外部に公開するゾーンに載せない。構成の手がかりが漏れる。

  6. キャッシュサーバで、ソフトウェア更新と、識別子・送信元ポートのランダム化（照合の強化）は実施済みである。それでもDNSSECの検証を検討する理由として最も適切なものはどれか。

    1. 照合の強化にも偽応答を通りにくくする効果がある。効果がないとも、置き換えが必須とも言えない。

    2. DNSSECは署名による検証で、暗号化ではない。盗聴は防げない。

    3. 再帰の制限やレート制限は可用性の対策で、DNSSECで置き換えられない。

    4. 正解。照合の強化に加えて、署名で応答の出所と完全性を検証できる。ただし双方の対応と鍵の運用が必要。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. DNS増幅攻撃の踏み台にされないために、キャッシュサーバと権威サーバでそれぞれ何をするかを、頭の中で説明してみよう。

    答えを開く

    キャッシュサーバは、再帰問い合わせに答える相手を内部の利用者に限り、誰にでも答えるサーバにしない。権威サーバは再帰を無効にして役割を分ける。加えて応答のレートを制限し、送信元を偽装したパケットはネットワークの出口で止める。

    思い浮かんだ要素にチェック

  2. 「DNSSECを導入したからDNSの攻撃は防げる」という主張が不十分な理由を、頭の中で説明してみよう。

    答えを開く

    DNSSECは応答の出所と完全性を検証する仕組みで、主にポイズニングへの対策。増幅やランダムサブドメインなど可用性を狙う攻撃や、ゾーン転送の情報漏えいには別の対策が要る。署名側と検証側の双方の対応と鍵の運用も必要で、層で守る必要がある。
