#71 ・ 第6章 情報セキュリティ対策技術（2）アクセス制御と認証

SSOを実現する仕組み どこで認証を受けるか

  1. リバースプロキシ型は手前の装置が認証を代行する。アプリの改修やソフト導入は要らないが、主にWebアプリ向け。
  2. エージェント型はサーバにソフト導入、代理認証型は認証情報を預かり代理入力、チケット型はチケットを示す。
  3. 方式は対象・改修の可否で選ぶ。認証情報が集まる装置は守り、直接アクセスなど迂回経路を残さない。

用語カード

クイズ

  1. 動画で出た問題リバースプロキシ型のSSOの説明として、適切なのは？

    1. 改修を要しないのが利点

    2. 前段で認証し、直接の経路は遮断

    3. エージェントは各サーバ側に入れる方式

    4. 再認証は不要になる

  2. リバースプロキシ型のSSOで、認証を代行する装置の背後にあるアプリが、装置を経由せず直接アクセスできる状態になっている。この評価として最も適切なものはどれか。

    1. 正解。アプリへの直接アクセスを遮断しないと装置を迂回できる。

    2. 認証を代行するのは装置であり、アプリへ直接アクセスできると装置を迂回できる。

    3. アプリは装置から伝えられた利用者情報で誰の要求かを判断するため、直接アクセスを許すと利用者情報を偽って送られうる。

    4. エージェント型は各サーバにソフトを導入する別の方式で、直接アクセスを許す理由にはならない。直接アクセスは遮断しておく。

  3. 代理認証型のSSOで、利用者の認証情報を預かる装置を導入する。運用上の留意点として最も適切なものはどれか。

    1. 代理認証型は利用者の認証情報を預かる方式で、預かる側の装置は厳重に守る必要がある。

    2. 預かった情報が漏れると、全システムに影響する。

    3. 正解。預かった認証情報が漏れると全システムに影響するため、厳重に守る。

    4. チケットを示すのはチケット型の説明。代理認証型は認証情報を預かり、各システムへ代わりに入力する。

  4. SSOの方式名と特徴の組合せとして、適切なものはどれか。

    1. 各サーバにソフトを導入して認証済みかを確認するのはエージェント型。リバースプロキシ型はアプリの手前に認証を代行する装置を置く。

    2. チケットを示すのはチケット型で、代理認証型は認証情報を預かり代わりに入力する。

    3. 認証情報を預かり代わりに入力するのは代理認証型で、エージェント型は各サーバにソフトを導入して認証済みかを確認する。

    4. 正解。チケット型は発行されたチケットを各サービスに示す方式で、Kerberosがその例。

  5. 社内にはWebアプリのほか、Web以外のさまざまなシステムが混在している。リバースプロキシ型は主にWebアプリが対象である。方式の選び方として最も適切なものはどれか。

    1. リバースプロキシ型は主にWebアプリが対象で、全システムを対象にできるとは限らない。

    2. SSOの方式にはエージェント型・代理認証型・チケット型などもあり、対象や条件を見て選ぶ。

    3. 正解。対象がWeb中心か混在かで向く方式が変わるので、対象ごとに検討する。

    4. 方式は、アプリを変更できるか、ソフトを入れられるかなどを見て選ぶ。代理認証型は認証情報を預かる装置の保護が要る。

  6. エージェント型のSSOを導入する計画を立てる。確認すべきこととして最も適切なものはどれか。

    1. 正解。エージェント型は各サーバにソフトを導入して認証済みかを確認するため、導入できるかや負担を確認する。

    2. アプリの手前に認証を代行する装置を置くのはリバースプロキシ型で、エージェント型は各サーバにソフトを導入する。

    3. 認証情報を預かる装置の保護は代理認証型の留意点で、エージェント型は各サーバにソフトを導入する方式である。

    4. エージェントは各サーバに導入するソフトで、認証済みかどうかの確認もサーバ側で行う。サーバ側の導入が不要になるわけではない。

頭の中で考える

  1. リバースプロキシ型のSSOで、アプリへの直接アクセスを遮断しておく理由を、頭の中で説明してみよう。

    答えを開く

    認証は手前の装置が代行し、アプリは伝えられた利用者情報で誰の要求かを判断する。直接アクセスを許すと装置を迂回され、利用者情報を偽って送られうる。

    思い浮かんだ要素にチェック

  2. SSOの方式を選ぶとき、どんな観点で何を確認するかを、頭の中で挙げてみよう。

    答えを開く

    対象がWeb中心か混在か、アプリを変更できるか・ソフトを入れられるか、導入の負担と運用の手間を比べる。認証情報が集まる装置は厳重に守り、認証を迂回できる経路は残さない。

    思い浮かんだ要素にチェック

午後問題にチャレンジ

業務アプリの認証統合に関する調査記録（ダミー）
現状: 三つの業務Webアプリが、個別のログイン画面を持つ
アプリは外部ベンダー製で、改修や追加のソフト導入はできない
アプリは設定で、前段が渡す利用者情報を認証済みとして扱える
通信経路は変更可。認証情報を他の装置に預けるのは不可
要件: アプリを変更せず、一度のログインで三つを使いたい

要件を満たす方法として、適切なのは？

答えを開く

アプリの前段の装置で認証し、認証済みの利用者情報をアプリへ中継する

よくある誤答

  • 各アプリにSSO用のエージェントを導入する … 追加のソフトを導入できない
  • 各アプリのパスワードを同じ値にそろえる … アプリごとに入力が要り、一度のログインにならない
