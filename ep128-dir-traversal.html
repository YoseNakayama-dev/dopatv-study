#28 ・ 第2章 情報セキュリティにおける脅威

ディレクトリトラバーサル 階層をさかのぼる仕組みと対策

  1. 入力をパスに使い、上位ディレクトリ指定を拒否・検証せず、実行権限で読めると成立する。
  2. 根本は入力をファイル名として直接使わないこと。使うなら正規化し、基準ディレクトリ配下か検証する。
  3. 文字列の除去だけでは別表記で回避されうる。実行権限の最小化や公開領域の整理は補助。

用語カード

用語を見て意味を言えるか試し、タップで裏返します。「覚えた」を続けるほど定着度が上がり、「まだ」で最初に戻ります。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題ディレクトリトラバーサルへの、有効な対策は？

    1. 圧縮は、パスの解決と無関係

    2. クォートの処理はSQL向け。パスは変わらない

    3. 正規化と配下の検証

    4. 1回でも外のファイルは読める

  2. 資料ダウンロード機能が、パラメータで受け取ったファイル名を基準ディレクトリのパスに連結して返している。根本に近い改修として最も適切なものはどれか。

    1. 文字列の除去だけでは、別の表記で回避されうる。

    2. 正解。入力をファイル名として直接使わず、IDから対応表で選ぶか許可した名前だけを通す。

    3. 実行権限の最小化は補助。入力を連結する問題は残る。

    4. 公開領域の整理は補助で、パスの検証をしない問題は直らない。

  3. ディレクトリトラバーサルの成立条件のうち、アプリの実行権限の最小化が関わるものはどれか。

    1. 正解。権限を絞って読めない状態にすれば、読める範囲が絞られる。ただし補助にとどまる。

    2. 入力をパスに使うかどうかは設計の話で、実行権限とは別の条件。

    3. 拒否・検証は入力の扱いの話で、権限の最小化では変わらない。

    4. 実行権限の最小化は補助で、根本対策ではない。

  4. 製品の制約で、利用者が指定した名前のファイルを開く必要がある。実装として最も適切なものはどれか。

    1. 文字列の除去だけでは、別の表記で回避されうる。

    2. 文字列の除去を重ねる方法は、別の表記で回避されうる点が変わらない。

    3. 開いた後の確認では、読める状態を防ぐ対策にならない。

    4. 正解。使うなら、正規化してから基準ディレクトリ配下かを検証する。

  5. ダウンロード機能の不備で設定ファイルを読まれた。この機能は読み出し専用である。影響の評価として最も適切なものはどれか。

    1. 正解。設定ファイルの接続情報が漏えいしうる。読める範囲は実行権限による。

    2. ソースコードやログも、さらなる攻撃の足がかりになる。

    3. 読める範囲はアプリの実行権限による。「すべて」は言い過ぎ。

    4. 改ざんは、書き込みの機能がある場合にありうる。

  6. ダウンロード要求をIDで受け、サーバ側の対応表で実際のファイル名に変換する設計にした。この設計の位置付けとして最も適切なものはどれか。

    1. 入力を直接使わない方法は根本の対策。正規化と検証は、入力を使う場合の対策。

    2. 正解。IDから対応表で選ぶか、許可した名前だけを通す。

    3. 文字列を除去する方法とは別で、入力をファイル名に使わない。

    4. 被害を絞る補助ではなく、入力の扱いを変える根本の対策。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. ディレクトリトラバーサルの成立条件を3つ挙げ、実行権限を絞ると何が変わるかを頭の中で説明してみよう。

    答えを開く

    ①外部入力をパスに使う、②上位ディレクトリ指定や絶対パスを拒否・検証しない、③アプリの実行権限でそのファイルを読める。実行権限を絞れば読める範囲が狭まるが、成立自体は防げない補助である。

    思い浮かんだ要素にチェック

  2. 「上位ディレクトリ指定の文字列を取り除く」だけの対策で足りない理由と、より確かな対策を頭の中で説明してみよう。

    答えを開く

    文字列の除去だけでは、別の表記で回避されうる。根本は入力をファイル名として直接使わず、IDの対応表や許可リストで選ぶこと。使うなら、パスを正規化して基準ディレクトリの配下かを検証する。

午後問題にチャレンジ

動画の午後問題です。ログを読んで、答えを頭の中で決めてから開いてください。

資料ダウンロード機能の調査記録（ダミー）
対象: 資料ダウンロード機能（ダミー）。公開ディレクトリ内の資料を返す
パラメータのファイル名を、公開ディレクトリのパスに連結 / 検証なし
パラメータに、上位ディレクトリを示す指定が繰り返し含まれていた
公開ディレクトリの外にある、設定ファイルが、応答200で返されていた
// パラメータは、ファイルパスの連結にのみ使われ、SQLにも外部コマンドの引数にも使われない

この事象の原因として、適切なのは？

答えを開く

入力のパスが検証されず、階層をさかのぼってファイルを指せた

よくある誤答

  • SQLインジェクション … パラメータはパスの連結にのみ使われる
  • OSコマンドインジェクション … パラメータはコマンドの引数に使われない

成立条件の3つと、入力をファイル名に使わない対策、正規化と基準配下の検証、権限の最小化が補助である点を確かめながら読む。
