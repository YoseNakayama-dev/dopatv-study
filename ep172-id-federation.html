#72 ・ 第6章 情報セキュリティ対策技術（2）アクセス制御と認証

ID連携の概要 認証は持ち主に任せる

  1. ID連携は信頼関係を結んだ組織間で認証結果を連携する。パスワードはIdPだけが持ち、サービス側は結果を信頼して受け入れる。
  2. IdPの侵害・停止は連携先すべてに及ぶ。認証結果の盗用や使い回し、渡す属性が多いほど漏えいの影響も大きい。
  3. 対策は連携先の事前確認、署名・宛先・有効期限の検証、属性の最小化、IdP側の多要素認証と冗長化。

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題ID連携の説明として、適切なのは？

    1. パスワードは複製しない

    2. 組織をまたいで使える

    3. 属性は必要最小限にする

    4. 結果を信頼して受け入れる

  2. サービス側が、IdPから届いた認証結果の署名だけを確認して受け入れている。使い回しを防ぐための扱いとして最も適切なものはどれか。

    1. 認証結果は本来の相手にだけ有効でなければならず、宛先や有効期限の確認が要る。

    2. 正解。署名、宛先、有効期限を確認して、盗まれた結果が別の場所で使われるのを防ぐ。

    3. 信頼関係は口約束ではなく技術で裏づける。認証結果は署名などを確認する。

    4. 別のサービス向けの認証結果を受け入れてはいけない。宛先も確認する。

  3. サービス側が、IdPから受け取る利用者の属性を決めている。方針として最も適切なものはどれか。

    1. 正解。渡す属性は必要最小限にする。

    2. 渡す属性は必要最小限にする。属性には個人情報も含まれうる。

    3. 渡す属性が多いほど、漏えいの影響が大きくなる。

    4. 属性の中には個人情報も含まれうるため、渡す範囲を絞る必要がある。

  4. 取引先のIdPの認証結果を受け入れているポータルで、IdPが停止した。影響と対策の組合せとして最も適切なものはどれか。

    1. IdPが止まると連携先にも入れなくなり、連携先の利用者は業務を続けられなくなる。

    2. 署名の検証は偽の認証結果や使い回しへの対策で、IdPの停止には効かない。IdP側の冗長化で備える。

    3. 正解。IdPの停止は連携先すべてに及ぶので、IdP側を冗長化する。

    4. 属性を絞るのは漏えいの影響を小さくする対策で、停止への対策ではない。

  5. ID連携の仕組みの説明として最も適切なものはどれか。

    1. 利用者のパスワードはIdPだけが持ち、サービス側は預からずに済む。

    2. 正解。パスワードを持つのはIdPだけで、サービス側はIdPの結果を信頼して受け入れる。

    3. サービス側は認証はしないが、何を許可するかは自分で決める。

    4. ID連携は、信頼関係を結んだ組織間で認証結果を連携し、SSOを組織の境界を越えて実現する。

  6. 新たな取引先のIdPと連携を始める。連携前の対応として最も適切なものはどれか。

    1. 正解。事前に連携先を確認し、証明書などで確かめる。

    2. 文書の取り決めだけでは、連携先が本当にその組織かを確かめられない。信頼関係は技術で裏づけるもので、証明書などで確かめる。

    3. 連携を始めた後の確認では、確認前に、正規かどうか分からない相手の認証結果を受け入れ、属性を渡してしまうおそれがある。連携前に確認し、証明書などで確かめる。

    4. IdP側を多要素認証にするのは別の対策で、事前に連携先を確認し証明書などで確かめることの代わりにはならない。

  1. ID連携で、IdPに信頼を集中させることのリスクと、その対策を、頭の中で説明してみよう。

    答えを開く
