#5 ・ 追加テーマ（目次外）

CSRF 本人の意図かを確認しないと何が起こる？

  1. CSRFは、Cookie等でログイン状態を保つサイトで、リクエストが本人の意図か識別しないと成立する。
  2. 根本対策は、予測困難な秘密情報（トークン）の照合かパスワード再入力。POSTで送り、GETで状態を変えない。
  3. SameSiteや通知メールは補助。XSSが残るとトークンも読まれ、CSRF対策は破られうる。
用語 9クイズ 6考える 2午後本

用語カード

クイズ

  1. 動画で出た問題CSRFの根本的な対策として適切なのは？

    1. 「<」の削除はXSS向けで、CSRFは防げない

    2. XSSの対策で、CSRFは防げない

    3. 本人の意図の証拠を照合する

    4. SQLインジェクション向けの対策

  2. 退会処理が GET /account/delete?confirm=1 で実行される実装のサイトで、セッションCookieに SameSite=Lax を付けた。評価として最も適切なものはどれか。

    1. LaxでもGETによる状態変更は防げない。Cookieが付かないと言い切れない。

    2. SameSiteは多層防御の一つで、トークンなどの根本対策の代わりにはならない。

    3. SameSiteは主にCSRFへの備え。XSSの対策ではない。

    4. 正解。GETでの状態変更はLaxでも防げない。GETで状態を変えない設計にし、トークン等と併用する。

  3. 確認画面から登録を実行するとき、CSRFトークンをクエリ文字列に入れたGETで送っている。この設計の問題点として最も適切なものはどれか。

    1. 照合を省略できるかどうかは、メソッドの種類とは関係しない。

    2. 正解。GETだと秘密情報がRefererに出る。秘密情報はPOSTで送る。

    3. GETでもCookieは送られる。問題の本質ではない。

    4. 利便性の話で、セキュリティ上の問題点ではない。

  4. OriginヘッダでCSRFを検証するサイトに、Originの値が null のリクエストが届いた。扱いとして最も適切なものはどれか。

    1. 正解。欠落や null は同一オリジンの証拠にならない。

    2. null は同一オリジンを示す値ではない。信頼して通してはいけない。

    3. ヘッダの欠落も同一オリジンの証拠にならない。通す根拠にならない。

    4. Cookieが付くことは、本人の意図の証拠にならない。それがCSRFの前提。

  5. ページにXSSの脆弱性が残るサイトで、CSRFトークンを導入した。評価として最も適切なものはどれか。

    1. XSSがあると、ページ内のトークンを読まれてCSRF対策が破られうる。

    2. XSSがあるとCSRF対策は破られるとされる。属性の追加では前提が覆らない。

    3. 正解。XSSがあるとCSRF対策は破られる。XSS対策が前提になる。

    4. XSSは別物だが、CSRF対策の有効性には影響する。

  6. パスワード変更の完了後に、登録メールアドレスへ通知メールを送る機能だけを追加した。CSRF対策としての評価で最も適切なものはどれか。

    1. 通知は事後に気づくための保険的対策で、攻撃を防ぐものではない。

    2. 正解。重要操作後の通知は、防ぐのではなく気づく契機。本文に重要情報は入れない。

    3. 通知を送る順序を変えても、リクエストの処理自体は止められない。

    4. メール本文に秘密情報を入れるべきではない。根本対策はトークンの照合などで行う。

頭の中で考える

  1. CSRFで、攻撃者が利用者のCookieを盗んでいないのに操作が成立する理由を、頭の中で説明してみよう。

    答えを開く

    ログイン中の利用者のブラウザが、別サイトから送られたリクエストにもCookieを自動で付けるため。サーバはCookieの有効性しか見ておらず、本人の意図かを識別する仕組みが無い。

    思い浮かんだ要素にチェック

  2. SameSite属性を付ければCSRF対策は完了、と言えない理由を、頭の中で説明してみよう。

    答えを開く

    SameSiteは多層防御の一つ。Laxでも、GETでの状態変更は防げない。同一サイト内のサブドメインは対象外で、全ブラウザ前提にもできない。根本対策は秘密情報の照合など。

    思い浮かんだ要素にチェック
