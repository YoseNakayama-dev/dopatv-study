メール認証 SPF・DKIM・DMARC なりすましへの備え

  1. SPFは接続元IP、DKIMは署名の検証。見るのはMAIL FROMのドメインと署名のドメインで、ヘッダFromとは別。
  2. DMARCは、SPFかDKIMが合格し、かつ合格したドメインがヘッダFromと一致して初めて合格になる。
  3. 転送や件名の追記で失敗しうる。攻撃者が自分のドメインで認証を通す類似ドメインは防げない。

クイズ

  1. 動画で出た問題DKIMの説明として、適切なものは？

    1. 秘密鍵で署名し、公開鍵で検証

    2. 送信元IPの確認はSPF

    3. 失敗時の扱いの宣言はDMARC

    4. DKIMは署名で、暗号化ではない

  2. 自社ドメイン corp.example のメールを、配信サービス経由で送っている。配信サービスはMAIL FROMに自社のものではないドメインを使い、メールには corp.example の署名（DKIM）を付けている。ヘッダFromは corp.example である。DMARCの判定として最も適切なものはどれか。

    1. SPFが一致しないだけでは不合格にならない。DMARCはSPFまたはDKIMのどちらかが、合格かつFromと一致すれば合格になる。

    2. 正解。SPFが一致しなくても、DKIMの署名ドメインがヘッダFromと一致して検証に合格すれば、DMARCは合格しうる。

    3. 両方が必要なのではなく、どちらか一方で足りる。両方を要求すると、この構成の正規メールが落ちてしまう。

    4. MAIL FROMで決まるのはSPFの検証対象。DMARCはSPFとDKIMを束ね、ヘッダFromとの一致を見る。

  3. 社員が会社のメールを個人のメールアドレスへ自動転送しており、転送先で一部のメールが迷惑メール扱いになるとの申告があった。自社ドメインはDMARCをrejectにする予定である。検討として最も適切なものはどれか。

    1. 転送先は不特定で、全てを許可IPとして列挙するのは現実的でない。転送でIPが変わる点はDKIMで補う考え方になる。

    2. 転送で失敗しやすいのはSPFで、DKIMは署名が保たれていれば検証できる。「どの認証も成立しない」は言い過ぎ。

    3. 正解。転送では送信元IPが変わりSPFが失敗しうる。署名対象が書き換わらなければDKIMで合格し、DMARCも合格しうる。

    4. noneは観測の段階として有効だが、強化せず固定すると不合格時の扱いを宣言した意味が薄れる。観測しながら強める運用が基本。

  4. 経理に「取引先の請求書メール」が届いた。表示名は取引先名で、受信ヘッダではSPF・DKIM・DMARCがすべて合格だったが、送信ドメインは取引先のドメインに似た別の綴りだった。振込先の変更依頼が含まれている。適切な判断はどれか。

    1. 攻撃者は自分のドメインで認証を通せる。合格は、そのドメインから送られたことしか示さない。

    2. 取引先のDMARCが守るのは取引先のドメインのなりすまし。別の綴りのドメインは攻撃者のものなので、先方の設定では防げない。

    3. 認証が合格でもこのメールは疑わしい。認証の結果だけでなく、ドメイン名や内容の確認が要る。

    4. 正解。類似ドメインや表示名の偽装、本文の正当性は認証では保証されない。別経路での確認が必要。

  5. 自社ドメイン corp.example はDKIM署名を付けて送信しており、現在のDMARCは p=none で集計レポートを受け取っている。外部のメーリングリストに投稿すると、メーリングリストが件名に識別タグを追記して配信し、一部がDMARCで不合格と集計された。rejectへの切替えを検討している。原因の見立てと対応として最も適切なものはどれか。

    1. 鍵長は署名の強さに関わり、署名後の本文や件名の変更で検証が失敗する問題は変わらない。

    2. 正解。件名の追記など署名対象の書き換えでDKIMは失敗しうる。noneなどで観測し、段階的に強める運用が基本になる。

    3. 原因を見ないまま拒否にすると、正当な投稿も拒否される。受信側がローカルポリシーで判断する場合もあるが、頼り切るのは危うい。

    4. 転送ではSPFのほうが失敗しやすい。DKIMをやめると、合格する手段をさらに減らしてしまう。

  6. 自社ドメインにDMARCを導入する担当者が、まず p=none で公開した。経営層から「noneでは何も止められないので意味がない」と指摘された。担当者の説明として最も適切なものはどれか。

    1. 隔離にあたるのはquarantine。noneは「何もしない」ポリシーで、不合格のメールの扱いは変わらない。

    2. 拒否にあたるのはreject。noneは受信側の扱いを変えず、「必ず拒否」は言い過ぎで取り違えになっている。

    3. 正解。noneは扱いを変えないが、ruaの集計で正規の送信元の状況を把握でき、段階的に強める運用の入口になる。

    4. レポートは認証の状況を知る手段で、攻撃者の特定は目的ではない。また、全てが届くとも限らない。

頭の中で考える

  1. SPF・DKIM・DMARCは、それぞれ何を検証しているか。DMARCが「束ねる」とはどういうことか、頭の中で説明してみよう。

    答えを開く

    SPFは接続元IPがMAIL FROMのドメインの許可リストにあるかを見る。DKIMは署名を公開鍵で検証し、改変を検知する。DMARCはそのどちらかが合格し、かつ合格したドメインがヘッダFromと一致したときに合格とし、不合格時の扱い（none/quarantine/reject）をドメイン所有者が宣言する。

    思い浮かんだ要素にチェック

  2. 3方式をすべて導入しても防げないなりすましは何か。理由とあわせて、頭の中で整理してみよう。

    答えを開く

    攻撃者が自分のドメインで認証を通す類似ドメイン、表示名の偽装、本文の正当性は保証されない。認証されるのはドメインであり、そのドメインが信頼できる相手かは別の話になるため、送信ドメインの目視確認や別経路での確認が要る。

ポリシーに従う受信側は、どう扱う？

答えを開く

DMARCは不合格となり、ポリシーに従って拒否する

よくある誤答

  • SPFが合格なので、そのまま受信箱へ配送する … 合格したのはbad.testで、Fromのexample.jpとは別のドメインである
  • DKIMが合格なので、example.jpの正規メールとして扱う … 署名したのもbad.testで、example.jpの署名ではない
