#68 ・ 第6章 情報セキュリティ対策技術（2）アクセス制御と認証

RADIUSとKerberos 認証を集めてチケットで通す

  1. RADIUSは入口の装置がクライアントとなり、認証要求をサーバへ転送して認証・認可・記録を一元化する。
  2. Kerberosは、KDCが発行するTGTとサービスチケットで、パスワードをサービスへ送らず利用できる。
  3. 共有秘密とKDCは保護が要る。チケットには有効期限があり、時刻のずれが大きいと認証に失敗する。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題Kerberosの説明として、適切なのは？

    1. パスワードをそのまま送らない

    2. チケットには有効期限がある

    3. 時刻のずれは認証失敗の原因

    4. チケットを示して利用を許可

  2. 無線LAN親機とVPN装置が、利用者の認証を1台のRADIUSサーバに問い合わせる構成にする。RADIUSクライアントに当たるものはどれか。

    1. 正解。入口の装置がRADIUSクライアントとなり、認証要求をサーバへ転送して、結果に従う。

    2. RADIUSクライアントは利用者の端末ではなく、入口の装置。端末が直接サーバへ送る構成ではない。

    3. 許可か拒否を返すのはRADIUSサーバ。クライアントはその結果に従う側。

    4. チケットを発行するのはKerberosのKDC。RADIUSの構成要素ではない。

  3. RADIUSクライアントとサーバの共有秘密を、短く単純な文字列にして全装置で共通にしている。この設定の評価として、適切なものはどれか。

    1. 共有秘密そのものが流れなくても、弱いと盗聴した通信から推測されうる。短くても影響を受けないとは言えない。

    2. 正解。共有秘密は推測されにくくして使い回さない。弱いと盗聴した通信から推測されるおそれがある。

    3. 経路の保護も必要だが、共有秘密が弱くてよい理由にならない。共有秘密も推測されにくくする。

    4. KDCはKerberosの構成要素。RADIUSの共有秘密とは別で、推測への備えが要る。

  4. Kerberos環境で、利用者が認証を受けてTGTを得たあと、TGTの有効期間内に新しいサービスを使う。このときの手順として、適切なものはどれか。

    1. 有効期間内は、パスワードの再入力なしで複数のサービスを使える。

    2. Kerberosはパスワードをサービスへ送らずに済む。これが利点のひとつ。

    3. 正解。TGTを示してサービスチケットを得て、それをサービスに示すと利用を許可される。

    4. TGTはチケットをもらうためのチケット。サービスにはサービスチケットを示す。

  5. 社内の認証をKDC 1台で運用している。運用上の評価として、適切なものはどれか。

    1. 正解。KDCは止まると全体が止まり、侵害の影響も大きい。冗長化して厳重に保護する。

    2. KDCは認証とチケット発行を担う。止まると全体に影響が及ぶ。

    3. 有効期限があっても、KDCの侵害の影響は大きい。冗長化と保護が要る。

    4. RADIUSサーバはKerberosのKDCの代わりにならない。KDCは止まる・侵害される影響が大きく、冗長化と保護が要る点は変わらない。

  6. Kerberos環境で、あるサーバだけ利用者の認証が失敗する。パスワードは正しく、KDCは稼働している。調べると、そのサーバの時計が大きくずれていた。対応として、適切なものはどれか。

    1. パスワードは正しいと確認できている。時刻のずれが大きいと認証に失敗するので、原因は時計のずれ。

    2. 正解。時刻のずれは認証失敗の原因になる。時刻は同期して保つ。

    3. 有効期限はチケットの仕組みの一部。原因は時計のずれなので、期限をなくすのではなく時計を合わせる。

    4. 冗長化はKDCの停止への備え。時刻のずれによる認証失敗は防げない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. RADIUSで認証を一元化すると何が楽になり、何を守る必要が出るかを、頭の中で説明してみよう。

    答えを開く

    入口の装置がRADIUSクライアントとなり、認証要求をサーバへ転送して、許可か拒否の結果に従う。利用者の登録が一か所なので、削除や変更も一度で済み、認証・認可・利用記録もサーバで扱える。一方、共有秘密は推測されにくくして使い回さず、通信は保護された経路で運ぶ。

    思い浮かんだ要素にチェック

  2. Kerberosの認証の流れと、成立の前提・弱点を頭の中で整理してみよう。

    答えを開く

    利用者はKDCで認証を受けてTGTを得て、TGTを示してサービスチケットを得て、それをサービスに示して利用する。パスワードをサービスへ送らずに済む。ただしチケットには有効期限があり、時刻のずれが大きいと認証に失敗する。KDCは停止や侵害の影響が大きいので、冗長化と保護が要る。

利用者認証の見直しに関する調査記録（ダミー）
現状: 無線LANの親機とVPN装置ごとに、利用者の登録を持つ
退職者の削除を、装置ごとに行っており、消し忘れが出た
各装置は外部サーバとの連携機能を持つが、チケットは扱えない
要件: 利用者の登録を一か所にまとめ、削除も一度で済ませたい

要件を満たす構成として、適切なのは？

答えを開く

各装置をRADIUSクライアントにして、RADIUSサーバへ認証を問い合わせる

よくある誤答

  • 管理者が毎週、各装置の登録を点検して直す … 登録は装置ごとに残り、一か所にならない
  • 利用者にKerberosのチケットを配り、各装置で検証する … 装置はチケットを扱えない
