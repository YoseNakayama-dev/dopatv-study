OSコマンドインジェクション 成立条件と、シェルを使わない対策

  1. シェル経由で外部コマンドを呼び、外部入力を連結し、無害化もしないと成立する。
  2. 根本対策はシェルを介さず引数を分けて呼ぶこと。やむを得ない場合は許可リストで検証する。
  3. 被害はアプリの実行権限の範囲でroot実行は大きい。最小権限・WAFは補助で、エスケープだけでは取りこぼす。

  1. 動画で出た問題OSコマンドインジェクションの対策として、適切なのは？

    1. HTMLエスケープは、XSSの対策

    2. シェルを介さないAPI

    3. プレースホルダは、SQLの対策

    4. secure属性は、Cookieの送信の制限

  2. OSコマンドインジェクションの成立条件は、①シェル経由の外部コマンド呼び出し、②外部入力をコマンド文字列に含める、③検証・無害化なし、の3つ。設計の見直しで成立そのものをなくせるものはどれか。

    1. ①②が残る限り、無害化や検証に頼る形になり、成立の根を断てない。「確実に」は言い過ぎ。

    2. 最小権限は被害を抑える補助で、成立は防げない。

    3. WAFは補助で、条件が揃っていれば脆弱性そのものは残る。

    4. 正解。①を外せば、そもそも成立しない。

  3. ネットワーク診断機能は、root以外の専用アカウントで動いている。それでも診断画面から想定外のコマンドが実行された。被害の評価として最も適切なものはどれか。

    1. 正解。得られるのはアプリの実行権限の分だけだが、漏えい・改ざん・踏み台は起こりうる。

    2. 権限が低ければ被害は抑えられるが、被害が出ないとは言えない。

    3. 被害は実行権限の範囲による。「必ず」は言い過ぎ。

    4. 踏み台になりうることは否定できない。断定は誤り。

  4. 既存の製品の制約でどうしてもシェル経由で外部コマンドを呼ぶ必要がある。入力されたホスト名の扱いとして最も適切なものはどれか。

    1. エスケープだけでは取りこぼしが残る。

    2. WAFは補助で、入力の扱いの不備は直らない。

    3. 正解。やむを得ない場合は許可リストで検証し、最小権限などを補助にする。

    4. 最小権限は被害を抑える補助で、入力の検証の代わりにならない。

  5. Webアプリをrootで動かしたまま、シェル経由の外部コマンド呼び出しが残っている。リスクの評価として最も適切なものはどれか。

    1. 被害の範囲はアプリの実行権限による。成立した場合、rootなら被害は大きくなる。

    2. 正解。得られるのはアプリの実行権限の分。rootなら被害は大きくなる。

    3. シェルを介さなければ、そもそも成立しない。問題の向きが逆。

    4. 最小権限は被害を抑える補助で、呼び出し方の問題は残る。

  6. OSコマンドインジェクション対策の優先順位の説明として最も適切なものはどれか。

    1. 正解。根本はシェルを介さず引数を分けて呼ぶこと。許可リスト・最小権限・WAFは補助。

    2. エスケープだけでは取りこぼしが残る。

    3. WAFは補助で、脆弱性そのものは直らない。

    4. 許可リストはやむを得ない場合の対策。最小権限やWAFは被害を抑える補助として組み合わせる。

  2. 診断機能の改修で、エスケープの追加だけで済ませてはいけない理由と、被害を抑える補助策を頭の中で説明してみよう。

    答えを開く
