クラウドの責任共有モデル IAMと設定不備

  1. 事業者はクラウド自体（施設・ネットワーク・仮想化基盤）、利用者はデータ・アカウント・設定を守る。範囲は形態で変わる。
  2. どの形態でも、データとアクセス権の管理は利用者に残る。設定の誤りは利用者側の事故に直結する。
  3. 対策は最小権限、管理者の多要素認証、設定の継続点検、監査ログの有効化と保全。ログは見直して初めて役に立つ。

クイズ

  1. 動画で出た問題クラウドの責任共有モデルの説明として、適切なものは？

    1. SaaSでも、データとアクセス権は利用者

    2. IaaSのOSは利用者が管理する

    3. データとアクセス権は利用者に残る

    4. 設定の点検は利用者が行う

  2. IaaS上の仮想サーバで、OSの更新が長期間適用されていなかった。責任共有モデルの整理として最も適切なものはどれか。

    1. 正解。IaaSではOS以上が利用者の管理範囲になる。ただし細部は事業者の資料で確認する。

    2. 事業者が守るのは施設・ネットワーク・仮想化基盤。IaaSではOS以上は利用者が管理する。

    3. 担当範囲はIaaS/PaaS/SaaSで変わる。形態によらず事業者がすべて担うという整理は誤り。

    4. 担当範囲の細部は、事業者ごとの資料で確認する。確認せずに一任するのは誤り。

  3. 不正な設定変更が疑われ、調査のために初めて操作の監査ログを有効にした。事故前の操作記録は残っていなかった。再発防止として最も適切なものはどれか。

    1. 監査ログの有効化は、事故が起きる前に済ませておく。事故後に有効にする運用では、今回と同じく事故前の記録がない状態になる。

    2. 正解。事故が起きる前に有効にして保全し、見直す運用にする。

    3. 監査ログは、有効にして保全し、見直して初めて役に立つ。有効化だけでは足りない。

    4. 自動点検ツールは設定の不備を見つけるためのもの。操作を記録する監査ログの代わりにはならない。

  4. 開発チームが、クラウドのアクセスキーをソースコードに埋め込んでいる。このキーには、手間を省くため広い権限が付いている。利用者側の対策として最も適切なものはどれか。

    1. アクセス権の管理は利用者に残る。キーが公開されると第三者に使われうるので、権限を絞る必要がある。

    2. 多要素認証は管理者の認証を強くする対策。キーが公開されると第三者に使われうるという問題は、埋め込みをやめて権限を絞って対処する。

    3. 監査ログは操作を記録するもので、見直して初めて役に立つ。広い権限を許す理由にはならない。

    4. 正解。アクセスキーの埋め込みと広すぎる権限は設定不備の例。埋め込みをやめ、最小権限にする。

  5. IaaSの仮想サーバで、管理用の通信が全体に向けて許可されていることが点検で見つかった。事業者の基盤に問題は報告されていない。対処として最も適切なものはどれか。

    1. 設定は利用者が守る範囲。基盤に問題が報告されていないので、事業者の修正を待つ筋ではない。

    2. 多要素認証は管理者の認証を強くする対策で、全体への許可という設定不備を直すものではない。

    3. 正解。管理用の通信の全体許可は設定不備の例で、利用者が許可範囲を絞る。

    4. 監査ログは操作の記録で、見直して初めて役に立つ。点検で見つけた不備を直す代わりにはならない。

  6. 夜間バッチ用のアカウントが、ストレージの読み取りだけを行うのに、全操作を許可する権限を持っている。IAMの観点での対応として最も適切なものはどれか。

    1. 正解。権限は、必要な操作だけを許可する最小権限に絞る。

    2. 広すぎる権限を付けたままにするのは設定不備の例で、必要な操作だけに絞る。人が操作しないことは、権限を広くしてよい理由にならない。

    3. 監査ログは操作を記録するもので、権限を絞る代わりにはならない。最小権限は必要な操作だけを許可する対策。

    4. アカウント・アクセス権と設定は、利用者が守る範囲。権限を絞るのは利用者側の対策。

頭の中で考える

  1. 「クラウドは事業者が守るので、設定ミスの責任も事業者にある」という主張の誤りを、頭の中で説明してみよう。

    答えを開く

    事業者が守るのはクラウド自体（施設、ネットワーク、仮想化基盤）。データ、アカウント・アクセス権、設定は利用者側に残る。どの利用形態でもデータとアクセス権の管理は利用者の責任で、公開設定や広すぎる権限などの設定の誤りは利用者側の事故に直結する。担当範囲の細部は事業者の資料で確認する。

    思い浮かんだ要素にチェック

  2. 監査ログについて、有効化の時期と、有効にしただけでは足りない点を説明してみよう。

    答えを開く

    有効化は事故が起きる前に済ませておく。操作を記録して保全し、見直して初めて役に立つ。ログを取るだけでは足りないので、最小権限や設定の継続的な点検と組み合わせる。

午後問題にチャレンジ

クラウド上のデータ取得事案の調査記録（ダミー）
構成: クラウドのオブジェクトストレージ
調査: ストレージは、匿名の利用者でも取得できた
事業者の調査: 基盤に障害も侵害もなかった
要件: 責任の所在を踏まえ、利用企業の再発防止を決めたい

この利用企業の再発防止策として、適切なのは？

答えを開く

利用者側で公開設定を見直し、匿名の取得を許さない

よくある誤答

  • ストレージは事業者の設備なので、設定の修正も事業者に任せる … アクセス設定は、どの利用形態でも利用者の責任
  • 事業者の基盤が破られたとして、対策の強化を待つ … 調査では、基盤に障害も侵害もなかった
