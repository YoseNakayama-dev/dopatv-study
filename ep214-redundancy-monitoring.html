#114 ・ 第5章 情報セキュリティ対策技術（1）予防・検知・防御

二重化・監視・クラスタ・RAID 止めない備えと気付く仕組み

  1. 冗長化は単一障害点をなくすが、同じ原因の故障や誤操作は防げない。切替は事前に試験する。
  2. 機器がping応答してもサービスが動くとは限らない。サービス自体の応答も確認する。
  3. ハートビートが途切れ両系が稼働系になるとデータが壊れうる。RAIDはバックアップの代わりでない。
用語 9クイズ 6考える 2午後本

用語カード

クイズ

  1. 動画で出た問題可用性対策の説明として、適切なものは？

    1. RAID1は1台の故障に耐える

    2. RAID5は1台の故障まで

    3. 待機系は通常は待機

    4. 誤削除は戻せない

  2. 2台のHAクラスタで、ハートビートは1本のLANだけで通していた。スイッチの故障で通信が途切れ、両方のノードが稼働系になって共有データに不整合が出た。再発防止として最も適切なものはどれか。

    1. 台数を増やしても、ハートビートが途切れて両方が稼働系になる状況は起こりうる。原因は状態確認の通信にある。

    2. 正解。ハートビートの経路を二重にしておけば、片方が故障しても途切れにくく、両方が稼働系になる事態に備えられる。

    3. 性能監視は使用状況を見て警報を出す仕組みで、状態確認の通信が途切れる原因には対処しない。

    4. RAIDはディスクの故障に備えるもの。両方が稼働系になって書き込みが衝突する問題とは別である。

  3. ファイルサーバは4台のディスクのRAID5構成だった。1台が故障し、交換する前に2台目も故障してデータが読めなくなった。今後の設計見直しとして最も適切なものはどれか。

    1. RAID5が耐えるのは1台の故障までである。台数を増やしても、この性質は変わらない。

    2. RAIDは誤削除や暗号化されたデータを戻せず、バックアップの代わりにならない。RAID1に変えても不要にはならない。

    3. 正解。RAID6はパリティを二重に持ち、2台の故障まで耐える。そのうえで、RAIDで戻せない事態に備えてバックアップも併用する。

    4. 気付くのが早くなっても、冗長性の範囲を超えた故障が起きれば読めなくなる。構成の見直しにならない。

  4. 稼働系と待機系の2台構成で、更新時の誤操作により両方に同じ誤った設定が反映された。切替は自動で行われたが、待機系でも同じ原因で停止が続いた。この事象の評価として最も適切なものはどれか。

    1. 追加した待機系にも同じ誤設定が反映されれば、同じ原因で止まる。台数を増やしても、同じ原因の故障は防げない。

    2. 切替自体は動いている。切替の試験は大切だが、同じ原因で両方が止まる事象を「必ず防げた」とは言えない。

    3. 冗長化の目的は、一部が壊れても止めないこと。同じ原因で止まり続けたのだから、目的を果たしたとは言えない。

    4. 正解。冗長化の限界として、同じ原因で同時に壊れる故障や誤操作は防げない。この種の事象には別の備えが要る。

  5. ファイルサーバのディスク使用率はグラフに記録されていたが、警報の設定は無かった。使用率が少しずつ上がって満杯になり、サービスが停止した。機器とサービスは直前まで応答していた。見直しとして最も適切なものはどれか。

    1. 正解。性能監視は使用状況を見て、しきい値を超えたら警報を出し、担当者の対応につなげる。容量が尽きる前の増強判断にもつながる。

    2. 機器やサービスは直前まで応答していた。動いているかの確認を増やしても、使用率の増加には気付けない。

    3. RAID1はディスクの故障に備えるもので、容量不足を防ぐものではない。

    4. ハートビートはクラスタの状態確認の通信で、使用率の増加とは関係がない。

  6. 稼働系と待機系の構成を導入して2年たつ。死活監視は両系とも正常で、障害時は自動で待機系に切り替わる設定だが、切替を実際に試したことはない。評価として最も適切なものはどれか。

    1. 死活監視が見るのは動いているかどうかで、障害時に切替が手順どおり進むかは別の話である。

    2. 正解。切替の手順は事前に試験しておく。設定があることと、実際に切り替わることは別である。

    3. 設定があっても、実際に動くかは試すまで分からない。自動で動くと決めつけられない。

    4. 性能監視は使用状況を見て警報を出す仕組みで、障害時に切替が手順どおり進むかを確かめるものではない。

頭の中で考える

  1. サーバがpingに応答しているのに、Webサービスだけが止まっていた。なぜ見落とすのか、どう備えるかを頭の中で説明してみよう。

    答えを開く

    pingは機器が動いているかを見るだけで、サービスが動いているとは限らない。サービス自体の応答（HTTP要求への応答など）を確認するヘルスチェックを併用し、応答がなければ振り分けから外す。

    思い浮かんだ要素にチェック

  2. クラスタでスプリットブレインが起きる流れと、備えを頭の中で説明してみよう。

    答えを開く

    ハートビートが途切れ、相手が止まったと判断して両方が稼働系になる。同じデータへ両方が書き込み、データが壊れうる。状態確認の通信経路を二重にして備える。

    思い浮かんだ要素にチェック

午後問題にチャレンジ

Web2台構成の障害記録（ダミー）
Webサーバ2台に、負荷分散装置が処理を振り分ける
装置は、各サーバへのpingの応答で、動作を確認する
昨夜、サーバAのWebサービスのみ停止。pingは応答
装置はAへの振り分けを続け、一部の利用者がエラー
要件: 停止したサーバへの振り分けを、自動で止めたい

適切な対策は、どれ？

答えを開く

装置が、Webサービスの応答を確認し、なければ振り分けから外す

よくある誤答

  • pingの間隔を短くする … Aはpingに応答しており、間隔を短くしても停止を検知できない
  • サーバを3台に増やす … 台数を増やしても、停止したAへの振り分けは止まらない
