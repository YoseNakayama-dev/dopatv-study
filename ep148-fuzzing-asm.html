#48 ・ 第5章 情報セキュリティ対策技術（1）予防・検知・防御

ファジングとASMの概要 未知の穴と未把握の資産

  1. ファジングは不正な入力を大量に自動で与え、異常から未知の脆弱性の手がかりを探す手法。
  2. 検証環境で行い、異常検知と再現入力の記録が要る。異常がすべて脆弱性とは限らず、無くても安全とは言えない。
  3. ASMは公開資産を継続的に洗い出して台帳と照合する。診断は決めた対象を深く調べる点が違う。

用語カード

用語を見て意味を言えるか試し、タップで裏返します。「覚えた」を続けるほど定着度が上がり、「まだ」で最初に戻ります。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題ファジングの説明として、適切なのは？

    1. 正常な入力だけでは、異常を探せない

    2. それは、既知の脆弱性の診断

    3. 不正な入力で、異常を観察

    4. 設計書のレビューの説明

  2. ファイル解析ライブラリにファジングを行う。実施前の準備として最も適切なものはどれか。

    1. 正解。異常を検知する仕組みと、再現できる入力の記録が要る。対象が停止・破損しうるので検証環境で行う。

    2. 対象が停止したりデータが壊れたりしうるため、本番では行わない。再現入力の記録も必要。

    3. 他者の製品やサービスに許可なく実施しない。

    4. クラッシュや異常終了を観察するには、異常を検知する仕組みが要る。

  3. ファジングで異常終了が多数記録された。結果の扱いとして最も適切なものはどれか。

    1. 検出された異常がすべて脆弱性とは限らない。

    2. 正解。異常がすべて脆弱性とは限らないので、原因を調べて分類する作業が要る。

    3. 再現できる入力の記録は、原因の調査に必要。

    4. 異常が見つからなくても安全とは言えない。少数であることも同じで、無いとは判断できない。

  4. ファジングを実施して異常が検出されなかった。担当者は「脆弱性は無いので、診断などの他の確認は省ける」と報告した。評価として最も適切なものはどれか。

    1. 見つからなくても安全とは言えない。

    2. 到達しにくい処理は見つかりにくい。全処理が検査済みとは判断できない。

    3. 既知の脆弱性の確認が中心なのは脆弱性診断。ファジングはそれを補う位置づけ。

    4. 正解。ファジングには限界があり、見つからなくても安全とは言えない。診断を補う位置づけ。

  5. ASMと脆弱性診断の違いを述べた説明として最も適切なものはどれか。

    1. 正解。診断は決めた対象を深く調べ、ASMは対象そのものを継続的に探す。

    2. 役割が逆。診断が決めた対象を深く調べ、ASMが対象を探す。

    3. ASMは継続的に洗い出す取り組み。一度で完了するものではない。

    4. ASMは外部から見える範囲が中心で、内部資産は見づらいのが限界。

  6. ASMで、台帳にない公開資産が見つかった。発見後の流れとして最も適切なものはどれか。

    1. ASMの流れは、発見のあとに照合・管理者の特定・評価・対処が続く。見つけただけでは終わらない。

    2. 正解。発見、台帳との照合と管理者の特定、評価、対処の順に進め、継続する。

    3. 管理者の特定は人手で行う。分からない資産を対象から外して終わりにすると、台帳にない資産が放置され、診断や更新から漏れて攻撃対象になりやすい。

    4. 流れは台帳との照合と管理者の特定、評価のあとに対処する順。削除を先にしない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. ファジングで異常が見つからなかったとき、安全と言えない理由を、頭の中で説明してみよう。

    答えを開く

    到達しにくい処理は見つかりにくく、見つからなくても安全とは言えない。脆弱性診断を補う位置づけで使う。

    思い浮かんだ要素にチェック

  2. 台帳にない公開資産が危険になる理由と、ASMで見つけた後の流れ、ASMの限界を、頭の中で説明してみよう。

    答えを開く

    把握していない資産は診断や更新の対象から漏れ、攻撃対象になりやすい。ASMは発見、台帳との照合と管理者の特定、評価、対処の順に継続する。限界は、外から見える範囲が中心で内部は見づらく、管理者の特定や対処が人手になること。

    思い浮かんだ要素にチェック

午後問題にチャレンジ

動画の午後問題です。ログを読んで、答えを頭の中で決めてから開いてください。

公開資産の調査記録（ダミー）
対象: 自社の、インターネットに公開している資産（ダミー）
資産台帳に記載の公開サーバは12台。12台は、定期診断と更新が済んでいる
今回、外部から公開資産を調べる作業を、担当者が、手作業で一度だけ行った
結果、台帳にない公開サーバが2台あり、OSに公開済みの弱点が残っていた
2台は、過去の検証用に部門が個別に立てたもの。今回の洗い出しで初めて存在が判明した

台帳にない資産への対策として、適切なのは？

答えを開く

公開資産を継続的に洗い出し、台帳と照合する

よくある誤答

  • 台帳の12台の診断を増やす … 12台は、診断と更新が済んでいる
  • 2台の弱点を直して終える … 修正は個々の脆弱性への対処。設問は、台帳にない資産を把握する対策

  • 5.3.4 ASMの概要

ファジングの準備と限界、ASMの流れと診断との違い、外部から見える範囲が中心という限界を確かめながら読む。
