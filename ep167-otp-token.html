#67 ・ 第6章 情報セキュリティ対策技術（2）アクセス制御と認証

トークンによるOTP認証 手のひらで変わる合言葉

  1. トークンはOTPを表示する携帯認証装置。パスワード（知識）に所持を加えて二要素にできる。
  2. 時刻同期は秘密情報と現在時刻、イベント同期は秘密情報と使用回数から計算する。ずれに注意。
  3. 紛失は速やかに無効化し、ずれは許容範囲と再同期で吸収する。偽画面へのその場の入力は防げない。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題時刻同期方式のトークンの説明として、適切なのは？

    1. 回数から計算するのはイベント同期方式

    2. 固定の値は使い回せてしまう

    3. 秘密情報と現在時刻から計算

    4. 値の入力と応答は別の方式

  2. パスワードとトークンを併用している従業員が、トークンを電車で紛失したと連絡してきた。対応として、適切なものはどれか。

    1. 正解。紛失したら速やかに該当トークンを無効にして、拾った人に使わせない。

    2. パスワードも必要なので拾っただけでは突破されにくいが、パスワードが知られれば所持の要素だけが頼りになる。紛失時は速やかに無効化する。

    3. 値が時間で無効になるのは時刻同期方式の話。イベント同期方式では次を使うまで同じ値が有効なまま残りうる。どちらも紛失したトークンの無効化の代わりにならない。

    4. 再同期は、時計や回数のずれを直す手順。紛失したトークンを安全にする手段ではない。

  3. イベント同期方式のトークンで、利用者が何度かトークンを使ったが、そのうち数回は認証サーバへ入力していない。その後、表示値でのログインが失敗するようになった。最も疑われる原因と対応はどれか。

    1. 時計のずれが問題になるのは時刻同期方式。イベント同期方式は使用回数から計算する。

    2. 正解。イベント同期方式は使用回数から計算するので、回数がずれると一致しなくなる。許容範囲と再同期の手順で吸収する。

    3. 自動的に無効になるのは時刻同期方式。イベント同期方式は、次を使うまで同じ値が有効なまま残りうる。

    4. 秘密情報は登録時に共有済み。以後はトークンが単独で計算するので、毎回値を受け取る必要はない。

  4. 時刻同期方式のトークンを使う社内システムで、ある時刻から全員の認証が失敗した。調べるとサーバの時計がずれていた。対応として、適切なものはどれか。

    1. サーバの時計のずれという事実が分かっている。時刻同期方式では、時計のずれで値が一致しなくなる。

    2. 値が変わること自体は仕様だが、全員が失敗する状態は想定外。時計のずれへの対応が要る。

    3. 全員の失敗の原因はサーバの時計のずれ。利用者の入力の速さは原因ではない。

    4. 正解。時計のずれは、時刻を合わせ、許容範囲と再同期の手順で吸収する。

  5. あるシステムは、パスワードの入力は求めず、スマートフォンのアプリが表示するOTPだけでログインさせている。この方式の分類について、適切な説明はどれか。

    1. 正解。トークンは所持の要素。パスワードという知識を加えると二要素認証になる。

    2. 毎回変わる値でも、OTPだけでは所持の1要素。知識を加えて二要素になる。

    3. ソフトウェアトークンも、ハードウェアトークンと同じく所持の要素になる。知識には分類されない。

    4. ソフトウェアトークンもハードウェアトークンと役割は同じで、所持の要素になる。

  6. トークンによるOTP認証の導入にあたり、秘密情報の管理方針を検討している。説明として、適切なものはどれか。

    1. サーバも同じ計算をして、一致すれば認証する。サーバ側にも秘密情報がある。

    2. 正解。秘密情報は登録時に共有し、利用者側もサーバ側も漏えいさせない。

    3. 共有するのは登録時。以後はトークンが単独で計算し、表示だけなら通信しなくてよい。

    4. 紛失対応と秘密情報の保護は別の対策。秘密情報は両側で守る必要がある。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 時刻同期方式とイベント同期方式の違いを、値の作り方と、ずれの種類の両面から頭の中で説明してみよう。

    答えを開く

    時刻同期方式は秘密情報と現在時刻から計算し、一定時間ごとに値が変わって自動的に無効になる。ずれるのは時計。イベント同期方式は秘密情報と使用回数から計算し、使うたびに値が変わるが、次を使うまで同じ値が有効なまま残りうる。ずれるのは回数。

    思い浮かんだ要素にチェック

  2. トークンを導入しても残る課題と、運用での備えを頭の中で整理してみよう。

    答えを開く

    紛失した場合は速やかに無効化する。パスワードと併用するので拾っただけでは突破されにくい。時計や回数のずれは許容範囲と再同期の手順で吸収する。ただし偽の画面にその場で入力させられる悪用は防げない。

社内システムの認証強化に関する調査記録（ダミー）
現状: 利用者は固定のパスワードだけで、社内システムに接続する
認証の強化のため、表示専用の小型トークンを配布する
トークンには、サーバから値を受け取る手段も、ボタンもない
サーバとトークンは、同じ秘密情報を持ち、時計も合わせてある
要件: 表示された値が、時間が経つと自動的に無効になること

要件を満たす、表示値の作り方として、適切なのは？

答えを開く

秘密情報と現在時刻から計算し、サーバも同じ計算で照合する

よくある誤答

  • 秘密情報と使用回数から計算する … 次に使うまで、同じ値が有効なまま残る
  • サーバが送る値を入力し、応答を表示する … トークンに値を受け取る手段がない

本で読む

  • 6.4.3 トークン（携帯認証装置）によるOTP認証システム

トークンの値の作り方（時刻同期・イベント同期・チャレンジレスポンス型）を比べ、それぞれで何がずれると失敗するかを確かめながら読む。
