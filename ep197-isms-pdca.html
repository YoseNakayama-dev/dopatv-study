#97 ・ 第1章 情報セキュリティ及びITの基礎

ISMSとPDCA 規格・認証・確立と運用の主な作業

  1. ISMSは作って終わりではない。計画・実施・点検・処置のPDCAで、評価と改善を回し続ける。
  2. 27000は用語と概要、27001は認証の基準となる要求事項、27002は管理策の実践規範。認証は範囲を決めて受ける。
  3. 範囲と方針、リスクの評価と残留リスクの受容判断、適用宣言書、内部監査とレビューの流れで確立と運用を行う。

  1. 動画で出た問題JIS Q 27002の説明として、適切なものは？

    1. 認証の要求事項はJIS Q 27001

    2. 管理策の実践規範

    3. 用語と概要はJIS Q 27000

    4. 個人情報の認証は別の制度

  2. 取引先からISMS認証の有無を問われた。当社は情報システム部門で、JIS Q 27002の管理策に沿った整備を済ませている。認証を受けたい場合の説明として、最も適切なものはどれか。

    1. 正解。認証を受けるときの基準になるのは27001の要求事項。認証は第三者の認証機関が審査し、範囲を決めて受ける。

    2. 認証は第三者の認証機関が審査して行うもので、社内の宣言では取得したことにならない。また基準は27002ではない。

    3. 27002は管理策を選ぶときの手引きで、認証の基準そのものではない。管理策を実施したことが基準を満たすことにはならない。

    4. 27000は用語と概要を示す規格で、用語に合わせて文書を整えても要求事項への適合にはならない。

  3. 当社のISMS認証の範囲は「情報システム部門の運用」と決められている。取引先から「営業部門が扱う顧客情報も、認証で保証されているのか」と問われた。回答として最も適切なものはどれか。

    1. 認証は範囲を決めて受けるので、会社単位とは限らない。今回は範囲が情報システム部門の運用と決められている。

    2. 情報を共有していても、範囲に含まれていない部門が自動で対象になるとは言えない。範囲の定義で決まる。

    3. 正解。認証は範囲を決めて受ける。範囲外の部門や業務は対象にならない可能性があり、定義を確認して回答する。

    4. 範囲は組織が決めるもので、規格が全社と一律に定めるものではない。

  4. 管理策を選定中。当社はクラウドだけで事業を行い、自社の機器室を持たないため、機器室の入退室に関する管理策は採用しない予定である。適用宣言書の扱いとして最も適切なものはどれか。

    1. 載せないと、検討した結果として採用しなかったのか、検討漏れなのかが分からない。採用しない理由を示す必要がある。

    2. 形式的に採用したことにすると、実態と宣言書が食い違う。採用しない管理策は理由を示せばよい。

    3. 内部監査は運用後の点検で、宣言書の段階で示す理由の代わりにならない。宣言書に理由を示す。

    4. 正解。適用宣言書は選んだ管理策をまとめた文書で、採用しない管理策もその理由を示す。

  5. リスク対応を実施したが、一部のリスクが許容できる水準まで下がり切らず残っている。担当者は「ゼロになるまで追加対策を続けるので、運用開始は延期する」と述べた。判断として最も適切なものはどれか。

    1. 正解。リスク対応のあとに残るリスクは、受容してよいか判断する。受容できないなら、追加の対応を選ぶ。

    2. リスクをゼロにすることが前提ではない。残るリスクについて、受容してよいかを判断する流れになる。

    3. 残るリスクがあるからといって対応の失敗とは限らず、評価の最初からやり直す理由にならない。

    4. 受容の判断は、リスク対応のあとの作業。内部監査は運用後の点検で、時期も役割も違う。

  6. 規程を整備し、全社への周知と研修も終えた。担当者が「実施まで完了したのでISMSの確立は終わり。以後は現状を維持すればよい」と報告した。指摘として最も適切なものはどれか。

    1. 記録は必要だが、それだけでは評価にならない。点検では監視や内部監査で有効性を評価する。

    2. 守れているかだけでなく、効いているかも見るのが点検。効果の評価を別にすると、改善につながらない。

    3. 正解。点検で有効性を評価し、処置で不適合に是正処置をとり、その結果を次の計画に反映して回し続ける。

    4. 改善を一度にまとめると、不適合が放置される期間が長くなる。回し続けることが肝心で、時期を固定しない。

頭の中で考える

  1. ISMSでPDCAの各段階（計画・実施・点検・処置）が、それぞれ何をするか。頭の中で整理してみよう。

    答えを開く

    計画では適用範囲と方針を決め、リスク対応の計画を立てる。実施では管理策を導入し運用し、記録を残す。点検では監視と内部監査で有効性を評価する。処置では不適合に是正処置をとり、改善の結果を次の計画に反映する。

    思い浮かんだ要素にチェック

  2. 27000・27001・27002の役割の違いと、「認証」で何が審査されるかを、頭の中で説明してみよう。

    答えを開く

    27000は用語と概要、27001はISMSの要求事項で認証の基準、27002は管理策の実践規範で認証の基準そのものではない。認証は第三者の認証機関が審査し、範囲を決めて受けるため、範囲外は対象にならない。

午後問題にチャレンジ

ISMS内部監査の結果記録（ダミー）
リスク対応計画は承認され、運用に移された
内部監査で、手順の未実施が1件見つかった
原因は、担当者が手順を知らなかったことだった
要件: 同じ不適合を、繰り返さないようにしたい

このあとの対応として、適切なのは？

答えを開く

原因（手順の周知不足）への是正処置を決め、実施後に有効性を確認する

よくある誤答

  • リスクアセスメントを最初からやり直す … 不適合の原因は、手順の周知不足にあり、リスク評価ではない
  • 原因が分かっているのに、見つかった1件だけを直す … 要件は再発防止であり、原因への対応が要る
