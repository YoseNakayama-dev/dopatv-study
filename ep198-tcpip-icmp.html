#98 ・ 第1章 情報セキュリティ及びITの基礎

TCP/IPの基礎 IP・TCP・UDP・ICMP の役割分担

  1. IPは宛先を示してルータが中継するが、到達も順序も保証しない。保証は上の層が補う。
  2. TCPは接続の確立・順序・再送で確実さを取り、UDPは再送せず遅延の小ささを取る。どちらもポートで識別する。
  3. ICMPはエラー通知と到達性の確認に使う。全遮断は障害の切り分けや経路MTUに響き、全許可は探索に使われうる。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題ICMPの説明として、適切なものは？

    1. 接続・順序・再送はTCP

    2. 名前解決はDNS

    3. エラー通知と到達性の確認

    4. ポート番号はTCP・UDPの仕組み

  2. FWでICMPを全て遮断したところ、特定の拠点との間で、小さな通信は通るのに大きなデータの転送だけが止まるという報告が出た。調査の方針として最も適切なものはどれか。

    1. 正解。全遮断は経路MTU探索（Fragmentation needed）に影響しうる。必要な種類のICMPだけを許可するのが基本の考え方。

    2. ICMPはpingだけでなく、経路MTUの調整にも使われる。大きな転送だけが止まる症状は、その影響の可能性がある。

    3. 帯域の不足であれば小さな通信にも影響が出やすい。ICMPの影響を確かめずに、回線の増強へ進むのは根拠が弱い。

    4. 全許可は機器の探索に使われうる点が残る。全遮断も全許可も避け、必要な種類だけを許可する。

  3. tracerouteを実行すると、3番目のホップ以降の応答が全て「*」になり、最終宛先まで表示されなかった。この結果の扱いとして最も適切なものはどれか。

    1. tracerouteはTTLが尽きた機器から返る通知で経路を調べる。通知が返らないのは、その機器が返さない場合や途中で遮断される場合もある。

    2. 正解。応答がないことは障害の確定を意味しない。ほかの確認と組み合わせて判断する。

    3. 通知が返らなくても、先の機器が動いていないとは限らない。宛先の停止と結論づけるのは言い過ぎ。

    4. 経路の確認に使える手段であり、結果が部分的でも手がかりにはなる。切り捨てず、他の確認と併用する。

  4. 同じ宛先IPアドレスに対して、Web用のTCP 443番と、別のアプリ用のTCP 8443番の通信がある。ルータが基本の動作として、次の転送先を選ぶときに主に参照するものはどれか。

    1. ポート番号はアプリを識別するためのもの。基本の動作では、ルータは宛先を見て経路を選ぶ。条件によって例外的な設定はありうる。

    2. ポート番号の組は、通信先のアプリを識別するために端末側で使われる。経路選択の基本の情報は宛先のアドレスになる。

    3. 接続の確立はTCPが端末同士で行う手順。ルータは宛先を見て次の経路を選び、中継する。

    4. 正解。IPは宛先アドレスを示し、ルータはそれを見て次の経路を選ぶ。アプリの識別はTCP・UDPのポート番号の役割。

  5. 社内の通知アプリがUDPで通知を送っている。ネットワークが混む時間帯に、通知が届かないことがある。開発担当者は「UDPでもOSが自動で再送し、順序も整える」と説明した。指摘として最も適切なものはどれか。

    1. 正解。UDPは接続を作らず、再送も順序の回復もしない。確実さが要る用途では、TCPを使うかアプリ側で補う。

    2. UDPもポート番号でアプリを識別する。欠落の原因はポート番号の有無ではなく、再送の仕組みがないこと。

    3. IPは到達も順序も保証しない。保証は上の層が補うので、IPが再送を担うという前提が誤り。

    4. ICMPはエラー通知や到達性の確認に使うもので、UDPの再送とは関係がない。遮断しても解消しない。

  6. 監視サーバから対象のWebサーバへpingは通るが、TCP 443番への接続は確立できない。SYNを送ってもSYN/ACKが返ってこない。判断として最も適切なものはどれか。

    1. pingはIPレベルの到達性を示すだけで、TCP 443番が動作している証拠にはならない。監視側だけに原因を絞るのは早すぎる。

    2. 正解。pingはICMPによる疎通の確認で、特定ポートのTCP接続とは別。FWの設定など、ポートの側も確認する。

    3. pingが通る以上、経路は届いている可能性が高い。TCPの失敗を全て経路の障害と断定するのは言い過ぎ。

    4. SYN/ACKが返らないのは、順序の保証とは別の問題。再試行だけで解消すると決めつけず、原因を確認する。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. IPが「到達も順序も保証しない」のに、WebやメールがTCP/IPで成り立つのはなぜか。頭の中で説明してみよう。

    答えを開く

    IPは宛先を示してルータが中継する役割で、到達や順序は保証しない。その保証は上の層が補う。TCPが接続の確立、順序の整理、欠けた分の再送を行うので、確実さが要る通信が成り立つ。遅延を重視する用途では、再送しないUDPを使う。

    思い浮かんだ要素にチェック

  2. FWでICMPを「全遮断」「全許可」にしない理由を、頭の中で説明してみよう。

    答えを開く

    全遮断すると、障害の切り分けが難しくなり、経路MTUの調整にも影響しうる。全許可だと、機器の探索に使われる点が残る。そのため、必要な種類のICMPだけを許可する。

    思い浮かんだ要素にチェック

音声通話の通信要件（ダミー）
用途: 社内の音声通話。遅延は小さいほどよい
パケットが少し欠けても、通話は成り立つ
欠けた分を再送して待つと、声が遅れて届く
要件: 遅れを増やさず、音声を連続して届けたい

トランスポート層で、適切なのは？

答えを開く

UDP。再送せず、遅れを増やさずに送る

よくある誤答

  • TCPで、欠けた分を再送させる … 再送を待つと、声が遅れて届く
  • TCPのまま、再送の回数だけ減らす … TCPは順序を保つため、欠けた分があると、後ろのデータも待たされる
