#38 ・ 第3章 情報セキュリティにおける脆弱性

HTTPとセッション管理 IDを持つ人が本人になる仕組み

  1. HTTPは1回ごとのやり取りが独立（ステートレス）で、セッションIDをCookieで毎回送り利用者を見分ける。
  2. 弱点は推測・盗用・固定化の3つ。IDを持つ人が利用者として扱われるので、IDの扱いが要になる。
  3. 乱数ID・URLに含めない・Cookie属性・ログイン後の再発行・サーバ側の破棄を重ねる。HttpOnlyはXSSを防がない。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題セッション管理の対策として、適切なのは？

    1. ログイン後にIDを再発行する

    2. URLに含めると、外部へ漏れやすい

    3. 規則的なIDは、推測される

    4. 破棄しないと、盗まれたIDが使える

  2. ログイン前と後でセッションIDが同じ値のままで、攻撃者があらかじめ用意したIDを利用者に使わせることができる。この問題の分類と対策として最も適切なものはどれか。

    1. 乱数は推測への対策。ここでは攻撃者が用意したIDを使わせているので、固定化の問題。

    2. 正解。攻撃者が用意したIDを使わせる固定化には、ログイン成功後のID再発行が有効。

    3. HttpOnlyはXSS経由の盗用を限定する属性。固定化の対策ではない。

    4. 推測は規則的なIDを当てる問題。ここでは当てるのではなく、用意したIDを使わせている。

  3. XSSが残っているサイトで、セッションIDのCookieにHttpOnly属性を付けた。評価として最も適切なものはどれか。

    1. HttpOnlyはXSS自体を防がない。

    2. 再発行は固定化に有効な別の対策で、HttpOnlyの代わりにはならない。

    3. HttpOnlyは盗聴を防ぐものではない。通信の暗号化（HTTPS）が前提になる。

    4. 正解。HttpOnlyはXSS経由の盗用を限定するが、XSSそのものは防がない。

  4. HTTPはステートレスだが、ログイン状態は保たれる。その仕組みの説明として最も適切なものはどれか。

    1. HTTPは前の状態を覚えていない。そのためサーバがセッションIDを発行して利用者を見分ける。

    2. 毎回送られるのはパスワードではなくセッションID。

    3. 正解。サーバがセッションIDを発行し、ブラウザがCookieに保存して以降の要求に毎回付けて送る。

    4. Cookieの付与はブラウザが自動で行う。

  5. 利便性のため、セッションIDをURLのパラメータに含める設計を提案された。評価として最も適切なものはどれか。

    1. 乱数は推測への対策。URLに含めること自体が外部への漏えいの経路になる。

    2. 正解。URLに含めると外部へ漏れやすい。IDはURLに含めない。

    3. HTTPSは通信の盗聴への前提だが、URL経由の漏えいは防げない。

    4. SameSiteはCookieの属性で、URLの中のIDを守るものではない。

  6. ログアウトや一定時間の無操作の後のセッションの扱いとして、最も適切なものはどれか。

    1. 期限切れと破棄はサーバ側で行う。ブラウザ側の削除だけでは足りない。

    2. 破棄しないと、盗まれたIDが使い続けられる。乱数は推測への対策。

    3. 再発行は固定化への対策。期限切れと破棄は別に要る。

    4. 正解。期限切れと破棄はサーバ側で行い、通信はHTTPSにする。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. セッションIDの弱点（推測・盗用・固定化）を、それぞれ一言で区別し、対策を結びつけてみよう。

    答えを開く

    推測は規則的なIDを当てられる弱点で、暗号論的乱数で防ぐ。盗用は盗聴・XSS・URL経由の漏えいなどで入手される弱点で、HTTPS、URLにIDを載せない、Cookie属性で備える。固定化は攻撃者のIDを使わされる弱点で、ログイン後の再発行で防ぐ。

    思い浮かんだ要素にチェック

  2. 外部サイトのログに利用者のIDを含むURLが残り、そのIDで操作された。IDは長い乱数で、ログイン後に再発行されていた。原因と直し方を頭の中で説明してみよう。

    答えを開く

    原因はURLに含めたセッションIDが外部へ漏れて使われたこと。乱数なので推測ではなく、再発行されているので固定化でもない。IDをURLに含めず、Cookieで送る。

    思い浮かんだ要素にチェック
