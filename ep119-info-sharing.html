#19 ・ 第2章 情報セキュリティにおける脅威

サイバーセキュリティ情報の共有 J-CSIP・ISAC・TLPの考え方

  1. 攻撃者は似た手口を複数の組織に使うことがあり、共有すると他組織が早く気づいて備えられる。
  2. 共有では通信先やファイルの特徴値、手口と対処を扱い、個人・顧客情報は除いてTLPで範囲を決める。
  3. 共有された情報は古い・誤りもありうるため、自組織で確認して使い、自分からも出して信頼を育てる。

用語カード

用語を見て意味を言えるか試し、タップで裏返します。「覚えた」を続けるほど定着度が上がり、「まだ」で最初に戻ります。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題TLPの「赤（RED）」が示すのは、次のうちどれ？

    1. 名指しの受け手のみ・再共有しない

    2. 公開してよいのは、CLEAR（旧WHITE）

    3. コミュニティ内は、GREEN

    4. 色は緊急度でなく、共有範囲

  2. 標的型メールの被害を、業界のISACへ共有したい。手元の調査ログには、通信先とファイルの特徴値のほか、顧客名の抜粋が混ざっている。対応として最も適切なものはどれか。

    1. 除去は共有する側が共有前に行う。受け手に任せると、個人・顧客情報が出てしまう。

    2. 正解。個人・顧客情報そのものは共有せず、攻撃の特徴や手口を、取り除いたうえで共有する。

    3. 共有しないと、他組織が同じ手口に気づけない。共有すべき情報と除くべき情報を分けるのが要点。

    4. TLPは共有範囲の目印で、個人・顧客情報を共有してよい根拠にはならない。

  3. 共有された情報にTLP:GREENと付いていた。取扱いとして最も適切なものはどれか。

    1. 公開してよいのはCLEAR（旧版ではWHITE）。GREENは公開までは認めない。

    2. 名指しの受け手のみで再共有しないのはRED。GREENはそれより広い。

    3. 正解。GREENは同じコミュニティ内で共有できる範囲。公開はCLEARの扱いになる。

    4. TLPの色は緊急度ではなく共有範囲を示す。緊急度と取り違えない。

  4. 他組織から共有された通信先の一覧を、そのままFWの遮断リストへ全件登録する案が出た。共有情報の限界を踏まえた対応として最も適切なものはどれか。

    1. 共有された情報は古い・誤りもありうる。確認せずに登録すると、正規の通信を止めるおそれもある。

    2. 誤りがありうることは、使わない理由にならない。自組織で確認して活用する。

    3. TLPは共有範囲の目印で、内容の正確さを示すものではない。

    4. 正解。情報は古かったり誤りがあったりするので、自組織で確認して使う。

  5. 脅威情報を機械で処理できる形式で表し、組織間で自動的に交換したい。STIXとTAXIIの役割の組合せとして最も適切なものはどれか。

    1. 役割が逆。表現がSTIX、交換がTAXII。

    2. 正解。STIXは脅威情報の表現形式、TAXIIはその交換のプロトコル。

    3. どちらも暗号化のための標準ではない。表現と交換の仕組みである。

    4. 共有範囲の目印はTLP、組織の枠組みはISACなど。STIXとTAXIIの説明ではない。

  6. IPAを情報の窓口として、参加組織の間で標的型攻撃などの情報を共有する取組みはどれか。

    1. ISACは業界・分野ごとの組織が情報を持ち寄る枠組み。IPAが窓口とは限らない。

    2. JPCERT/CCはインシデント対応の調整、注意喚起、情報提供を行う組織。

    3. 正解。J-CSIPはIPAが窓口になり、参加組織間で攻撃情報を共有する取組み。

    4. TLPは共有範囲を色で示す目印で、取組みや組織の名前ではない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 被害を受けた組織が、自社の被害情報を黙っておくより共有したほうがよいとされる理由を、頭の中で説明してみよう。

    答えを開く

    攻撃者は似た手口を複数の組織に使うことがあり、1組織だけでは全体の傾向がつかめない。共有すれば、他の組織が早く気づいて備えられ、被害の拡大を防げる。自分から出すことで相互の信頼も育つ。

    思い浮かんだ要素にチェック

  2. ISACへ共有する前にやるべきことと、受け取った側が持つべき姿勢を、頭の中で説明してみよう。

    答えを開く

    共有前に個人・顧客・自社固有の情報を取り除き、TLPなどで共有範囲を決めて、受け手にも守ってもらう。受け取った側は、情報が古い・誤りもありうるので、自組織で確認して使う。

    思い浮かんだ要素にチェック

ISACへの共有として、適切なのは？

答えを開く

個人・顧客の情報を除き、攻撃の特徴と手口を、共有範囲を指定して共有する

よくある誤答

  • 共有しない … 他組織が同じ手口に気づけない
  • 全部そのまま共有 … 個人・顧客情報が含まれる
