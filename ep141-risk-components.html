#41 ・ 第4章 情報セキュリティマネジメントの実践

リスクの構成要素と損失 資産・脅威・脆弱性とアセスメント

  1. リスクの構成要素は、情報資産・脅威・脆弱性。3つが重なると事故につながりうる。
  2. 損失は直接損失と間接損失。リスクの大きさは、影響と可能性で見積もる。
  3. アセスメントは特定→分析→評価。見積もりは不確実で、前提を明示する。残留リスクもある。

用語カード

用語を見て意味を言えるか試し、タップで裏返します。「覚えた」を続けるほど定着度が上がり、「まだ」で最初に戻ります。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題リスクを構成する要素の組合せとして、適切なのは？

    1. 対策は手段、損失・事故は結果

    2. 監査・費用・期間は要素外

    3. 利用者・権限・場所は要素外

    4. 資産・脅威・脆弱性

  2. DBサーバのOSの修正プログラムを適用し、公開済みの弱点を解消した。リスクの構成要素と、この対策の効果の説明として適切なのはどれか。

    1. 正解。修正プログラムの未適用は脆弱性の例。構成要素のどれかを減らせば、リスクは下がる。

    2. 不正アクセスの試行は外部の行為（脅威）で、修正の適用では減らない。

    3. 資産は守る対象。修正で資産の価値が変わるわけではない。

    4. 弱点を減らしているので、構成要素の脆弱性が変わる。どれかを下げればリスクは下がる。

  3. 顧客情報の漏えい事故に備えた損失の見積もりで、間接損失にあたるものはどれか。

    1. 賠償や復旧の費用は直接損失。

    2. 正解。信用の低下、取引の減少、機会損失が間接損失にあたる。

    3. 業務の停止による損失は直接損失に含まれる。

    4. 損失の種類ではなく、リスクの大きさ（影響と可能性）の見積もり値。

  4. リスク分析で担当者が損害額と年間の発生回数を見積もり、「これは確定値なので前提の説明は不要」と報告した。評価として適切なのはどれか。

    1. 定量的でも定性的でも、見積もりには誤差がある。

    2. 定性的な見積もりにも誤差がある。どちらが確実という話ではない。

    3. 正解。見積もりは不確実なので、前提を明示して使う。

    4. 不確実さは前提の明示で扱う。見積もりをやめて経験だけで決めるのは適切でない。

  5. 資産・脅威・脆弱性を洗い出した結果をもとに、影響と可能性からリスクの大きさを見積もった。この作業と、次に行う作業の組合せとして適切なのはどれか。

    1. 正解。大きさの見積もりがリスク分析で、次は基準と比べるリスク評価。

    2. 洗い出しがリスク特定。見積もりはすでに終わっていて、基準と比べるのは評価の役目。

    3. 評価は基準との比較。洗い出しは先に行うので、順序が逆。

    4. リスク対応は、評価の結果をもとに決める。見積もりはその前に行う。

  6. リスク評価で基準を超えたため対策を実施し、再び見積もると値が基準を下回った。報告として適切なのはどれか。

    1. 基準を下回ってもリスクがゼロになるわけではない。残るリスクがある。

    2. 正解。見積もりは定性的・定量的いずれも誤差があり、残留リスクがある。前提を明示する。

    3. 損失の分け方と、残るリスクの有無は関係しない。

    4. 定量的でも見積もりに誤差があるので、値が一致するとは言えない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 資産・脅威・脆弱性の3つの関係と、リスクを下げる考え方を、頭の中で説明してみよう。

    答えを開く

    資産は守る対象、脅威は害を及ぼす原因や行為、脆弱性は資産や対策の弱点。3つが重なると事故につながりうる。どれかを下げればリスクは下がる。たとえば脆弱性は、修正プログラムの適用で減らせる。

    思い浮かんだ要素にチェック

  2. リスクの大きさをどう見積もり、その結果を使うときに何を注意すべきか。頭の中で説明してみよう。

    答えを開く

    損害の大きさ（影響）と発生のしやすさ（可能性）から見積もる。定性的・定量的いずれも見積もりには誤差があるので、前提を明示して使う。対応後にも残留リスクがある。

午後問題にチャレンジ

動画の午後問題です。ログを読んで、答えを頭の中で決めてから開いてください。

顧客情報DBサーバの調査記録（ダミー）
対象: 顧客情報を保管するDBサーバ（ダミー）。業務上、社外拠点からの接続を許可（接続元は限定済み）
保管している顧客情報は、漏えいすると損害が大きい（資産としての価値は高い）
このDBサーバのOSには、修正プログラムが未適用で、公開済みの弱点が残っている
許可外の外部IPアドレスから、DBサーバへの接続の試行が、毎日記録（遮断済み）
漏えいした場合は、賠償と復旧の費用に加え、信用低下による取引の減少が見込まれる

ログの中で、「脆弱性」にあたるものは？

答えを開く

OSの修正プログラムが未適用で、公開済みの弱点が残っていること

よくある誤答

  • 外部からの接続の試行 … 外部の行為であり、システムの弱点ではない（脅威）
  • 信用低下による取引の減少 … 事故のあとに生じる結果（間接損失）
