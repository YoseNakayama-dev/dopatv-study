#39 ・ 第3章 情報セキュリティにおける脆弱性

HTTPの仕様とWebサーバの設定不備 仕様側と設定側の弱点

  1. HTTP自体は平文で盗聴・改ざんされうる。対策はHTTPSとHSTSで、Basic認証もHTTPS前提で使う。
  2. 要求の値（ヘッダ・パラメータ）は送る側が自由に変えられるので、信用せずサーバ側で検証する。
  3. 設定不備（一覧表示・公開領域の置き忘れ等）はHTTPSでは防げない。無効化・更新・定期点検で守る。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題Webサーバの設定不備への対策として、適切なのは？

    1. 公開領域の中身が見えてしまう

    2. 初期設定は、広く知られている

    3. 不要機能の無効化と汎用エラー

    4. 公開済みの弱点が残る

  2. HTTPで公開したサイトでBasic認証を使っている。通信路で取得した要求には、符号化された利用者名とパスワードが含まれていた。評価として適切なのはどれか。

    1. 正解。Base64は符号化で暗号化ではない。元に戻せるので、HTTPS上で使うことが前提になる。

    2. 符号化は暗号化ではない。元に戻せてしまう。

    3. 要求の値は送る側が自由に変えられるので、むしろサーバ側で検証する。

    4. 盗聴への対策はHTTPS/TLS。バージョンの非表示は補助にとどまる。

  3. サーバが要求ヘッダとクエリの値を、そのまま正しい値として処理に使っている。送る側が値を変えられることを前提にした、適切な扱いはどれか。

    1. ヘッダの値も、送る側が自由に変えられる。

    2. HTTPSは経路を守るもので、送る本人による値の変更は防がない。

    3. ヘッダもパラメータも同じく、送る側が変えられる。

    4. 正解。受け取った値は信用せず、サーバ側で検証する。

  4. 調査記録によると、公開ディレクトリへの通常のパスへの要求で、ファイル一覧が表示され、バックアップファイルが認証なしで取得された。通信は常にHTTPSだった。最も適切な対策はどれか。

    1. 通信はすでにHTTPS。HTTPSは経路を守るが、サーバの設定不備は防がない。

    2. 正解。一覧の表示と公開領域のバックアップが原因なので、設定側で直す。

    3. バージョン情報の非表示は補助で、一覧表示やバックアップの置き忘れは直らない。

    4. エラーの汎用化は別の弱点への対策で、今回の事象の原因ではない。

  5. Webサーバの定期点検で、サンプル機能、初期設定のままのアカウント、詳細なエラー表示、古い版のソフトが見つかった。対応として適切なのはどれか。

    1. バージョンの非表示は補助にとどまる。古い版の弱点はソフトの更新で解消する。

    2. HTTPSは経路を守るが、サーバの設定不備は防がない。

    3. 正解。不要機能の無効化、エラーの汎用化、更新を行い、設定は定期的に点検する。

    4. 設定は定期的に点検する。構築時の一度きりでは足りない。

  6. HTTPSとHSTSを導入した直後に、「Webサーバの弱点への対策は完了」と報告された。評価として適切なのはどれか。

    1. 正解。HTTPSは経路を守るが、サーバの設定不備は防がない。両方を別々に守る。

    2. 一覧表示やバックアップの置き忘れは設定の不備で、HTTPSでは防げない。

    3. 要求の値は送る側が変えられるので、HSTSがあってもサーバ側で検証する。

    4. Basic認証はHTTPSを前提に使うものとされており、使えなくなるわけではない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. Basic認証をHTTPのまま使うと何が問題か。Base64の性質に触れて、頭の中で説明してみよう。

    答えを開く

    Basic認証は利用者名とパスワードをBase64で符号化して送るだけで、暗号化ではなく元に戻せる。HTTPは平文なので通信路で読まれうる。HTTPSの上で使うことが前提で、HSTSで常にHTTPSを使わせる。

    思い浮かんだ要素にチェック

  2. 「HTTPSにしたからWebサーバの設定は安全」という説明の誤りを、頭の中で指摘してみよう。

    答えを開く

    HTTPSは通信経路を守るが、サーバの設定不備は防がない。一覧表示や公開領域のバックアップ、不要な機能、詳細なエラー表示、古い版のソフトは別に対策が要る。無効化・更新・定期点検で守る。

Webサーバの調査記録（ダミー）
対象: 企業のWebサーバ（ダミー）。外部から、公開用ディレクトリへの要求が多数あった
要求は、公開ディレクトリ内の通常のパスで、上位ディレクトリを示す指定は含まない
応答には、ディレクトリ内のファイル一覧が含まれ、バックアップファイルが取得されていた
この公開ディレクトリは、一覧の表示設定が有効で、認証なしで取得できた
// 通信は常にHTTPSで暗号化 / 取得は外部からサーバへの直接の要求

この事象の原因として、適切なのは？

答えを開く

ディレクトリ一覧の表示が有効で、公開領域にバックアップを置いた設定の不備

よくある誤答

  • ディレクトリトラバーサル … 要求は通常のパスで、上位指定を含まない
  • 通信の盗聴 … 通信はHTTPSで暗号化され、直接の要求だった
