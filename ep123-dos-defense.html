#23 ・ 第2章 情報セキュリティにおける脅威

DoS攻撃への総合的な対策 型に合わせた守備範囲と限界

  1. DoS対策は型ごとに違う。帯域は上流での吸収やCDN、接続はSYNクッキー等、アプリはWAFやレート制限とキャッシュ。
  2. どの対策にも限界がある。攻撃規模が上回れば自社では防げず、厳しすぎる設定は正規の通信も落とす。
  3. 脆弱性型はパッチ適用が基本だが未公開の弱点には間に合わない。平常時の把握と連絡手順の整備も要る。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題帯域を埋める大量通信への備えとして、適切なのは？

    1. 入力値の検査は、インジェクションの対策

    2. CDNや上流での遮断

    3. パスワードは、認証の強化

    4. 試行回数の制限は、ログイン攻撃の対策

  2. SYNフラッド対策として接続数の上限を極端に低くし、タイムアウトも大幅に短縮した。その後、正規の利用者の接続が切れるという苦情が出た。評価として最も適切なものはどれか。

    1. 厳しすぎる設定は正規の接続も落とす。サービスの継続を損なうので、維持すべきではない。

    2. SYNクッキーは状態を保持しないで済ませる工夫。説明が逆である。

    3. 正解。接続型の対策には、厳しすぎる設定が正規接続を落とすという限界がある。

    4. WAFはHTTP要求を扱う対策で、接続の確立段階の設定とは別の話。

  3. 帯域型のDDoSに備えて、自社の回線と設備に余裕を持たせた。それでも十分とは言えない場合がある。その理由として最も適切なものはどれか。

    1. 正解。自社の回線と設備には限りがあり、攻撃規模が上回ると防げない。上流での吸収・遮断が要る。

    2. 余裕を持たせても使用率は把握できる。平常時の把握はむしろ必要な運用である。

    3. CDNは拠点を分散して負荷を受け止める。1拠点に集中するという説明は逆である。

    4. 回線の増強は帯域型に効果がありうる。アプリ型にしか効かないと決めつけるのは言い過ぎ。

  4. 脆弱性型のDoSへの対策として、パッチ適用を徹底している。それでも残るリスクとして最も適切なものはどれか。

    1. パッチは公開された弱点への対処。未公開の弱点には間に合わないため、残るリスクはある。

    2. 帯域型の主な備えは上流での吸収・遮断やCDN。パッチは脆弱性型への対策である。

    3. 入力値検査は有効だが、新しい弱点を必ず防げるとは言えない。断定が過ぎる。

    4. 正解。パッチは公開された弱点への対処で、未公開の弱点には間に合わない。異常時も停止しない設計で補う。

  5. DDoSを受けた際、平常時の通信量を把握しておらず、異常かどうかの判断と上流への連絡に時間がかかった。事前の備えとして最も適切なものはどれか。

    1. WAFがあっても、平常時の把握は異常の判断に必要。不要にはならない。

    2. 連絡手順は事前に決めておく。攻撃を受けてからでは対応が遅れる。

    3. 正解。平常時の把握（ベースライン）、ISP・委託先との連絡手順、縮退・切替の訓練が共通の運用になる。

    4. 増強だけでは攻撃規模が上回る場合に防げない。連絡手順や訓練も要る。

  6. アプリ型のDoS対策として、WAFを導入した。評価として最も適切なものはどれか。

    1. 正解。WAFはアプリ型への対策の一つだが、正規に見える要求とは区別しにくいという限界がある。

    2. 帯域型や接続型は別の資源を狙う攻撃で、別の対策が要る。WAFで同時には防げない。

    3. 完全に防げるとは言えず、レート制限やキャッシュなどとの組合せが要る。

    4. 区別しにくい場合があっても、WAFが無意味とは言えない。限界を踏まえて他の対策と併用する。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 回線を増強したのに、帯域型のDDoSで再びサービスが止まった。自社だけでは防げない理由と、次に取る手を、頭の中で説明してみよう。

    答えを開く

    攻撃規模が自社の回線と設備の余裕を上回れば、自社だけでは防げない。上流のISPやDDoS対策サービスでの吸収・遮断を使い、CDNで拠点を分散する。平常時からISPなどとの連絡手順を決めておく。

    思い浮かんだ要素にチェック

  2. DoSの型ごとの対策には、それぞれ限界がある。接続型とアプリ型について、限界を頭の中で説明してみよう。

    答えを開く

    接続型は、接続数の上限やタイムアウトを厳しくしすぎると、正規の接続も落としてしまう。アプリ型は、WAFやレート制限を使っても、正規に見える要求とは区別しにくい。
