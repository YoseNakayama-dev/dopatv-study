#96 ・ 第1章 情報セキュリティ及びITの基礎

情報セキュリティの特性 機密性・完全性・可用性と付加的な特性

  1. 機密性・完全性・可用性の三つで、漏えい・改ざん・停止のどれが崩れたかを言い分ける。
  2. 付加的な特性は、真正性・責任追跡性・否認防止・信頼性の四つ。責任追跡性と否認防止は別物。
  3. 対策は抑止・予防・検知・回復で整理する（教材により分類は異なる）。限界があるので多層防御などで組み合わせる。
用語 10クイズ 6考える 2午後本

用語カード

クイズ

  1. 動画で出た問題付加的な特性の説明として、適切なものは？

    1. 改ざんされていないのは完全性

    2. 許可された者だけが見られるのは機密性

    3. 必要なときに使えるのは可用性

    4. 意図した動作と結果が一貫するのが信頼性

  2. 次の三つの事象で崩れた特性の組合せとして適切なものはどれか。（1）共有フォルダの誤設定で、権限のない他部署が顧客名簿を閲覧できた。（2）承認済みの見積書の金額が無断で書き換えられていた。（3）注文サイトが2時間停止し、注文を受け付けられなかった。

    1. 正解。権限のない閲覧は機密性、無断の書換えは完全性、サービスの停止は可用性が崩れた事象にあたる。

    2. 書換えで見積書が使えなくなったかではなく、内容が不正に変えられた点が問題。これは完全性の崩れで、サイトの停止のほうが可用性にあたる。

    3. 閲覧されただけで名簿の内容は変わっていない。許可されていない者に開示された点が問題で、機密性にあたる。

    4. 他部署が使えたことは、使える人が増えたという開示の問題。可用性は、認可された主体が必要なときに使えることを指す。

  3. 取引先に電子発注システムを提供している。後日、取引先から「その発注は出していない」と主張される事態に備えたい。なりすましの形跡はなく、操作ログも残っている。この懸念に最も直接対応する特性と手段の組合せはどれか。

    1. 責任追跡性は誰の操作かを追える特性で、行為を後から否認されないようにする否認防止とは別。懸念への直接の備えは否認防止になる。

    2. 正解。懸念は、行為が後から否認されること。電子署名などで発注の事実を支えるのが否認防止にあたる。

    3. 前提にあるのは、なりすましの形跡がないこと。本人確認を強めても、後からの否認という懸念には直接対応しない。

    4. 信頼性は動作と結果の一貫性の話。発注の事実を否認される懸念とは、観点が異なる。

  4. ある組織の対策は、FWとアクセス制御による侵入の予防が中心で、不正アクセスの兆候の監視も、被害を受けた後の復旧手順もない。外部の評価でその点を指摘された。対応方針として最も適切なものはどれか。

    1. どの対策にも限界があり、予防だけでは破られた事態に対応できない。予防だけでなく、検知と回復も欠かせない。

    2. 抑止は一つの機能だが、それだけでは兆候に気づく手段も復旧する手順も整わない。指摘された欠けを埋めていない。

    3. 正解。抑止・予防・検知・回復を組み合わせ、予防が破られた場合も想定する。

    4. 検知できても、被害を受けた後に元へ戻す手順がなければ、業務は止まったままになる。回復は検知で代えられない。

  5. 経理担当者Aは、支払の起票、承認の入力、振込の実行までを一人で行える。誤りも不正も、Aだけでは気づかれにくい。改善策として最も適切なものはどれか。

    1. 正解。職務分離は、一人で完結させない設計。不正も誤りも防ぎやすくなる。

    2. Aの業務に起票から振込までが必要なら、権限を絞っても一人で完結できる状態は残る。最小権限と職務分離は目的が異なる。

    3. 追跡できることは事後の説明に役立つが、不正を事前に防ぐ保証にはならない。一人完結の構造は残る。

    4. 外部からの侵入を防ぐ層を足しても、内部の担当者が一人で完結できる構造は変わらない。

  6. 設計レビューで「境界のFWとWAFを二重に置いたので、侵害は防げる。ほかの対策は不要」と説明された。指摘として最も適切なものはどれか。

    1. 層を重ねても、どの層にも限界は残る。限界がなくなるとは言えない。

    2. 正解。多層防御は、どの層にも限界があると考え、一つ破られても次の層で止める考え方。検知や最小権限などを組み合わせる。

    3. 統合すれば層が減る。多層防御の考え方に反するうえ、安全性が高まるとは言えない。

    4. 職務分離は一人で完結させない設計で、外部からの侵害を防ぐ手段ではない。境界の対策の代わりにならない。

頭の中で考える

  1. 責任追跡性と否認防止の違いを、「共有ID」と「電子署名」を例に頭の中で説明してみよう。

    答えを開く

    責任追跡性は、主体の行動をその主体まで一意に追えること。共有IDだと誰の操作か追えず、損なわれる。否認防止は、行為の発生を後から否認されないこと。電子署名などで支える。追跡できても否認されうるし、署名があっても共有IDなら誰かは特定できないため、別の特性として扱う。

    思い浮かんだ要素にチェック

  2. 「対策は予防だけでは足りない」と言える理由を、多層防御の考え方を使って頭の中で説明してみよう。

    答えを開く

    どの対策にも限界があり、予防が破られる場合を想定する必要がある。そこで抑止・予防・検知・回復を組み合わせ、一つ破られても次の層で止める多層防御にする。最小権限で被害を小さくし、検知で気づき、回復で元に戻す。

    思い浮かんだ要素にチェック

午後問題にチャレンジ

在庫管理の更新調査記録（ダミー）
在庫管理の画面を、担当者全員が共有IDで使う
不審な更新があるが、在庫数は検証で正しかった
更新の間も、システムは止まらず利用できた
更新の事実と日時は、操作ログで確認できる
共有IDは正規に発行され、不正使用の形跡はない
要件: 疑いのある更新を、利用者ごとに説明したい

この記録で、特に欠けている特性は？

答えを開く

責任追跡性。操作者を一意に特定できない

よくある誤答

  • 完全性が損なわれている … 更新後の在庫数は、検証で正しいと確認されている
  • 可用性が損なわれている … 更新の間も、システムは止まらず利用できた
  • 否認防止・真正性が欠けている … 更新の事実はログで示せ、なりすましの形跡もない
