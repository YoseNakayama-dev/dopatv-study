#80 ・ 第7章 情報セキュリティ対策技術（3）暗号

PKIとデジタル証明書 署名をたどって信頼する

  1. PKIは、CAが公開鍵と持ち主を結び付け、CAの秘密鍵で署名した証明書（X.509）で持ち主を確かめる仕組み。
  2. 検証は、登録済みCAの公開鍵で署名を確かめ、有効期間と接続先の名前の一致、失効も確認する。
  3. 穴は署名の未検証、怪しいCAの登録、期限切れ・失効の見落とし、秘密鍵の流出。登録CAを絞り期限を管理する。

  1. 動画で出た問題デジタル証明書の説明として、適切なのは？

    1. 結び付けるのは公開鍵。秘密鍵は持ち主だけが保管

    2. 証明書にパスワードは載らない

    3. 公開鍵と持ち主を結び付け、CAが署名

    4. 載るのは公開鍵。共通鍵は配らない

  2. 取引先サイトの証明書は、CAの署名の検証に成功した。ただし有効期間が切れているとの警告が出ており、業務を急いでいる。適切な判断はどれか。

    1. 期限切れや失効の見落としは危険で、警告を無視して進むのも同じく危険。

    2. 検証ではCAの署名に加えて、有効期間と接続先の名前の一致も確認する。署名が正しくても期限切れは見落とせない。

    3. 有効期間も検証の確認項目で、失効の確認だけでは足りない。署名・有効期間・名前の一致をそろえて確認する。

    4. 正解。署名・有効期間・名前の一致を確認する。期限切れは見落とすと危ない項目。

  3. 取引先から、端末の信頼するCAとして、自社のCAの証明書を登録するよう依頼された。適切な対応はどれか。

    1. 正解。登録したCAが信頼の起点になる。登録するCAは、必要なものに限る。

    2. 登録したCAが検証の起点になるので、怪しいCAを登録すると偽の証明書も信じる。多めの登録は避ける。

    3. 登録したCAが検証の起点なので、怪しいCAを登録すると偽の証明書も信じる。署名の検証では見分けられない。

    4. 有効期間の管理は別の対策。登録したCAが信頼の起点になるので、登録するCAの数と中身は信頼に直結する。

  4. サーバの秘密鍵が、紛失したバックアップ媒体から漏れたおそれがある。証明書の有効期間は残っている。適切な対応はどれか。

    1. 秘密鍵が漏れると本人になりすまされる。期限まで待たず、漏れたら失効させる。

    2. 正解。秘密鍵が漏れたら失効させる。証明書は失効させるまで有効に見える。

    3. 秘密鍵が流出すると本人になりすまされる。公開鍵が同じでも防げない。

    4. 流出した秘密鍵は本人になりすませる状態を作る。必要な対応は失効で、署名の作り直しではない。

  5. 接続先として pay.example を入力した。提示された証明書は、所有者が shop.example、発行者は登録済みのCA-Xで、有効期間内、CAの署名の検証にも成功した。評価として適切なものはどれか。

    1. 署名の検証に成功しても、証明書の所有者はshop.exampleで、入力したpay.exampleと違う。接続先の名前の一致は、署名の検証とは別に確認する。

    2. 有効期間は確認項目の一つで、名前の一致は別に確認する。名前が違えば同一サイトとはいえない。

    3. 登録CAは信頼の起点だが、署名・有効期間・名前の一致はそれぞれ確認する。名前の確認は省けない。

    4. 正解。接続先の名前の一致も検証の項目。一致しないので、本人のサーバとは確認できない。

  6. 取引先から、自社の公開鍵と所有者名を書いたテキストがメールで届いた。受け取った側の判断として適切なものはどれか。

    1. 所有者名は、作った人が自由に書ける。書いてあるだけでは持ち主と確定できない。

    2. 公開鍵は公開してよいが、公開鍵だけでは持ち主は分からない。結び付きの確認は省略できない。

    3. 正解。CAが公開鍵と持ち主を結び付け、署名して証明書を発行する。登録済みCAの公開鍵で署名を検証して確かめる。

    4. 有効期間は証明書の項目の一つ。公開鍵と持ち主を結び付けるのは、CAの署名。

頭の中で考える

  1. 端末に怪しいCAが登録されていたら何が起きるか。対策も含めて頭の中で説明してみよう。

    答えを開く

    登録したCAが信頼の起点になるので、そのCAが発行した偽の証明書も信じてしまう。登録するCAは必要なものに限り、署名・有効期間・名前の一致を確認する。

  2. CAの署名の検証に成功した証明書でも、使い続けてはいけない場合を挙げ、それぞれ何を確認するか頭の中で説明してみよう。

    答えを開く

    有効期間が切れている場合は有効期間、接続先の名前と一致しない場合は名前の一致、失効している場合や秘密鍵が漏れた場合は失効を確認する。署名の検証だけでは足りない。

午後問題にチャレンジ

取引先サイトの本人確認に関する調査記録（ダミー）
現状: 利用者が、取引先のサイトにHTTPSで接続する
ブラウザには、信頼するCAの証明書が登録されている
取引先のサーバは、証明書を提示してくる
要件: 接続先が、取引先本人のサーバだと確認したい

要件を満たす確認方法として、適切なのは？

答えを開く

登録済みCAの公開鍵で署名を検証し、名前が接続先と一致することも確認する

よくある誤答

  • 証明書が提示されたことを、確認とみなす … 誰でも証明書を作れるため、署名の検証なしでは本人と分からない
  • 所有者名が取引先名と同じなら、署名の検証は省く … 署名を検証しなければ、所有者名は誰でも自由に書ける

  • 7.7.2 デジタル証明書
