#74 ・ 第7章 情報セキュリティ対策技術（3）暗号

暗号の概念と主な暗号方式 鍵の使い分けと渡し方

  1. 共通鍵暗号は高速だが鍵配送が課題。公開鍵暗号は低速だが、鍵の数はn組で済む。
  2. ハイブリッド暗号は、データを共通鍵で、その共通鍵を公開鍵で送る。公開鍵は証明書で本物か確認する。
  3. 鍵が漏れれば方式が強くても読まれる。推奨方式を十分な鍵長で使い、鍵の一生を管理する。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題公開鍵暗号方式の説明として、適切なのは？

    1. 別の鍵を使い、公開鍵は公開してよい

    2. 同じ鍵を使うのは共通鍵暗号

    3. 一般に共通鍵のほうが高速

    4. 秘密にするのは秘密鍵

  2. 社員10人の全員が互いに通信する。通信相手の組ごとに別の共通鍵を使う場合の鍵の本数と、公開鍵暗号を使う場合の鍵の組数の組合せはどれか。

    1. 公開鍵の10組は合っているが、共通鍵は n(n-1)/2 に n=10 を入れて 10×9÷2=45本になる。20本ではない。

    2. 正解。共通鍵は10×9÷2=45本、公開鍵暗号は人数と同じ10組で済む。

    3. 10×9=90を2で割っていないので誤り。共通鍵は45本。また公開鍵暗号の鍵はn組なので10組で、45組ではない。

    4. 共通鍵の45本は合っているが、公開鍵暗号の鍵はn組、つまり10組で済む。

  3. 共通鍵暗号で、推奨方式のAESを十分な鍵長で使っている。ただし鍵ファイルを、利用者全員が閲覧できる共有フォルダに置いていた。このシステムの評価はどれか。

    1. 鍵が漏れると、方式が強くても暗号文は読まれる。暗号の強さは鍵の秘密に支えられている。

    2. 処理の速さと、鍵が漏れたときの被害の大きさは関係がない。鍵が漏れれば読まれる。

    3. 正解。鍵の漏えいは方式の強さと無関係に致命的になる。鍵の生成・保管・更新・廃棄の手順を決めて管理する。

    4. 方式を替えても、鍵が漏れると読まれる点は変わらない。鍵の保管は管理の対象であり続ける。

  4. 社内システムが、古い方式（DES）の共通鍵暗号を、短い鍵長で使っている。見直しの方針として最も適切なものはどれか。

    1. DESや短い鍵は、方式や鍵長そのものが解読されるおそれのある対象。更新の頻度では解消しない。

    2. 独自の暗号方式は作らないのが原則。DESや短い鍵への対策は、推奨された方式を十分な鍵長で使うこと。

    3. 公開鍵暗号は共通鍵より低速で、大容量のデータ全体の暗号化には遅い。

    4. 正解。推奨された方式を十分な鍵長で使うのが、古い方式への対策。

  5. 取引先の公開鍵で共通鍵を暗号化して送る設計。通信路上の攻撃者が、自分の公開鍵を取引先のものとして渡してきた。起こりうることと対策の組合せはどれか。

    1. 公開鍵そのものは配ってよいが、偽の公開鍵を渡されると盗聴されうる。本物かは別に確かめる必要がある。

    2. 正解。偽の公開鍵を渡されると盗聴されうるため、公開鍵は証明書で本物かを確認する。

    3. 秘密鍵が漏れていなくても、偽の公開鍵を使わされると盗聴されうる。

    4. ハイブリッド暗号でも共通鍵は公開鍵で送る。その公開鍵が偽物なら盗聴されうるので、確認は必要。

  6. 共通鍵暗号で通信を始めたいが、共通鍵を相手へ安全に渡す方法がない。鍵配送問題への対処として最も適切なものはどれか。

    1. 鍵が漏れると、方式が強くても読まれる。鍵長を伸ばしても、渡す経路での漏えいは防げない。

    2. 鍵が渡る経路が安全でなければ、鍵そのものが漏れうる。安全に渡す方法が課題という点が解消していない。

    3. 正解。共通鍵を公開鍵暗号で安全に渡すのがハイブリッド暗号の形。データは速い共通鍵で暗号化する。

    4. 公開鍵暗号は共通鍵暗号より低速。高速なのは共通鍵暗号のほう。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. ハイブリッド暗号で、データと共通鍵にそれぞれどの方式を使うか、その理由とあわせて頭の中で説明してみよう。

    答えを開く

    データは高速な共通鍵暗号で暗号化し、その共通鍵を相手の公開鍵で暗号化して送る。公開鍵暗号は低速で大容量には不向きだが、鍵の配送には向く。両者の長所を組み合わせる。

    思い浮かんだ要素にチェック

  2. 公開鍵暗号を使っていても盗聴されうるのはどんな場合か。原因と対策を頭の中で説明してみよう。

    答えを開く

    偽の公開鍵を渡されて、それで暗号化してしまう場合。偽の公開鍵を渡されると盗聴されうる。対策は、公開鍵を証明書で本物か確認すること。

午後問題にチャレンジ

動画の午後問題です。ログを読んで、答えを頭の中で決めてから開いてください。

拠点間通信の暗号化に関する調査記録（ダミー）
現状: 本社と拠点が、インターネットで大容量の設計図を送る
拠点間で、鍵を安全に事前配布する手段はない
相手の公開鍵は、証明書で本物と確認して入手できる
要件: 大容量でも実用的な速度で、盗聴されても読まれない

要件を満たす方式として、適切なのは？

答えを開く

データは共通鍵で暗号化し、その共通鍵を相手の公開鍵で暗号化して送る

よくある誤答

  • データ全体を、受信者の公開鍵で暗号化する … 大容量では処理が遅く、実用的な速度にならない
  • 共通鍵を事前に全拠点へ配って暗号化する … 鍵を安全に事前配布する手段がない
