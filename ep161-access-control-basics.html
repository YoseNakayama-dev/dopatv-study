#61 ・ 第6章 情報セキュリティ対策技術（2）アクセス制御と認証

アクセス制御の概要 必要な人に必要な範囲だけ

  1. アクセス制御は、主体が客体に行える操作を制限する。流れは識別、認証、認可の順。
  2. 方式は、所有者が設定する任意、管理者の方針で一律の強制、役割に権限を与えるロールベース。
  3. 最小権限で与え、職務を分離し、異動や退職で不要になった権限は定期的に見直す。

クイズ

  1. 動画で出た問題最小権限の原則の説明として、適切なのは？

    1. 常時の管理者権限は必要な範囲を超える

    2. 不要になった権限を残すと積み上がる

    3. 必要な範囲に限って付与

    4. 見直さず維持すると不要な権限が残る

  2. 文書の所有者が共有範囲を自分で変更できないようにし、管理者の方針で一律に制御したい。適した方式はどれか。

    1. 正解。資源と利用者に区分を付け、管理者の方針で一律に制御する。所有者でも変更できない。

    2. 任意アクセス制御は所有者が権限を設定する方式で、所有者が共有範囲を変えられない条件に合わない。

    3. ロールベースは役割単位で権限を与える方式で、区分を付けて一律に制御する方式ではない。

    4. 職務分離は基本の考え方のひとつで、アクセス制御の方式ではない。

  3. 定期的な確認で、異動した利用者に前の部署の権限が残っていることが見つかった。再発を防ぐ運用として適切なものはどれか。

    1. 付与を止めると、業務に必要な権限まで与えられなくなる。しかも、すでに付いた不要な権限は外れない。必要なのは不要になった権限の見直し。

    2. 利用者の申告に頼ると、気づかない権限や申告されない権限が残る。異動や退職で不要になった権限は、管理側が定期的に確認して外す。

    3. ロールベースは役割の付け替えで異動に対応しやすいが、不要な権限の定期的な見直しは基本の考え方として残る。

    4. 正解。異動や退職で不要になった権限を定期的に見直し、権限が積み上がる権限クリープを防ぐ。

  4. 経理システムで、同じ担当者が支払いの申請・承認・実行をすべて行える。職務分離の観点で適切な見直しはどれか。

    1. 見直しだけでは、重要な作業が一人に集中した状態は変わらない。職務分離は別の考え方。

    2. 正解。職務分離は、重要な作業を一人に集中させないこと。

    3. 一人で申請から実行まで完結できると、誤りや不正を他の人が確認する機会がなくなる。責任の所在とは別に、重要な作業は一人に集中させない。

    4. 知る必要性は、必要な人にだけ必要な情報を見せる考え方。作業を一人に集中させない職務分離とは別。

  5. 部署ごとに文書の所有者が共有範囲を設定した結果、同種の文書でも公開範囲にばらつきが出た。説明と対応として適切なものはどれか。

    1. 正解。任意アクセス制御は柔軟だが、設定が利用者任せになりばらつきやすい。方式は情報の重要度と運用の負担で選ぶ。

    2. 強制アクセス制御は厳格だが、区分付けの負担が大きい。

    3. ばらつきの原因は、所有者が個別に設定する任意アクセス制御の性質にある。注意喚起だけでは設定の統一は保証できず、必ず解消できるとは言えない。

    4. ロールベースの異動時の対応は、役割の付け替えで行う。不要にはならない。

  6. ある利用者がIDを提示し、パスワードで本人確認が済んだあと、ファイルへの書き込みを要求した。システムが次に行う処理はどれか。

    1. 識別はIDを示す段階で、すでに済んでいる。次は認可。

    2. 認証は本人かを確かめること、認可は権限があるかを確認すること。別のものなので代わりにならない。

    3. 流れは識別、認証、認可の順。権限の確認は、要求を許可する前に行う。

    4. 正解。識別、認証のあとは認可。その主体に権限があるかを確認する。

頭の中で考える

  1. 最小権限の原則を守るために、権限を与えるときと与えたあとにやることを、頭の中で説明してみよう。

    答えを開く

    業務に必要な範囲に限って権限を与える。異動や退職で不要になった権限は定期的に見直して外し、権限が積み上がる権限クリープを防ぐ。侵害や誤操作があっても被害を小さくできる。

    思い浮かんだ要素にチェック

  2. 重要度の高い情報に強制アクセス制御を採用するとき、利点と負担を、頭の中で説明してみよう。

    答えを開く

    資源と利用者に区分を付け、管理者の方針で一律に制御するため、所有者でも変更できず厳格。一方、区分付けの負担が大きい。方式は情報の重要度と運用の負担で選ぶ。

午後問題にチャレンジ

権限管理の見直しに関する調査記録（ダミー）
現状: 権限は作成者が利用者・ファイル単位で個別に設定している
人事異動の後も、前の部署の閲覧権限が残っていた利用者がいた
閲覧範囲は部署・職務ごとに異なり、同じ職務の利用者は共通
権限の設定・変更は、情報システム部門が一元的に行える
要件: 付け替えを少ない手間で。全ファイルへの機密区分付与は不可

権限管理の方式として、適切なのは？

答えを開く

役割ごとに権限を定義し、利用者に役割を割り当てる

よくある誤答

  • 全員に同一の権限を与えて、権限の管理を単純にする … 閲覧範囲は、部署・職務ごとに異なる
  • 作成者が、利用者・ファイル単位で個別に設定し続ける … 異動のたびに全ファイルを直す必要があり、少ない手間を満たさない
