ゼロトラストの実現方式 ZTNAとSASEの考え方と限界

  1. ゼロトラストは製品ではなく考え方。利用者・端末・アプリ・通信の部品を組み合わせて実現する。
  2. ZTNAは許可されたアプリにだけ接続させ、状態を見て都度判断する。VPNより侵害時に動ける範囲が狭まる。
  3. SASEはネットワークと安全機能をクラウドで統合する手段の1つ。許可方針の設計は組織の仕事で、段階的に進める。

クイズ

  1. 動画で出た問題SASEの説明として、適切なのは？

    1. 暗号の名称ではない

    2. ネットワークとセキュリティをクラウドで統合

    3. 社内に限らず、拠点や在宅も対象

    4. 脆弱性情報の共有は別の取組み

  2. VPN接続後にネットワーク全体へ届いてしまう構成を改善したい。ZTNAの働きとして最も適切なものはどれか。

    1. 正解。許可されたアプリだけに接続させ、状態を見て都度判断する。侵害されても動ける範囲が狭くなる。

    2. それは従来のVPNの問題点。ZTNAは到達範囲を絞る。

    3. ゼロトラストは利用者や端末の確認を重ねる考え方で、省かない。

    4. ZTNAの特徴は暗号化ではなく、アプリ単位の許可と都度の判断。

  3. SASEを導入した組織が、「ゼロトラストは実現済み」と報告した。評価として最も適切なものはどれか。

    1. SASEはゼロトラストを実現する手段の1つで、同義ではない。

    2. 何を誰に許すかの設計は、自分たちの仕事。製品では代わりにならない。

    3. SASEはネットワーク機能とセキュリティ機能をクラウドで統合する考え方で、VPNの別名ではない。

    4. 正解。入れれば終わりではなく、方針の設計や段階的な移行が要る。

  4. VPN接続後は社内全体に到達でき、私物端末も支給端末も同じ条件で接続できる。ゼロトラストの観点で、足りない点として最も適切なものはどれか。

    1. 問題は速度ではなく、到達範囲と端末の確認。

    2. 製品の導入が目的ではない。製品だけでは足りず、方針の設計が要る。

    3. 正解。端末が管理下にあるか、状態は健全かを確認し、判断に使う。

    4. アプリ単位で許可を出し分けるのは望ましい。不足している点ではない。

  5. 全社員・全システムを一度にSASEへ切り替える計画が出た。評価として最も適切なものはどれか。

    1. 正解。事業者への依存や古いシステムへの対応も見ながら、段階的に進める。

    2. 古いシステムへの対応には時間がかかる。自動で対応するとは言えない。

    3. クラウド事業者への依存があり、障害時の影響も見ておく。

    4. 何を誰に許すかの設計は、組織の仕事として続く。

  6. ZTNAを検討している。ZTNAの評価として最も適切なものはどれか。

    1. VPNが不要になる、とは言い切れない。撤去を前提にするのは言い過ぎ。

    2. 全体に届くのは従来のVPNの特徴。ZTNAは許可されたアプリに絞る。

    3. 利用者と端末の状態を見て判断する。認証だけではない。

    4. 正解。許可されたアプリにだけつなぎ、状態を見て都度判断する。

頭の中で考える

  1. VPNとZTNAで、侵害された端末が動ける範囲がどう違うかを、頭の中で説明してみよう。

    答えを開く

    VPNは接続するとネットワーク全体に届きやすく、侵害された端末から複数のサーバへ到達しうる。ZTNAは許可されたアプリにだけつなぎ、利用者と端末の状態を見て都度判断するので、動ける範囲が狭くなる。

    思い浮かんだ要素にチェック

  2. SASEを導入しても、ゼロトラストが実現できたとは言えない理由を、頭の中で説明してみよう。

    答えを開く

    SASEはゼロトラストを実現する手段の1つで、同義ではない。何を誰に許すかの方針は自分たちで設計する必要がある。事業者への依存や古いシステムへの対応もあり、重要なアプリから段階的に進める。

    思い浮かんだ要素にチェック
