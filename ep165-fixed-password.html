#65 ・ 第6章 情報セキュリティ対策技術（2）アクセス制御と認証

固定式パスワードの特徴 保存の仕方で被害が変わる

  1. 固定式パスワードは導入が容易だが、知っていることだけが根拠なので、知られると破られる。
  2. 弱点は推測・使い回し・盗み見や偽画面・保存側の漏えい。保存はソルト付きハッシュにする。
  3. 失敗回数の制限と異常検知、漏えいの疑いでの変更、多要素認証の併用で補う。

用語を見て意味を言えるか試し、タップで裏返します。「覚えた」を続けるほど定着度が上がり、「まだ」で最初に戻ります。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題利用者のパスワードの扱いとして、適切なのは？

    1. 本人に関連する数字は推測されやすい

    2. 兆候のない定期変更は求めない

    3. 共有では操作者を特定できない

    4. 別々に使い、疑いで変更

  2. 会員ごとに異なるソルトを加えたハッシュで保存する設計の会員データベースを確認したところ、同じパスワードを使っていると分かっている会員どうしの保存値が同一だった。この状態の評価として、適切なものはどれか。

    1. 正解。ソルトは会員ごとの乱数で、同じパスワードでも保存値が異なる。同一なら会員ごとのソルトが使われていない。

    2. 一方向であることと、同じ保存値が並ぶことは別の話。ソルトを会員ごとに変えれば、同じパスワードでも保存値は異なる。

    3. ストレッチングは計算を意図的に遅くする工夫で、保存値を会員ごとに変える働きはない。

    4. 保存値の違いはソルトで作るもので、サービス側の方式で決まる。評価に関係する。

  3. 別のサービスで流出したIDとパスワードの組が、自社サイトのログインに試され、一部が成功した。各アカウントの失敗は1〜2回で、回数制限は作動していない。成功を直接防ぐ対策として、最も適切なものはどれか。

    1. 保存側の漏えい対策で、有効だが、入力された正しい組み合わせの試行は止められない。

    2. 正解。パスワードが知られても、別の分類の要素が無ければ認証されない。使い回しによる波及を補う対策になる。

    3. 少ない試行回数で成功しているので、回数制限は成功そのものを止めない。異常検知とともに補助の対策になる。

    4. 推測への対策。今回は流出した正しい組み合わせの使い回しで、推測の問題ではない。

  4. 従業員が、偽のログイン画面にパスワードを入力してしまったと申告した。対応として、適切なものはどれか。

    1. ソルト付きハッシュは保存側の対策。偽の画面に入力した値は、保存方式と関係なく相手に渡っている。

    2. 回数制限は試行を抑える対策で、すでに入力してしまった値の悪用は防げない。

    3. 正解。漏えいが疑われたら変更する。使い回しがあると別のサービスにも波及するので、同じ値は他でも変える。

    4. 長さは推測への備え。偽の画面に入力して渡った値は、長くても相手に知られている。

  5. ソルト付きハッシュでパスワードを保存するサービスで、ログイン時の照合の手順として、適切なものはどれか。

    1. ハッシュ化は元に戻せない一方向の変換。元のパスワードへ戻して比べる手順はない。

    2. 照合には、保存したときと同じソルトを使う必要がある。毎回作り直すと一致を確かめられない。

    3. 正解。同じソルトを加えて計算し、保存値と一致すれば認証する。

    4. ソルトを加えずに計算すると、保存値の作り方と合わず、一致を確かめられない。

  6. ログイン画面で、特定の1つのIDに対して短時間に失敗が続いている。サービス側の対応として、最も適切なものはどれか。

    1. 利用者側の対策だけでは、目の前で続いている試行に対応できない。サービス側の制限と検知が要る。

    2. 正解。失敗の回数を制限し、異常な試行を検知して対応する。

    3. ストレッチングは保存側の計算を遅くする工夫で、画面からの試行を止める対策ではない。

    4. ソルトは保存側の対策。ログイン画面での試行が続く状況への対応にはならない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. パスワードを平文で保存せず、ソルト付きハッシュで保存する理由と、ログイン時の照合の流れを頭の中で説明してみよう。

    答えを開く

    平文保存だと流出時にそのまま使われる。ハッシュは元に戻せない一方向の変換で、ソルトは会員ごとの乱数なので同じパスワードでも保存値が異なる。ログイン時は保存したソルトを入力に加えて計算し、保存値と一致すれば認証する。

    思い浮かんだ要素にチェック

  2. 固定式パスワードだけでは守りきれない理由と、補う手段を頭の中で整理してみよう。

    答えを開く

    知識のみの認証で、知っていることだけが本人である根拠になるため、一度知られると別の人もそのまま使える。使い回さず長く推測されにくいものにし、失敗回数の制限と異常検知、漏えいの疑いでの変更、多要素認証の併用で補う。

午後問題にチャレンジ

動画の午後問題です。ログを読んで、答えを頭の中で決めてから開いてください。

パスワード保存方式の見直し記録（ダミー）
対象: 会員サイトのパスワード保存方式の見直し（ダミー）
現状: パスワードを、平文のままデータベースに保存している
ログイン時は、入力値が登録済みの値と一致するか確認できればよい
同じパスワードの会員が複数いても、保存値から同一と判別させない
要件: 管理者を含め、元のパスワードを復元できないようにしたい

パスワードの保存方式として、適切なのは？

答えを開く

会員ごとにソルトを加えてハッシュ化し、ソルトとハッシュ値を保存する

よくある誤答

  • 鍵を用いて暗号化して保存する … 鍵があれば元に戻せ、復元できないという要件を満たさない
  • 平文のまま保存し、閲覧できる管理者を絞る … 絞っても、見える管理者には元の値が見える

本で読む

  • 6.3.1 固定式パスワードによる認証方式の特徴

固定式パスワードの弱点を、利用者側の対策とサービス側（保存・試行制限）の対策に分けて読む。ソルトとハッシュの役割を確かめる。
