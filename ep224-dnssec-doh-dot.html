DNSSECとDoH・DoT 真正性と秘匿性の違い

  1. DNSの課題は真正性と秘匿性の二つ。対策は別で、真正性はDNSSEC、端末側の秘匿はDoT・DoH。
  2. DNSSECは署名を検証して偽の応答や改ざんを検知する。暗号化はせず、署名側と検証側の両方が要る。
  3. DoT・DoHは端末とリゾルバの間を保護するが、リゾルバには見える。DoHは監視を回避されうる。

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題DNSの保護の説明として、適切なものは？

    1. DNSSECは暗号化しない

    2. リゾルバには見える

    3. 応答の真正性はDNSSECの役割

    4. 署名の検証で改ざんを検知

  2. 自社ドメインにDNSSECの署名を付けた。だが、社員の端末が使う社内リゾルバは、署名の検証を有効にしていない。この状況の評価として最も適切なものはどれか。

    1. 正解。DNSSECは署名する側と検証する側の両方の対応が要る。検証が無ければ、署名があっても検知は働かない。

    2. 検知するのは検証するリゾルバ。検証が無効なら、署名だけでは偽の応答を見抜けない。

    3. DNSSECは暗号化しない。内容を見えなくするのはDoTやDoHの役割。

    4. DSは親ゾーンが子の鍵を保証して連鎖をつなぐもの。検証するリゾルバがいなければ、その連鎖も使われない。

  3. 署名済みのゾーンで、署名の有効期限が切れたまま放置された。署名の検証を有効にしたリゾルバを使う利用者に起きる現象として、最も適切なものはどれか。

    1. 署名の期限切れや鍵更新の誤りは、検証の失敗として扱われる。署名がない場合と同じにはならず、名前解決が失敗する。

    2. 正解。署名の期限切れや鍵更新の誤りでは、検証に失敗して名前解決ができなくなる。運用ミスが可用性に直結する。

    3. DNSSECはもともと暗号化しない。期限切れで暗号化が外れるわけではない。

    4. DNSSECとDoTは別の仕組みで、対策も別。署名の期限切れで起きるのは署名の検証の失敗であり、DoTの経路が使えなくなるわけではない。

  4. 社内のDNSフィルタで不審なドメインを遮断している。ところが、一部の端末のブラウザが外部のリゾルバへDoHで問い合わせ、フィルタを通らなくなっていた。最も適切な対応はどれか。

    1. 853はDoTの専用ポート。DoHはHTTPSで運ばれ、通常のWeb通信に紛れるので、853の遮断では止まらない。

    2. DNSSECは応答の真正性を検証する仕組み。問い合わせの経路を変えて監視を回避することは防げない。

    3. 正解。DoHはDNSの監視やフィルタを回避されうる。使うリゾルバを方針で決めて管理するのが対応になる。

    4. DoHの効果は端末とリゾルバの間の盗聴・改ざんの防止。組織の監視を回避されうる点は別に残る。

  5. セキュリティ担当は、社内から外部へ出るDNSの暗号化通信を、ポート番号だけを手がかりにして把握したい。最も適切な評価はどれか。

    1. DoHはHTTPSで運ばれ、通常のWeb通信に紛れる。ポート番号だけでは見分けにくい。

    2. 専用のポートを使うのはDoT（853）。DoHは通常のWeb通信に紛れる側。

    3. 暗号化されても、DoTは専用ポート853で識別しやすい。把握できないとは言えない。

    4. 正解。DoTは専用ポートで識別しやすい。DoHは通常のWeb通信に紛れるので、別の管理方法が要る。

  6. 検証するリゾルバが、署名されたゾーンの署名鍵を信頼できる根拠として、最も適切なものはどれか。

    1. ゾーン自身が名乗る鍵だけでは、別の鍵にすり替えられても区別できない。親が保証する連鎖が根拠になる。

    2. 正解。親ゾーンが子の鍵をDSで保証し、それがルートまでつながる信頼の連鎖が、検証の根拠になる。

    3. TLSは通信の保護の仕組み。応答の署名の鍵を保証するのは、親ゾーンのDSの連鎖。

    4. DoHが保護するのは端末とリゾルバの間。署名の鍵の正当性は、DNSSECの信頼の連鎖で確認する。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 公開リゾルバへ暗号化なしで問い合わせている環境で、ドメインはDNSSEC署名済みで検証も有効だった。それでも問い合わせ内容を第三者に見られた。理由と対策を頭の中で説明してみよう。

    答えを開く

    DNSSECは署名で応答の真正性を確かめる仕組みで、通信を暗号化しないため、問い合わせの内容は見える。端末とリゾルバの間をDoTまたはDoHで暗号化するのが対策。ただしリゾルバ自身には内容が見え、応答の真正性はDNSSECが担うので、両者は役割が別である。
