#75 ・ 第7章 情報セキュリティ対策技術（3）暗号

ハッシュ関数とMAC、DH鍵交換 値で確かめ、鍵を作る

  1. ハッシュ値だけでは、改ざん後に値ごと作り直されると見抜けない。鍵を使うMACか署名で検知する。
  2. MACは鍵を共有する当事者の間でしか確認できない。第三者への証明や否認防止には署名を使う。
  3. DH鍵交換には相手の認証がなく中間者に割り込まれうる。署名や証明書で認証し、使い捨ての鍵で交換する。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題ハッシュ関数の説明として、適切なのは？

    1. 暗号化ではなく復号もできない

    2. 少しの変化で値は大きく変わる

    3. 出力は固定長

    4. 固定長で逆算が困難

  2. 配布サイトが、ファイルと同じサーバの同じページに、そのファイルのハッシュ値を載せている。サーバが侵害されてファイルが差し替えられた場合の説明として、適切なものはどれか。

    1. 改ざん後にハッシュ値も作り直されると、見抜けない。一方向性はこの点を防がない。

    2. 正解。ハッシュ値だけでは改ざん後に値ごと作り直されうる。ハッシュ値は改ざんされない経路で確認する。

    3. SHA-2は推奨される方式だが、値ごと作り直されうる点は方式の違いでは防げない。確認は別経路で行う。

    4. ハッシュ関数は逆算が困難で、値から元のファイルは復元できない。

  3. 取引先とのAPI通信で、事前に共有した秘密の鍵を使ってMACを付け、受信側で再計算して照合する運用にした。MACの照合に成功したとき、確認できることはどれか。

    1. 正解。MACは共有鍵とデータから作る確認用の値で、改ざんと、鍵を持つ相手が作ったことを確認できる。

    2. 鍵を共有するMACでは、第三者への証明や否認防止はできない。それにはデジタル署名を使う。

    3. MACは鍵を共有する当事者の間でしか確認できない。鍵を持たない第三者は検証できない。

    4. MACは確認用の値で、暗号化ではない。内容が読まれないようにするのは暗号化の役割。

  4. 二つの拠点がDH鍵交換で共通の鍵を作る構成。通信路上の攻撃者が両者の間に割り込み、それぞれと別々に鍵交換を行った。この構成の評価として適切なものはどれか。

    1. DH鍵交換には相手を確かめる機能がなく、中間者に割り込まれると偽の相手と鍵を共有する。

    2. 一時的な鍵で得られるのは前方秘匿性で、相手の認証にはならない。割り込みの防止には認証が要る。

    3. 正解。DH鍵交換は署名や証明書で相手を認証して使う。

    4. ハッシュ値だけでは、値ごと作り直されると見抜けない。認証には署名や証明書を使う。

  5. DH鍵交換で、通信のたびに使い捨ての（一時的な）鍵を使う設計にした。この設計で得られる利点として、適切なものはどれか。

    1. 正解。通信ごとに鍵を使い捨てにすれば、後から長期の鍵が漏れても過去の通信は守りやすくなる（前方秘匿性）。

    2. DH鍵交換には相手の認証機能がない。相手の確認には署名や証明書を併用する。

    3. 割り込みへの対策は、署名や証明書による相手の認証。使い捨ての鍵では防げない。

    4. 共有鍵は秘密に保ち、定期的に更新する。更新不要になるわけではない。

  6. ファイルの完全性確認にMD5のハッシュ値を使っているシステムがある。見直しの方針として適切なものはどれか。

    1. 値が大きく変わる性質があっても、MD5は衝突が見つかり非推奨。別のデータで同じ値を作れてしまう。

    2. 正解。MD5やSHA-1は衝突が見つかり推奨されない。SHA-2など推奨される方式を選ぶ。

    3. 保存時の暗号化では、別のデータで同じ値が作れてしまう衝突の問題は解消しない。

    4. SHA-1もMD5と同様に衝突が見つかり、推奨されない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 「ハッシュ値を付けて送れば改ざんを検知できる」が不十分な理由と、改善策を頭の中で説明してみよう。

    答えを開く

    データを書き換えた攻撃者が、ハッシュ値も作り直せるため、改ざんも作成者も確認できない。鍵を使うMACか署名で改ざんを検知し、ハッシュ値は改ざんされない経路で確認する。

    思い浮かんだ要素にチェック

  2. DH鍵交換の弱点と、その対策、使い捨ての鍵の効果を頭の中で説明してみよう。

    答えを開く

    DH鍵交換には相手の認証がなく、中間者に割り込まれると偽の相手と鍵を共有する。署名や証明書で相手を認証する。使い捨ての鍵を使えば前方秘匿性が得られ、後から長期の鍵が漏れても過去の通信は守りやすくなる。
