#111 ・ 第4章 情報セキュリティマネジメントの実践

情報セキュリティ監査とシステム監査 独立と証拠で測る

  1. 監査は管理の状況を基準に照らして客観的に評価する。自分の管理は見落としやすく、監査人は被監査部門から独立する。
  2. 聞き取りだけでは裏付けにならず、資料の閲覧・質問・現場の確認で証拠を集める。報告後はフォローアップで改善を確認する。
  3. 監査は抽出した範囲の評価で、全てを保証しない。診断は弱点を探す手法で、監査は管理が基準に合うかを評価する。

クイズ

選ぶと、すべての選択肢について「なぜ正しいか・なぜ違うか」が出ます。間違えた問題は復習に入ります。

  1. 動画で出た問題監査の説明として、適切なものは？

    1. 助言が中心なのは助言型

    2. システム全般が対象

    3. 被監査部門から独立する

    4. フォローアップで改善を確認

  2. 経営層から、情報セキュリティ管理が基準に適合しているかを、被監査部門から独立した立場で評価し、その結果を保証してほしいとの依頼があった。改善案の提示は今回は求められていない。実施方法として最も適切なものはどれか。

    1. 正解。管理の状態を評価して保証するのは保証型。監査人は被監査部門から独立し、基準に照らして客観的に評価する。

    2. 助言型は、問題点を指摘して改善を助言する型。今回は評価の保証を求められており、改善案は求められていない。

    3. 診断は技術的な弱点を探す手法。監査は、管理が基準に合うかを評価するもので、弱点の一覧は評価の結果にならない。

    4. 被監査側が自ら確認する自己点検は、監査ではない。客観的な評価には、被監査部門から独立した監査人が要る。

  3. アクセス権の見直しは四半期ごとに実施していると、担当者が監査人に説明した。しかし、見直しの記録を閲覧すると直近2期分が見当たらない。担当者は「実施した」と繰り返している。監査人の対応として最も適切なものはどれか。

    1. 聞き取りだけでは裏付けにならない。説明は質問で得た情報にとどまり、資料の閲覧や現場の確認で裏付ける必要がある。

    2. 記録が見当たらないことは重要な手がかりだが、そこで断定せず、資料の閲覧や現場の確認など追加の証拠で裏付けてから評価する。

    3. 正解。監査証拠は、資料の閲覧・質問・現場の確認で集める。聞き取りだけでは裏付けにならないので、追加の証拠で評価する。

    4. 診断は技術的な弱点を探す手法で、見直しという管理の実施状況を評価する手段ではない。監査では管理が基準に合うかを証拠で確かめる。

  4. 監査チームで、評価に使う文書の位置づけを整理している。「管理策がどこまで整っているかを評価する基準」と「監査人としての行動の拠りどころ」の使い分けとして、最も適切なものはどれか。

    1. 監査人は被監査部門から独立する。行動を被監査部門の方針に従って決めると、独立性が保てない。

    2. 正解。管理基準が評価の物差し、監査基準が監査人の行動の拠りどころ。

    3. 二つの役割が逆になっている。評価の物差しは管理基準、監査人の行動の拠りどころは監査基準。

    4. 客観的な評価は、基準に照らして行う。経験だけの判断では、何に照らして評価したのかが示せない。

  5. 監査報告を受けた経営層が、「サーバの個別の弱点の一覧がない。弱点を洗い出したかったのに、監査では役に立たない」と述べた。監査の目的に照らした説明として最も適切なものはどれか。

    1. 正解。診断は技術的な弱点を探す手法、監査は管理が基準に合うかの評価。弱点の洗出しが目的なら診断が向く。

    2. 監査と診断は目的が違う。監査報告書は管理の評価を伝えるもので、診断と同じ弱点の一覧を載せなければ不完全とは言えない。

    3. 二つの説明が逆になっている。弱点を探すのが診断、管理を基準で評価するのが監査。

    4. 監査は抽出した範囲の評価で、全てを保証するものではない。一覧がないことは、弱点が存在しない証明にならない。

  6. 監査の結果が「重大な指摘事項なし」だったため、経営層は「管理は全て問題ないと保証された」と受け止め、セキュリティ対策の予算を縮小しようとしている。担当者の助言として最も適切なものはどれか。

    1. 監査は抽出した範囲の評価で、全てを保証するものではない。指摘がないことを、全ての管理の適切さの保証とは受け取れない。

    2. 監査は計画で決めた目的・範囲・方法に沿って行い、全てを保証するものではない。結果を改善につなげる取組みが要る。

    3. 正解。監査は抽出した範囲の評価で、全てを保証しない。どこまでが対象だったかを確認し、結果を改善につなげる。

    4. 監査計画では、リスクの高い所を重点にする。指摘がなかったことで、この考え方が不要になるわけではない。

頭の中で考える

書かなくて大丈夫です。答えを頭の中で組み立ててから開き、要素がそろっていたか確かめます。

  1. 監査人が被監査部門から独立していなければならない理由と、内部監査・外部監査の違いを頭の中で説明してみよう。

    答えを開く

    自分の管理は担当者自身では見落としやすく、被監査側が自ら確認する自己点検は監査ではない。客観的に評価するため、監査人は被監査部門から独立する。内部監査は自組織の別部門が、外部監査は外部の第三者が行う。

    思い浮かんだ要素にチェック

  2. 聞き取りの内容だけで監査の結論を出してはいけない理由と、報告のあとに必要なことを頭の中で説明してみよう。

    答えを開く

    聞き取りだけでは裏付けにならないため、資料の閲覧・質問・現場の確認で監査証拠を集めて評価する。結果は監査報告書で依頼者に伝え、指摘した事項が改善されたかをフォローアップで確認する。監査は抽出した範囲の評価で全てを保証しないため、改善につなげることが要る。

監査実施前の確認記録（ダミー）
対象: 情報システム部の、サーバ運用管理
監査人の候補: 運用担当者、または別部門の者
サーバの設定とアクセスの記録は、いつでも確認できる
要件: 結果を、客観的な評価として経営層へ報告したい

適切な進め方は、どれ？

答えを開く

運用に関与しない者が、設定と記録を確認して評価する

よくある誤答

  • 運用担当者が、自分で確認して監査報告とする … 別部門の者を選べるのに自分で評価すると、独立性が保てない
  • 運用に関与しない者が、聞き取りだけで結論を出す … 申告だけでは裏付けにならず、記録は確認できる
