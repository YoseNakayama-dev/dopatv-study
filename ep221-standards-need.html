#121 ・ 第9章 情報セキュリティに関する法制度

セキュリティの規格と制度 15408・PCI DSS・20000

  1. 規格は基準を定めた文書、制度は審査して認証する仕組み。何を対象にした認証かの取り違えに注意する。
  2. 15408は製品の評価基準でEALは保証のレベル。PCI DSSはカード会員データを扱う事業者向けで、維持が要る。
  3. 20000は組織が認証を受けるITサービス管理の規格。ITILは指針で、情報セキュリティはISMSと組み合わせる。

  1. 動画で出た問題規格や制度の説明として、適切なものは？

    1. EALは保証のレベル

    2. 承認後は保存しない

    3. 20000は組織が認証を受ける

    4. ITILは指針で認証の規格でない

  2. ファイアウォール製品の入札で、複数ベンダーの製品を同じ要件で比べたい。各社のSTは、評価対象の範囲や要件が個別に異なる。比較の物差しとして適切なものはどれか。

    1. STは個別の評価対象の要件・仕様なので、各社で異なる。記載量の多さは、共通の物差しにも機能の強さにもならない。

    2. ISO/IEC 20000は、組織がITサービスマネジメントの認証を受ける規格。製品の機能を比べる物差しではない。

    3. PCI DSSはカード会員データを扱う事業者向けの基準で、製品の機能を評価する制度ではない。

    4. 正解。PPは製品の分類ごとの要件をまとめたもの。分類で共通の要件を基準にすれば、各社の製品を同じ物差しで比べやすい。

  3. ECサイトで、再購入を簡単にするため、カード番号とセキュリティコードを保存する機能を追加したい。PCI DSSの考え方に沿った設計として適切なものはどれか。

    1. 正解。カード番号を保存するなら読めないよう保護し、セキュリティコードは承認後に保存しない。

    2. セキュリティコードは、承認後に保存してはならないとされる。暗号化しても保存してよいことにはならない。

    3. カード番号は、保存するなら読めないよう保護する。アクセス制御は別の要求であり、平文保存の代わりにならない。

    4. バックアップだけを保護しても、本体の平文は読める。保存するカード番号は読めないよう保護する必要がある。

  4. 調達先が「この製品はISO/IEC 15408の認証を取得済みなので、導入後の脆弱性対応は不要」と説明した。この説明への見解として適切なものはどれか。

    1. 認証を受けても、脆弱性がないという保証にはならない。導入後の脆弱性対応が不要とは言えない。

    2. 正解。認証は脆弱性が無い保証ではなく、評価した構成・版に限られる。

    3. EALは保証のレベルで、評価した構成・版が前提。EALが高くても、異なる構成に同じ保証が及ぶわけではない。

    4. ISMS認証の対象は組織の運用で、製品ではない。製品の脆弱性がそれで担保されるわけではない。

  5. 運用委託先の選定で、委託先はISO/IEC 20000の認証を取得済みである。当社は、委託先の情報セキュリティの管理水準も確認したい。進め方として適切なものはどれか。

    1. 20000はITサービスマネジメントの要求事項。情報セキュリティはISMSと組み合わせて運用するもので、それだけで網羅されるとは言えない。

    2. インシデント管理は20000の管理対象の一つだが、それだけで情報セキュリティの管理水準が十分と判断できるわけではない。

    3. 正解。情報セキュリティはISMS（ISO/IEC 27001）と組み合わせて運用する。別の枠組みで確認する。

    4. ITILは指針で、組織が認証を受ける規格ではない。導入していても、ISMSの代わりにはならない。

  6. 昨年PCI DSSの準拠と判定された事業者が、今期、カード会員データを扱う新システムを追加した。見解として適切なものはどれか。

    1. 正解。準拠は評価時点の状態であり、維持する運用が必要。新しい構成についても、基準を満たす状態を保つ。

    2. 判定は評価時点の状態に対するもの。新たに追加したシステムまで準拠済みと扱える根拠にはならない。

    3. PCI DSSは事業者向けの基準で、製品の機能を評価する制度ではない。製品認証で代替するものでもない。

    4. セキュリティコードを保存しないことはPCI DSSの要求の一つにすぎない。ほかの要求を含め、準拠の維持が必要。

頭の中で考える

  1. ISMS認証済みの開発元の製品を選んでも、製品の機能の検証にならないのはなぜか。頭の中で説明してみよう。

    答えを開く

    ISMS認証の対象は組織の運用で、製品ではないため。製品のセキュリティ機能を第三者の検証結果で確かめたいなら、ISO/IEC 15408に基づく評価・認証を受けた製品を選ぶ。

  2. ISO/IEC 15408の認証を受けた製品でも、脆弱性対応が不要にならない理由を頭の中で説明してみよう。

    答えを開く

    認証は脆弱性がないという保証ではなく、評価した構成・版に限られるため。EALは保証のレベルで、高いほど評価が厳格という意味であり、機能が強いことや脆弱性が無いことを意味しない。

よくある誤答

  • ISMS認証を取得した開発元の製品を選ぶ … 認証の対象は組織の運用で、製品ではない
  • PCI DSSへの準拠を求める … 事業者向けの基準で、製品の機能を評価する制度ではない
